## 3. Root cause found investigating E2's 0.0042 (READER_POOL NATIVE), reported before this cell
   was designed

Loaded `data/exp_scorer_swap_e2_v1/units.jsonl` directly (2400 READER_POOL query records, 3
seeds x 400 queries x ~2 pools). Measured: **READER_POOL candidate-set size is constant at
4286-4287 across all 2400 queries** (`reader_eligible_pool()` returns essentially the FULL
~5491-anchor vocabulary, minus self-lemma variants, intersected with CSKG-entity existence).
**STORE_POOL candidate-set size has median 3, max 8** (the store's top-50 raw shortlist,
INTERSECTED WITH reader-anchor coverage AFTER the top-50 cut, collapses to single digits). So E2's
"swap" compared a K~=4287 pool against a K~=3 pool and called the result AMBIGUOUS without ever
reporting K. At K~4287, DEGREE_FLOOR and SCRAMBLE both hit exactly 0/2400 -- consistent with chance
(expected ~0.24 and ~0.56 hits respectively at that pool size, so P(exactly 0) is 57-79%, not
anomalous) -- and NATIVE (reader cosine argmax over ~4287) at 0.42% is in the same ORDER of
magnitude as, but ~10x below, the already-established open-vocabulary BASE floor (4.80%,
`exp_orthographic_floor_vet_v1`) on a similarly-sized full-vocab pool. SWAPPED (store's
`pull_in_multi_exclude` scoring that same ~4287-candidate pool) reaches 16.4%, ~40x NATIVE at
identical K. At K~3, NATIVE and SWAPPED are statistically indistinguishable (44.97% vs 45.97%,
CI-overlapping) -- unsurprising, since 3-way argmax is easy for almost any reasonable scorer. THE
0.0042 IS A REAL K-DRIVEN EFFECT, not a broken pairing or a crashed index -- but the K DISPARITY
BETWEEN POOLS WAS NEVER CONTROLLED OR REPORTED, so the "ambiguous" verdict is confounded by K
rather than informative about mechanism-identity. This cell's design (sec 4) fixes that: BOTH
sites rank the SAME shared candidate universe, so K is a controlled independent variable rather
than an artifact of each pool's own construction rule.

## 4. Design

**Shared candidate universe (fixes the E2 confound).** For each query, build ONE candidate
universe of CSKG entity indices: `normalize_lemma(entity_id)` is a reader anchor, is not the query
subject `s` or a lemma-variant of it. This is computed ONCE per query and used for BOTH pools --
only the RANKING differs:
- STORE ranking: `store.score_all(key)` (the associative-memory dot product), restricted to the
  universe.
- READER ranking: cosine(`space.bundle(query_lemma)`, `space.bundle(candidate_lemma)`), restricted
  to the same universe.

For K in the grid, each pool's top-K is the first K entities of ITS OWN ranking within the shared
universe. K=FULL means the entire universe (typically ~4000-4300 entities, matching E2's measured
READER_POOL size -- NOT the full 482,588-entity CSKG vocabulary, which includes entities with no
reader-anchor correspondent and would make "full" incomparable across pools).

**Selection mechanisms per pool (each pool tests TWO, one native, one swapped-in from the other
site -- reused unmodified from `exp_scorer_swap_e2_v1`):**
- STORE_POOL/NATIVE: `pull_in_multi_exclude` (DG/CA3-style gated settle) over `store.E[top-K]`.
- STORE_POOL/SWAPPED: reader cosine argmax (`E2.cosine_argmax`) over the same top-K's reader
  bundles.
- READER_POOL/NATIVE: reader cosine argmax over `space.bundle` for the reader-ranked top-K.
- READER_POOL/SWAPPED: `pull_in_multi_exclude` over `store.E[top-K]` for the READER-ranked top-K
  (i.e. store selection scoring a reader-chosen candidate set -- the genuine cross-mechanism test
  for the reader site).

**READ-OUT INVARIANCE CHECK (required before running, per brief).** READER_POOL/NATIVE ranks
candidates for retrieval AND selects among them with the IDENTICAL score (cosine similarity to the
same query vector). Because the top-1 item by any score is always inside that score's own top-K
for every K>=1, `argmax == gold` implies `rank(gold) == 1` regardless of K, so
`conditional_accuracy(K) = P(rank==1) / P(rank<=K) = hit@1 / recall@K` for this arm ANALYTICALLY,
not empirically. hit@1 is a FIXED number (does not vary with K); recall@K is non-decreasing in K;
so READER_POOL/NATIVE's conditional accuracy is MECHANICALLY NON-INCREASING in K by construction,
independent of anything the substrate does. This is reported (both figures are honest and were
asked for) but is NOT evidence about whether shortlist width helps or hurts selection -- that
question is only visible on the three arms above where retrieval-ranking and selection-scoring use
different score functions (STORE_POOL/NATIVE, STORE_POOL/SWAPPED, READER_POOL/SWAPPED). This
would have been visible on paper before running: the four organ rows in tonight's floored-negatives
were killed by exactly this kind of pre-registered invariance check.

**Query set.** Reused unmodified from `exp_scorer_swap_e2_v1.build_query_set`: real CSKG (s,p,o)
edges where lemma(s), lemma(o) are both reader anchors AND o is in `gold_meaning_set(lemma(s))`.
Same `DATA_SEEDS = [20260810, 20260811, 20260812]`, same `MAX_Q_PER_SEED = 400`,
`STORE_SCALE = 100000`. Each seed independently redraws the store's entity/relation codebooks
(`KGStore(..., generator=seeded)`), which is the BETWEEN-RANDOM-PROJECTION-DRAW spread control on
the store side (3 independent draws). The reader's `ConceptSpace` is built once and reused across
seeds (unchanged from E2); a second independent reader projection draw (DRAW2-style, as
`exp_capacity_binds_c3_v1` used) is OUT OF SCOPE for this cell on time-budget grounds and is
flagged, not silently omitted -- `exp_capacity_binds_c3_v1` already showed DRAW2 tracks PRIMARY
closely at every d (deltas CI-including-zero at every d), which is the closest existing evidence
that this omission is low-risk.

**Floors (reused, not reimplemented, per exp_dev discipline of reusing an existing
implementation):**
- STORE_POOL: `DEGREE_FLOOR` -- `E2.degree_argmax` / `E2.load_node_degree` (node-degree /
  popularity), reused verbatim.
- READER_POOL: `TRIGRAM_FLOOR` -- `MS.trigram_matrix` (character-trigram cosine, zero substrate
  signal), the exact construction `tools/orthographic_floor_vet_v1.py` uses for its A6 arm, reused
  verbatim (imported as `MS`, already an E2 dependency).
- SCRAMBLE (`E2.scramble_argmax`, deterministic per-query seed) at both pools, as a second, even
  weaker floor.
- DEGREE_FLOOR is also computed at READER_POOL and TRIGRAM_FLOOR at STORE_POOL for completeness
  (cheap, already have the inputs) but the pre-registered STRONGEST floor per site is the one
  named above.

**Known-answer arm (instrument-validity gate, checked -- not merely computed -- at report time,
replayed identically alongside every K row since the check itself is K-independent by
construction).** Up to 150 real queries per seed per site, 2-candidate discriminability (the true
answer vs one random distractor entity/lemma, excluding self-lemma variants): STORE side runs
`pull_in_multi_exclude(probe, store.E[[o, distractor]], ...)`; READER side runs cosine argmax over
`[bundle(lo), bundle(distractor)]`. Must clear **0.70** (matching the project-standard
`SELF_RETRIEVAL_FLOOR`); a site/seed below this is void-plumbing and its whole K-row for that
seed is excluded from the read, not just annotated.

**Bootstrap.** Paired bootstrap (`MS.paired_bootstrap`, 5000 draws, seed 20260815) over the
conditional-accuracy indicator vectors, computed separately per (pool, K) since the conditional
population (queries with recall@K==True) changes with K and is NOT the same fixed set across K
values -- these are NOT paired samples across K, so cross-K deltas are read directionally (does
the CI on K=500/full lie above/below/overlap the CI on K=5) rather than as a single paired delta.
Within-K comparisons (NATIVE vs SWAPPED vs floors, same conditional population) ARE paired.

## 5. Can-fail bands (pre-registered before running)

- **KILL CONDITION (pre-registered, stated before running per brief):** if conditional accuracy on
  the genuinely-decoupled arms (STORE_POOL/NATIVE, STORE_POOL/SWAPPED, READER_POOL/SWAPPED) is
  FLAT across the full K range -- i.e. the CI on (conditional_acc[K=500-or-FULL] minus
  conditional_acc[K=5]) INCLUDES ZERO for all three -- then "the shortlist is too crowded" as an
  explanation for the C3 open-vocabulary shortfall is DEAD: selection quality does not depend on
  how many distractors it has to reject, so widening or narrowing the shortlist would not have
  fixed the shortfall.
- **PASS band (interesting, worth further work):** conditional accuracy on at least one decoupled
  arm falls significantly (CI-separated) as K grows across the 100x range -- selection genuinely
  degrades with more distractors, licensing a narrower-shortlist intervention.
- **VOID:** known-answer arm below 0.70 for a site/seed, or `arms_differ_verified` fails (NATIVE
  and SWAPPED digest-identical at smoke gate), or fewer than `MIN_Q_FOR_VERDICT=20` scoreable
  queries at some K.
- READER_POOL/NATIVE is reported but EXCLUDED from the kill-condition verdict per the read-out
  invariance check in sec 4 -- its flatness or non-flatness is analytically pinned, not evidence.

non-degenerate results at all three K values on real (small-slice) data before the full run pays
the ~30+ minute cost.
