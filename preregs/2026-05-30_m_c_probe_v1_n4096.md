# Pre-registration: m_c_probe_v1_n4096

**Date:** 2026-05-30

**Queue:** overnight_queue

## Hypothesis

M_c (codebook-collision boundary) at N=4096, beta=4.0 lies inside the
sweep range M in [2048..32768]. Retention should drop sharply (>= 0.4
between two adjacent M_frac values) as M crosses M_c.

beta=4.0 is fixed well below beta_c~10 (from t1_beta_fine_v2) so the
transition is M-driven, not temperature-driven.

## Configuration

- N: 4096 (PROT-018 binding)
- beta: 4.0 (fixed; below beta_c~10)
- M_frac sweep (multiplier of 1024): [2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 28, 32]
  Absolute M = M_frac * 1024 -> M in [2048..32768]
- Seeds: [7, 17, 23, 31, 41] (5)
- Per-cell-seed checkpoint (12 * 5 = 60 cell-seeds; key = seed int)
- Smoke at N=1024, M_fracs=[2, 8, 32], seed=17

## Pre-registered bands

**HARD_PASS:** sharp transition detected -- max |ret[i+1] - ret[i]| >= 0.4
between adjacent M_fracs in >= 3/5 seeds. M_c is INSIDE the sweep range
and resolved.

**HARD_FAIL:** no transition -- accuracy stays >= 0.7 across all M (M_c >
32K; extend in v2) OR accuracy stays <= 0.3 across all M (M_c < 2K; below
probe range).

**MIDDLE_BAND:** gradual decline without sharp transition.

## Smoke result

Wall: 1.75s. N=1024, beta=4.0, seed=17:
  M_frac=2  (M=2048)  retention=1.000
  M_frac=8  (M=8192)  retention=0.515
  M_frac=32 (M=32768) retention=0.115

Biggest adjacent drop = 0.485 between M_frac=2 -> 8 (already over the 0.4
sharp-drop threshold at smoke scale). Verdict = MIDDLE_BAND because only
1 seed at smoke (HP requires >= 3/5 seeds).

This is a strong-signal smoke. Full N=4096 with 5 seeds is expected to
resolve M_c well inside the sweep range. Effect size at smoke: drop of
0.485 vs. threshold 0.4 = 1.2x clearance; this is "borderline" by the
walk-back-gate test (within 20% of threshold) so the FULL config keeps the
planned 5 seeds rather than doubling.

## Timeout estimate

- smoke_wall_s = 1.75 (CPU smoke; CPU is slower than GPU production)
- FULL_N / smoke_N = 4096 / 1024 = 4
- FULL_seeds / smoke_seeds = 5
- scaling_exp = 1.5 (matrix-store dominant via store_facts_batched)
- formula: ceil(1.5 * 1.75 * 4^1.5 * 5) = ceil(105) = 105s nominal.
- Larger M values dominate; M_frac=32 is roughly 16x heavier than M_frac=2
  so a conservative re-estimate using mean-M cost: ~2000s.
- PROT-019 _n4096 floor: 14400s. User spec adopts 21600s (50% headroom
  over PROT-019 floor for grid characterization safety margin).
- Final: timeout_s = 21600s.
