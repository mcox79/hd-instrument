# Research: storage IS the map — brain-scale storage architecture and native VSA-store integration

**Filed by:** research sub-agent. **Trigger:** mission directive — the reasoning geometry (phase-rotation/RotatE-equivalent, currently a standalone torch coordinate-embedding proxy fit per-run on CSKG) must become the substrate's NATIVE store representation, not a bolt-on. Drilled brain-scale storage mechanisms (hippocampal-entorhinal cognitive map, structure/content factorization, distributed-memory capacity theory, systems consolidation) via 4 parallel Sonnet lit-scan sub-agents, then synthesized against the substrate's actual code (`hdlab/kg_traversal.py::KGStore`, `hdlab/binding.py`, `hdlab/cleanup_family.py`, `hdlab/continual.py`, `hdlab/hippocampal_encoder.py`) and the existing relational-capability cert record (`notes/relational_capability_track_record_scour_2026-07-10.md`). Pure research — no local compute.

## HEADLINE

**The brain answer is unambiguous and converges across all 4 angles: storage and reasoning are the SAME computation over the SAME representation (not a store plus a bolted-on reasoner), and the specific trick that lets that unified representation scale is factorizing a reusable STRUCTURAL code (relations) from per-instance CONTENT (entities) — exactly the shape of `KGStore`'s existing `key = E[s] * R[p]` bind op. The substrate already has this right at the architecture level for the two-hop regime (CERT 585, chain-grade); what is NOT native is the reasoning geometry — the phase-rotation/HAKE fit lives in a separate torch coordinate table, disconnected from `E`/`R`/`W`. The concrete, remote-runnable integration is to promote `KGStore`'s bind op from real bipolar `{-1,+1}` multiplication to complex64 unit-phase multiplication (= FHRR bind = RotatE, exactly) and to write phase refinement into `R` via the SAME replay/consolidation cycle that already exists (`hdlab/continual.py::replay_cycle`, `hdlab/hippocampal_encoder.py::cls_discrete_budget_consolidate`), rather than a standalone per-run fit. This targets same-graph relation-pattern EXPRESSIVITY and multi-hop composability — it does NOT, and per the track record cannot, fix the separately-proven held-out inductive-inference wall, which requires more ingest, not richer per-edge geometry.**

## (1) Storage = map = reasoner: does the brain unify them, and must we?

**Verdict: yes, unified — with one real, load-bearing caveat (CLS's two-timescale split) that does not contradict the unification, it explains its scaling limit.**

- **Tolman-Eichenbaum Machine (TEM)** (Whittington, Muller, Barry, Behrens et al. 2020, *Cell*; NeurIPS-2018 precursor arXiv:1805.09042) factorizes an environment-independent **structural code** (medial entorhinal grid/border/object-vector cells — transition rules) from environment-specific **sensory/content code** (lateral entorhinal), bound via a Hopfield-like associative memory into place-cell-like conjunctions. Retrieval and generalization-to-a-new-environment use the literal SAME pattern-completion machinery — there is no separate inference module. TEM explicitly reproduces transitive inference as the same generative process used for spatial navigation.
- **Successor representation (SR)** (Dayan 1993; Stachenfeld, Botvinick, Gershman 2017, *Nat Neurosci*, "The hippocampus as a predictive map") is stored as a predictive occupancy map and READ OUT for value/planning via a linear operation on that same stored object (V = SR . reward) — storage and inference share one artifact by construction, not by coincidence.
- **CA3 pattern completion** (Eichenbaum relational-memory theory; Kumaran & McClelland structure-learning extensions; Behrens et al. 2018, *Neuron*, "What Is a Cognitive Map?") — completing an attractor from a partial cue IS the same operation whether the missing piece is "the rest of a memory" (recall) or "an unobserved relationship" (transitive/associative inference). Behrens et al.'s own framing: map-like codes are "general coding mechanisms capable of organizing knowledge of all kinds," with transitive inference and hippocampal remapping described as "two sides of the same coin."
- **Caveat (real, not a contradiction):** CLS theory still splits FAST hippocampal pattern-separated storage from SLOW neocortical consolidated generalization — even there, the hippocampal component itself unifies store+infer via its own attractor; the split exists because doing BOTH jobs (interference-free rapid one-shot storage AND slow interleaved generalization) in one weight matrix is mathematically in tension, not because storage and inference are different operations in principle. See (4) below — this is precisely the reason our design needs consolidation as a *second stage*, not a rejection of unification at the base layer.

**Implication for the substrate:** the map and the store MUST be one representation at the base layer — a separate "reasoning layer" that reads a store built for something else is the wrong shape. **`KGStore` already gets this right**: `key = E[s] * R[p]`, `score_all = E @ (W @ key)` — the bind op that constructs the query IS the same operation that constructed the storage (`W.add_((E[o].T @ keys) / n_dim)` at ingest). There is no separate reasoning engine bolted onto `W`. The standalone torch KGE fit (rotation/additive/HAKE on CSKG) VIOLATES this principle — it is a second, disconnected coordinate system that happens to share a bind-operator FORM (RotatE = complex Hadamard = FHRR bind) with the store but is not wired into `E`/`R`/`W` at all. That disconnect is exactly the "storage != map" anti-pattern the brain evidence says not to build.

**P_deflated: 0.75.** This is a literature-convergence claim (not novel synthesis), so the 0.50 novel-synthesis cap does not apply; deflated modestly for the CLS two-timescale caveat being a genuine complication rather than a clean unification story.

## (2) Structure/content factorization: the sub-linear storage-scaling mechanism (the make-or-break claim)

**Verdict: real and evidenced in the brain; already implemented in `KGStore` at the architecture level; the quantitative "how much cheaper" question is a genuine literature gap, not a solved comparison.**

- **TEM** is again the clearest brain precedent: the SAME structural (transition) code generalizes to a brand-new environment/graph near-zero-shot, because only the content binding (not the structure) has to be relearned. **Grid-cell remapping** corroborates the mechanism (coherent phase shifts across environments while spacing/orientation — the structural invariant — is preserved).
- **Schema-dependent consolidation** (Tse/Morris/McClelland, *Science* 2007) gives the cost claim directly: once a compatible neocortical schema exists, a NEW but schema-consistent fact can become hippocampus-independent after a single trial (vs. the normal weeks-long consolidation timeline) — the closest empirical number to "marginal cost of one more fact drops once structure is reused."
- **Prior VSA/HDC precedent is real, and it is not a gap — it is a known family.** HolE (Nickel, Rosasco, Poggio, arXiv:1510.04935) is the textbook version: one learned vector per RELATION TYPE reused across every triple of that type, scored via circular correlation against per-triple entity vectors — i.e. relation storage is O(1) per type, entity storage is O(#entities), and neither scales with O(#facts). Classical VSA/HRR/Tensor-Product-Representation literature (Plate 1995; Smolensky) generalizes this further. **`KGStore` is this exact pattern, already built and already CERT-585 chain-grade**: `R` (n_rel x n_dim) is allocated ONCE and reused across every triple; only `E` (content) and the accumulated `W` grow with ingest.
- **Genuine gap, honestly flagged by the lit-scan:** no source found directly benchmarks "N facts via reusable relation operator" against "N facts as N independent flat vectors" with a clean capacity/error curve. TEM's zero-shot-to-new-environment result and Marcus's own combinatorial-explosion estimate for unfactored tensor-product recursion (~10^7 nodes for a 5-level recursive structure, cited in the TPR survey literature) are the closest analogues, but neither is phrased as the exact storage-scaling law this mission wants. **This is the correct place to spend the "make-or-break" experimental effort** — not on re-deriving that factorization helps (settled), but on measuring HOW MUCH it helps at KG scale in the substrate's own regime (dimension, sparsity, relation-type count).

**P_deflated: 0.40** (capped under the 0.50 novel-synthesis ceiling — the qualitative factorization-helps claim is well-evidenced, ~0.70, but the specific quantitative sub-linear-scaling curve for THIS store, at THIS dimension, is unmeasured and is the actual thing being proposed).

## (3) VSA-store capacity limits: what dimension/sparsity/cleanup our store needs

**Verdict: converging but stratified capacity laws depending on which operation is being scaled — bind/superposition vs. factorization/cleanup vs. cortex-style dense readout are three different regimes with three different scaling exponents.**

- **HRR/superposition capacity (Plate; Gallant & Okaywe MBAT, arXiv:1501.07627; general VSA capacity analysis arXiv:2301.10352):** linear-in-dimension capacity for binding/bundling, i.e. capacity ~ c*D for some constant c set by required accuracy and cleanup-codebook size (naive HRR binding underperforms this bound; a projection-based variant restores it, per NeurIPS-2021 "Learning with HRR").
- **Resonator networks (Frady, Kent, Olshausen, Sommer, *Neural Computation* 2020, papers 1 & 2):** factorization/cleanup capacity scales **quadratically in dimension** (~N^2), because search happens IN superposition rather than exhaustive lookup — a materially better scaling regime than raw HRR bundling, and the natural cleanup upgrade path for `hdlab/cleanup_family.py`. The capacity wall is crosstalk between competing factor candidates, not a hard combinatorial limit.
- **Modern dense Hopfield / exponential capacity (Krotov & Hopfield 2016; Ramsauer et al. 2020):** exponential-in-dimension capacity with one-step retrieval, via a log-sum-exp energy — the best scaling of the three, but a different regime (dense associative readout / attention-style, not compositional bind-unbind); relevant to `cleanup_family.py`'s `modern_hopfield_continuous` arm, already present in the codebase.
- **Brain side (Treves & Rolls sparse-coding CA3 theory):** capacity scales roughly inversely with coding sparseness for a fixed synapse budget — sparser firing buys proportionally MORE storable patterns at the same wiring cost. **Systems consolidation extends effective capacity beyond the raw hippocampal ceiling** by keeping only transient, novelty-gated detail in the fast store while distilling everything else into a compact cortical schema — i.e. consolidation is the mechanism that lets total capacity exceed what the base linear/quadratic law alone would allow.
- **Substrate-specific reading:** `KGStore`'s `W` is a single dense `[n_dim, n_dim]` Hebbian correlation matrix summed over ALL ingested triples — this is architecturally a linear associative-memory / correlation-matrix store, whose capacity law is the SAME family as Plate/MBAT (linear-in-N, degrading past a load threshold). This is consistent with the substrate's own measured cliff: `substrate_KG_capacity_sweep` is chain-grade at M~10k and hits a cliff at M~50k (per the relational track record, section G) — a real, already-measured instance of exactly this capacity wall, not a hypothetical.
- **What's needed to hold a large KG without the crosstalk wall (concrete, in priority order):** (a) **partitioning/sharding** — the substrate already has a working partition-oracle-routing capability (CG to M=100k, bounded at M=1M per the track record's section D) that keeps any single `W` matrix below its own linear-capacity cliff by never asking one matrix to hold more than its safe load; (b) **sparsity** in `E`/`R` (a cheap, well-evidenced constant-factor capacity multiplier per Treves-Rolls, orthogonal to dimension); (c) **resonator-style cleanup** generalized to the complex/FHRR domain (Frady et al.'s resonator-network papers explicitly cover the complex/FHRR case, so this is not a new derivation, just an unimplemented port) for the N^2 factorization-capacity regime rather than relying on linear correlation-matrix capacity alone; (d) **consolidation** (below) to keep the raw/live `W` small by continuously distilling settled structure out of it.

**P_deflated: 0.55** for "our store needs partition + sparsity + complex-domain resonator cleanup + consolidation, in that priority order, to scale past the measured M~50k cliff" — well-grounded in both the literature and the substrate's own measured data, but the exact dimension/sparsity operating point for a specific target KG size is not derived here.

## (4) Consolidation as scale-storage: is this the same replay/map-builder already scoped?

**Verdict: yes — and the substrate already has the primitives; they are not yet pointed at `KGStore`.**

- **CLS theory** (McClelland/McNaughton/O'Reilly 1995; Kumaran/Hassabis/McClelland 2016 update) gives the mechanistic reason two systems beat one: fast, sparse, pattern-separated hippocampal encoding avoids interference for NEW one-shot facts, but that same sparse/pattern-separated code is a bad substrate for slow, generalizing structure — so the brain interleaves offline replay to move statistical structure into a separate, overlapping, slowly-updated cortical store without overwriting it.
- **Replay is literally a training/compression signal, not passive rehearsal:** sharp-wave-ripple replay (Wilson & McNaughton; Carr/Jadhav/Frank 2011; Ólafsdóttir/Bush/Barry 2018) reactivates recent sequences at 10-40x real-time during rest/sleep, and disrupting it experimentally impairs learning — direct causal evidence it functions as an offline training pass, not decoration. A 2024 bioRxiv model ("Hippocampo-neocortical interaction as compressive retrieval-augmented generation") frames the whole loop explicitly as compressed-key storage (hippocampus) + generative reconstruction/generalization (cortex) — an unusually direct match to "consolidate raw KG facts into a compact structured store."
- **Quantitative compression-ratio claims are thin** — the lit-scan found a solid quantitative anchor for replay SPEED (10-40x) but no citable number for how much SMALLER the resulting schema is than the sum of episodes it was built from. Treat any specific compression ratio here as novel synthesis (capped at 0.50), not literature fact.
- **This is the same replay/map-builder already scoped in the substrate.** `hdlab/continual.py::replay_cycle` (NREM-replay consolidation, +0.57 absolute drift reduction at best schedule — already landed) and `hdlab/hippocampal_encoder.py::cls_replay_cycle` / `cls_discrete_budget_consolidate` (DG/CA3 complementary-learning-systems primitives, with a working discriminator `_cls_consolidation_discriminator`) are the SAME mechanism class the brain literature describes — they are just not currently wired to consume `KGStore` triples or to write refined `R`/`E` codebooks back into it. **Concrete buy:** running the existing consolidation cycle over `KGStore` ingest would (a) periodically distill well-generalized/redundant triples out of the live `W` to free correlation-matrix headroom (directly answering the capacity-scaling need in (3)), and (b) is the natural place to fold in phase-rotation refinement (below) as an in-loop update rather than a disconnected external fit.

**P_deflated: 0.60** for "the existing replay_cycle/CLS primitives are the right vehicle and need only be re-pointed at KGStore, not rebuilt" — the mechanism match is strong and the code already exists; deflated for the untested assumption that wiring is straightforward (the DG/CA3 primitives operate on generic codevectors, not (s,p,o)-structured Hebbian matrices, so some adaptation work is real, not zero).

## (5) Concrete integration path: phase-rotation as the store's NATIVE bind op

**The proposal, precisely:**

1. **Upgrade `KGStore.E`/`KGStore.R` from real bipolar `{-1,+1}` (float32) to complex64 unit-modulus phase vectors** (`e^{i*theta}` per dimension) — a strict generalization of the existing bind op, not a new mechanism: `key = E[s] * R[p]` becomes elementwise COMPLEX multiplication, which is exactly FHRR binding and exactly RotatE's relation operator (phase rotation per dimension). This is a dtype/init change to the existing `_bipolar()` constructor and `key()`/`ingest_triples()` methods, not a new class of computation.
2. **Unbind by conjugate multiplication** (`E[s] ~ key * conj(R[p])`) gives an EXACT algebraic inverse — this is the same self-inverse property the current bipolar bind already has (`x*x=1`), generalized from the 2-element group `{-1,+1}` to the full unit circle, which is precisely what buys RotatE's stated advantage: continuous relation composition and the ability to represent symmetric, antisymmetric, inverse, and compositional relation PATTERNS that a sign-flip bind cannot express by construction (only symmetric/antisymmetric, no graded composition).
3. **HAKE's modulus (radius) channel does NOT fit cleanly into this exact-unbind scheme** — this is an honest tension the mission should know about upfront, not discover after building it: HAKE adds a magnitude component specifically because pure-phase RotatE cannot encode hierarchy depth/multiplicity, but a non-unit-modulus relation vector breaks the clean "unbind by conjugate = exact inverse" property. **Recommended resolution:** keep `R`'s phase channel unit-modulus (preserves native exact unbind, matches current architecture), and add hierarchy/multiplicity as a SEPARATE real-valued per-relation scalar or short vector stored alongside `R` (a second field on `KGStore`, e.g. `R_mod`), used only in scoring (`score_all`) as a magnitude reweighting, never inside the bind/unbind algebra itself. This preserves storage=map unification for the invertible phase geometry while still capturing HAKE's hierarchy signal as an auxiliary readout weight.
4. **Cleanup:** generalize `hdlab/cleanup_family.py`'s resonator/attractor readouts to complex64 — well-precedented (Frady et al.'s resonator-network papers explicitly treat the FHRR/complex case), not a novel derivation, just an unimplemented port; this is what buys the N^2 factorization-capacity regime from (3) instead of relying on the correlation matrix's linear-capacity law alone.
5. **Phase refinement lives IN the replay/consolidation cycle, not a standalone script.** Instead of fitting rotation/additive/HAKE coordinates in a disconnected per-run torch table, run a small gradient (or closed-form) phase-refinement step on `R` DURING the existing `replay_cycle`/`cls_discrete_budget_consolidate` pass, sampling replayed `(s,p,o)` triples and nudging `R[p]`'s phase angles to better satisfy the bind/unbind/score consistency the store already checks at ingest. This makes the "winning geometry" the store's own weight, updated the same way the store is normally updated (Hebbian write during ingest, phase refinement during consolidation) — never a second coordinate system.

**Remote-runnable test (no local compute, ships to the existing GPU/CPU queue):**

- **Cell A (parity / must-not-regress):** run the complex64 phase-rotation `KGStore` variant on the SAME CERT-585 ConceptNet 2-hop chain-grade benchmark (36.49x ratio, 2-hop acc 0.426 baseline). This is a pure re-implementation check — the phase geometry must reproduce (not necessarily improve) the certified composition result, since (1) says the bind/store must remain unified.
- **Cell B (the actual claim under test — relation-pattern expressivity):** restrict evaluation to relation subsets with known symmetric / antisymmetric / inverse / compositional structure (the standard RotatE diagnostic categories, directly applicable to FB15k-237/ConceptNet relation types already in the ingested KG) and compare single-hop accuracy on those subsets between the complex-phase bind and the current bipolar bind. This is the one place a REAL, mechanistic, falsifiable lift should appear if the geometry buys anything at all, because bipolar sign-flip is structurally incapable of representing graded/compositional relation semantics and phase rotation is designed to.
- **Cell C (consolidation wiring):** compare phase parameters produced by (i) the existing standalone external per-run torch fit vs (ii) the in-loop consolidation-cycle refinement proposed in step 5, on the SAME held-out slice, to check the in-store update is not a degraded shortcut relative to the disconnected fit it replaces.

**HARD-PASS thresholds (pre-registered):**
- Cell A: 2-hop accuracy >= 0.40 (no material regression from the certified 0.426 baseline).
- Cell B: >= 15% relative improvement in single-hop accuracy on the symmetric/antisymmetric/inverse/compositional relation subsets vs. the bipolar baseline, holding degree and relation frequency confound-controlled (per the standing fairness discipline — degree/frequency confound must be ruled out, not just an aggregate delta).
- Cell C: in-loop consolidation-refined phases within 10% relative of the standalone-fit phases on the same held-out relation-pattern discriminator (i.e. the native wiring is not a meaningfully worse substitute for the disconnected fit).

**HARD-FAIL thresholds:**
- Cell A: 2-hop accuracy < 0.35 (breaks the certified composition primitive — the complex generalization must not be allowed to regress the one thing already proven).
- Cell B: < 5% relative improvement (statistically indistinguishable from bipolar) on the confound-controlled relation-pattern subsets — meaning the phase geometry buys nothing once actually wired natively, which would mean prior standalone-fit gains (if any were observed) came from the gradient-learned entity embeddings, not the geometry, a confound the lit-scan explicitly flagged as untested anywhere in the literature.
- Cell C: in-loop refinement diverges or degrades by > 25% relative vs. the standalone fit — meaning consolidation-cycle wiring is not a safe drop-in replacement and needs a dedicated training loop rather than reuse of the existing replay primitive.

**Middle band (5-15% Cell B lift, or Cell A in [0.35, 0.40)):** diagnose whether the unit-modulus constraint (needed for exact unbind) is suppressing the specific HAKE hierarchy signal that free-modulus embeddings would capture — i.e. check whether adding the separate `R_mod` auxiliary channel (step 3) recovers the missing lift before concluding the geometry itself is the bottleneck.

**Explicit scope limit (do not overclaim):** per the relational-capability track record (`notes/relational_capability_track_record_scour_2026-07-10.md`), held-out inductive inference to genuinely UNSEEN entities/edges is a separately-proven wall (3 confound-free FULL HARD_FAIL cells: learned SR codes route no better than random codes on held-out edges, Δ0.011 < 0.05 margin; global additive TransE scored ZERO/vacuous; richer relation-type/density/structure-aware knobs over the SAME graph all independently fail to move held-out inference). **This integration targets same-graph relation-pattern expressivity and native storage/composability — it is not proposed as, and per the track record's own convergent finding should not be expected to be, a fix for the held-out inductive wall.** That wall's own diagnosis (ingest more knowledge, not richer per-edge codes) stands independently of this proposal.

**P_deflated: 0.35** for the overall integration proposal (Cell A+B+C combined) landing HARD-PASS. Base intuition ~0.55 (RotatE's own published results independently demonstrate the relation-pattern lift on FB15k-237-family graphs, and the bind-op FORM is already validated in-store via the bipolar case) deflated 0.20 for lit-scan calibration penalty: no source tests complex-domain wiring into a Hebbian correlation-matrix KG store specifically, the unit-modulus-vs-HAKE-modulus tension is a real unresolved design tradeoff rather than a solved problem, and the in-loop consolidation-refinement step (Cell C) has no direct precedent at all. Capped under the 0.50 novel-synthesis ceiling regardless of the base-intuition arithmetic.

## Intuitive summary

**What we studied:** how real brains store huge amounts of knowledge without running out of room, and whether "remembering something" and "reasoning about it" are actually different processes in the brain or the same one — so we could design our own knowledge-graph memory the same principled way instead of guessing.

**What we found:** the brain evidence is remarkably consistent across four independent angles. Storage and reasoning are the SAME operation on the SAME map — recalling a memory and inferring something new from partial information both come out of the identical brain circuit (the hippocampus's "pattern completion"). And the trick that lets the brain store enormous amounts of new experience cheaply is that it reuses a fixed "structural scaffold" (how things generally relate to each other) across every new set of specific facts, rather than rebuilding the scaffold each time. Separately, the brain's overnight "replay" (literally reactivating the day's memories at fast-forward speed during sleep) is how it compresses raw daily experience into that reusable, general-purpose scaffold — and our substrate already has both of these pieces built (a knowledge-store that reuses relation vectors across facts, already proven to work; and an overnight-style replay/consolidation mechanism), they are just not currently connected to each other.

**What this means for our system:** our "reasoning geometry" experiment (a rotation-based way of representing relationships, which happens to be mathematically the exact same operation the brain-inspired literature calls for) is currently living in its own separate table, disconnected from the actual memory store — which is precisely the anti-pattern the brain evidence says not to build. We designed a concrete, remote-runnable way to fold that geometry directly INTO the store's own memory-writing operation, and to have it get refined during the SAME overnight-replay-style process that already exists, instead of as a one-off side calculation.

**Why this matters, honestly:** this should make the store better at representing certain KINDS of relationships (ones with real structure, like "reverse of" or "type of X implies type of Y") using knowledge it already has — but it will NOT, by itself, teach the system to correctly guess facts it has never seen before, which a separate, already-completed set of experiments proved is a different and still-open problem (that one needs more raw knowledge fed in, not a smarter way of representing what's already there). We're being upfront about that limit so this doesn't get oversold as solving something it isn't aimed at.
