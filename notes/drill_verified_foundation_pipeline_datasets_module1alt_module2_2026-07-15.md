## (b) Module-#2 for the interface stress-test

**Recommended: BioGRID yeast interaction file (rank 2 above) paired against Costanzo 2016 (rank 1) — shared canonical ID = SGD systematic ORF name (e.g. YAL001C / YKL092C format), used natively by BOTH files' ID columns.**

- **VERIFIED**: fetched `downloads.thebiogrid.org/BioGRID/Latest-Release/` directly — confirmed the current release (5.0.259, dated 2026-06-25) exists and includes a per-organism TAB3 file for *Saccharomyces cerevisiae*, with columns 6/7 literally labeled "Systematic name Interactor A/B" per BioGRID's own TAB3 format spec (`wiki.thebiogrid.org/doku.php/biogrid_tab_version_3.0`).
- **Crosswalk needed: NONE.** SGD systematic ORF name is confirmed (via SGD's own documentation, fetched this session) to be the single stable community-wide join key for yeast genes — assigned once at genome-sequencing time, invariant across releases, and used natively by Costanzo, BioGRID, and (per the Hillenmeyer paper text, see below) yeast chemogenomics datasets too. This is a strictly EASIER case than the general canonical-ID-crosswalk problem described in this morning's `notes/drill_cross_module_interface_entity_sharing_brain_and_bestinclass_2026-07-15.md` (which assumed UniChem/MyGene.info/Bioregistry-mediated joins) — here the join is a literal string-equality match on the same column convention, no crosswalk service required at all.
- **Why it's a genuine stress test despite the trivial join**: Costanzo's epsilon score and BioGRID's physical-interaction / non-Costanzo-genetic-interaction calls are a genuinely DIFFERENT measured relation over the SAME entity set — this exercises the hub-and-spoke architecture's "one identity, two independent relation-modules" design (per the foundation-module-registry note, section 4) without also having to prove crosswalk-service correctness in the same test. That can be layered in later.
- **Harder/later stress test (deliberately NOT recommended for the first pass)**: Hillenmeyer et al. 2008 (Science) yeast chemogenomic fitness dataset — same yeast-ORF entity side, but the SECOND entity type is a chemical compound referenced only by free-text name in the paper (no PubChem CID/InChIKey used), which WOULD force a real crosswalk (free-text -> PubChem/ChEBI) rather than an identity join. Flagged for later because its live bulk-download path is currently DEAD this session: `chemogenomics.stanford.edu/supplements/global` and `fitdb.stanford.edu` both DNS-failed, `chemogenomics.pharmacy.ubc.ca/fitdb` connection-refused, and the GEO accession commonly associated with this era of screens (GSE7466) resolved to an unrelated human-tumor series (wrong/DEAD accession — do not reuse that GSE number without re-checking).
