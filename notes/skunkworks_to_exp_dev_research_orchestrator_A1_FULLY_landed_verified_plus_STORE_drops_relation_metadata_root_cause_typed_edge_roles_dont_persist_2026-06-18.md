## (2) SYSTEMATIC STORE FINDING: relation metadata is dropped on flush (root-caused)
While verifying the A1 edge I found relation_role=None -- the SAME as the A3 strengthens edge. Both raw edges have metadata={}. I traced the root cause (verify-the-referent on the Store, not just the symptom):
```
store.py _flush_relations (L115-126):
    explicit = [ Relation(src_id=src, tgt_id=tgt, rel_type=RelationType(rel_type_str))
                 for (src, rel_type_str, tgt) in self._all_relations ... ]
    save_relations(explicit, ...)
```
`self._all_relations` is a SET of (src, rel_type, tgt) **3-TUPLES** -- it carries NO metadata. So `_flush_relations` reconstructs every Relation WITHOUT metadata -> on every flush, ALL relation metadata is STRUCTURALLY DISCARDED. The atomizer SET relation_role='mechanism_for'/'strengthens'; the Store drops it on persist. This is NOT an atomizer bug.

**Scope + impact:**
- rel_TYPE persists fine (DEPENDS_ON / RELATES / USES / SUPERSEDED_BY / HAS_USERS). The SUPERSEDED_BY edges (cost-model 8a -> measured-8a, smoke refuse_gate -> NON_TEST) are SAFE (they're rel_types, not metadata).
- rel_ROLE (sub-types modeled as RELATES + metadata.relation_role: strengthens, mechanism_for, replicates) is DROPPED -> these collapse to indistinguishable bare RELATES edges.
- **NOT a cert-integrity issue:** the edges EXIST (graph linkage works), and the role SEMANTICS are recoverable from the SOURCE atom's metadata (A3: metadata.strengthens_cert; A1: verdict=ATTRIBUTION + attribution_findings). So nothing is LOST -- just not EDGE-queryable.
- **IS a typed-edge queryability limitation:** you CANNOT query "show all strengthens edges" or "all mechanism_for edges" at the edge level (they're all RELATES); you must go via the source atom's metadata.

**Fix options (architecture; NOT tonight -- Research/USER call):**
(a) Add first-class RelationType enum values (STRENGTHENS, MECHANISM_FOR, REPLICATES) so the role IS the rel_type (persists in the 3-tuple). Cleanest; small schema change.
(b) Change the Store to persist relation metadata (`_all_relations` -> include metadata; `_flush_relations` write it). More involved (the 3-tuple set is used for O(1) existence/dedup).
(c) Accept role-on-atom (the current de-facto state) + STOP setting relation_role on edges (it's silently dropped -> don't imply it persists).

**Interim guidance (cheap, do now): for typed-edge semantics, put the role on the SOURCE ATOM's metadata (A3 + A1 already do this), NOT on the edge metadata (it's dropped).** This is an AUDIT_LESSON candidate: "Store persists relations as (src, rel_type, tgt) 3-tuples -> edge metadata is dropped on flush; edge-role semantics must live on the source atom or as a first-class rel_type, never as edge metadata."
