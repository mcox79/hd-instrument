## PART 1 — component-by-component (representation | computes | meaning-source | brain-counterpart | limitation)

### 1. `hdlab/goal_typing.py` — the GOAL/OUTCOME typing + congruence organ

This file bundles several genuinely distinct mechanisms. Taking them in the order the task asked:

**1a. `find_desired_state` / `DESIDERATIVE_PASS` (goal recognition)**
- **Representation:** plain Python regex/token scan over lowercased word lists. `DESIDERATIVE_PASS` = a hand-enumerated closed set of 24 surface forms (`want(s/ed)`, `hope(s/d)`, `wish(es/ed)`, `mean(s/t)`, `plan(s/ned)`, `intend(s/ed)`, `aim(s/ed)`, `long(s/ed)`, `yearn(s/ed)`, `desire(s/d)`).
- **Computes:** locate a `DESIDERATIVE_PASS` verb, then scan forward for `"to VERB"` (skipping `"to NP"` via `DET_STOP`); extract the embedded verb's lemma + result-class + a referent (subject if the embedded verb's class is achievement-type, object if it's change-of-state-type, via `SUBJECT_IS_REFERENT_CLASSES`/`OBJECT_IS_REFERENT_CLASSES`).
- **Meaning source:** 100% SUPPLIED (hand-enumerated word list) for which verbs count as "wanting"; the syntactic pattern-match itself (purpose-infinitival "to VP") is a genuine STRUCTURAL/CONSTRUCTION read (verb-lemma-independent — this part legitimately generalizes to any verb standing in that slot, confirmed by `action_frame_feats`'s held-out FIT/TEST verb split in the same file, lines 374-395).
- **Brain counterpart:** the desiderative-verb recognition itself ≈ a closed-class function-word lexicon (like recognizing modal auxiliaries) — a small, plausibly-innate-scale set, not implausible as a supplied primitive. The purpose-infinitival CONSTRUCTION detector is a genuine syntactic-parsing capacity (construction grammar / left-corner parsing), brain-general.
- **Limitation:** the goal's CONTENT (what counts as "buying," "saving," "opening") is only as good as `_verb_classes`, covered next — `find_desired_state` itself never decides result-polarity, it just extracts the embedded verb + tries to place it in a class.

**1b. `CLASS_REGISTRY` + `OPPOSED_PAIRS` (the result-class taxonomy, Tier-1)**
- **Representation:** 12 named Python `set`s of literal lemma strings (`REPAIR_PRESERVE={"mend","fix","repair","save","rescue","protect","build","restore"}`, `DAMAGE_LOSE={"sink","break","fall","collapse",...}`, etc.), plus 6 hand-declared opposed pairs (`REPAIR_PRESERVE` vs `DAMAGE_LOSE`, `OPEN_CLASS` vs `CLOSE_CLASS`, ...).
- **Computes:** exact-membership lookup; `_class_relation` computes "same" (intersecting class-sets) / "opposed" (intersecting an `OPPOSED_OF` set) / `None` (unrelated → abstain).
- **Meaning source:** 100% SUPPLIED. A human decided, by reading the words, which of 12 buckets each of ~50 verbs belongs to and which buckets oppose which. There is no computation here that infers class membership from anything — it is a lookup table, full stop.
- **Brain counterpart:** closest analog is a hand-curated thematic/verb-class ontology (Levin-style verb classes) — the brain plausibly has something like this (posterior-temporal action-semantics network per the module's own citations), but the brain's version is LEARNED from a lifetime of seeing verbs used in situations with observable outcomes, not authored once by an engineer reading a word list.
- **Limitation:** closed-vocabulary by construction. Any verb not in one of the 12 sets is invisible to Tier-1, full stop, no matter how transparently its meaning follows from a related word.

**1c. `congruence_decision` (the MET/UNMET judgment)**
- **Representation:** Python control flow over two extracted structures (`desired`, `actual`), each `{referent, classes, verb_lemma, pattern}`.
- **Computes (exact procedure, `goal_typing.py:771-826`):** (1) find a desiderative goal in `goal_sentences`; abstain (`NA`) if none. (2) find ALL class-tagged verb occurrences in the outcome sentence (`find_actual_state_candidates`, not just the first — this fixes a documented distractor-clause bug); abstain if none carry a class at all. (3) among class-related candidates (same OR opposed to the desired class), pick the first whose referent LINKS to the desired referent (`_referent_links`, see below); if none link, fall back to the first candidate and record whatever link-tier it got (this preserves the "referent_mismatch → UNMET" precision guard rather than forcing a link). (4) if the winning candidate's class is unrelated to the desired class → abstain (`verb_class_unrelated`). (5) if either referent is `None` → abstain. (6) if the link-tier isn't a genuine link (`literal`/`pronoun_coref`/`shared_feature`) → **UNMET** (`referent_mismatch` — this is the over-link guard: a different entity's same-class outcome does NOT satisfy the goal). (7) same class + genuine referent link → **MET**. (8) opposed class + genuine referent link → **UNMET**.
- **Meaning source:** the DECISION LOGIC (same-class+same-referent→MET, opposed-class+same-referent→UNMET, unrelated→abstain) is a genuine, general, reusable STRUCTURAL/RELATIONAL algorithm — it is not per-item hard-coded, and it correctly generalizes to any goal/outcome pair once (a) both verbs are class-tagged and (b) the referents can be linked. This is real mechanism, not memorization (confirmed by the self-test's decisive flip case: the SAME word "sank" is scored MET in one context and UNMET in another, purely from which class the ANTECEDENT goal specified — a lexicon-only mechanism could not do this). But the two INPUTS the algorithm consumes (verb→class, referent→referent link) are each themselves gated by supplied lexicons (§1b, §3 below) or narrow acquired overlays (§6 below).
- **Brain counterpart:** this is structurally the closest thing in the pipeline to PFC goal-evaluation / anterior cingulate outcome-monitoring — comparing an intended end-state representation against an observed end-state representation for match/mismatch. The RELATIONAL COMPARISON operation itself (not the vocabulary it operates over) is brain-faithful in shape.
- **Limitation:** abstains (`NA`) whenever either verb is OOV of the class lexicon — which is the dominant failure mode on real prose (see Part 2).

**1d. `_verb_classes` / `_verb_classes_similarity` (Tier-1 exact / Tier-2 similarity)**
- **Representation:** `_verb_classes(lemma)` tries, in order: (Tier-1) exact `CLASS_REGISTRY` membership; (Tier-2) `_verb_classes_similarity` — argmax over `CLASS_REGISTRY`'s 12 classes' seed-exemplar-MEAN shared-feature cosine (via `hdlab.verb_lexical_similarity`, §2 below), floor=0.35, margin=0.15 (top pick must beat runner-up by ≥0.15); (Tier-3) a single-element "pole sentinel" (`{"ACQUIRED_REALIZED"}`/`{"ACQUIRED_BLOCKED"}`) read off `verb_lexical_similarity.ACQUIRED_OUTCOME_VERB_FEATURES`, the runtime-mutable overlay the word-acquisition loop writes into (§6).
- **Computes:** a 3-tier fallback chain, each stage OOV-safe (returns `set()`/abstain rather than guessing).
- **Meaning source:** Tier-1 = supplied lookup (§1b). Tier-2 = supplied hand-tagged FEATURES compared by cosine (§2 — NOT distributional, NOT learned). Tier-3 = a binary vote the acquisition loop computed (§6), itself choosing between two SUPPLIED pole tag-sets, never inventing a new one.
- **Limitation:** at every tier, the ceiling on what a verb CAN mean to this organ is the enumerated tag/class vocabulary a human wrote down in advance. Nothing here induces a new semantic dimension.

**1e. `_referent_links` (the discourse-entity linking, Tier-1/2)**
- **Representation:** three tiers — literal string match; `is_pronoun_mention` + `gender_number_for` + `gn_compatible` (production coreference primitives, genuinely GENERAL — not bank-specific, reused from `hdlab.coreference_resolver`); shared-feature cosine via `hdlab.lexical_similarity.concept_similarity` (§3) gated at `SIMILARITY_LINK_THRESHOLD=0.50`.
- **Meaning source:** Tier-1 pronoun-coreference tier is a genuine GENERAL grammatical mechanism (gender/number agreement — this is real, reusable, not per-item). Tier-2 synonym-linking is the same supplied-feature-cosine substrate as everywhere else.
- **Brain counterpart:** hippocampal/PFC relational binding for pronoun resolution is well-established; this tier is honestly brain-general. The synonym tier is again ATL-hub-style (see §3), i.e. supplied-feature not grounded.
- **Limitation:** OOV-of-`CONCEPT_FEATURES` referents (89 concepts total) never link at Tier-2 — falls through to no-link, which is safe (never a false MET) but caps recall.

### 2. `hdlab/verb_lexical_similarity.py` — the verb-feature-tagged sibling organ

- **Representation:** two disjoint `Dict[str, FrozenSet[str]]` dicts — `OUTCOME_VERB_FEATURES` (~65 lemma-keys, tags like `{STRUCT_INTEGRITY_DOM, POS_AFFECT, AGONIST_REALIZED, SCALE_UP, RESULT_ROOT}`) and `GOAL_VERB_FEATURES` (~50 lemma-keys, tags like `{DESIDERATIVE_DOM, NON_IMPLICATIVE_COMPLEMENT, BOULETIC_FORCE, UNREALIZED_FUTURE_DIRECTED}`). Each tag is itself a raw string label — encoded into an FHRR complex64 vector via `unit_phase_vec` (one fixed random phasor per tag, seeded, cached), and a word's concept vector is `bundle()` (the substrate's own superposition op) over its tag-vectors.
- **Computes:** `word_similarity`/`mean_similarity_to_seeds`/`classify_2way` — cosine of two words' bundled tag-vectors (`Re(sum(conj(a)*b))/d`), argmax-with-margin against two named seed pools.
- **THE FEATURE CONVENTION, inspected directly (not taken on the docstring's word):** every entry is a HAND-WRITTEN categorical label assigned by a human reading the word and applying a "rubric" (the module docstring cites Jackendoff 1990 Action-Tier AFF polarity, Talmy 1988 force-dynamics, Beavers 2008/2011 scalar affectedness, Karttunen 1971 implicative typology — i.e. the rubric IS linguistic theory, applied by a human, not learned from data). There is no corpus co-occurrence statistic anywhere in this file, no reward signal, no perceptual/sensorimotor input. `EVENT_DOMAIN` tags (`STRUCT_INTEGRITY_DOM`, `APERTURE_DOM`, `SOCIAL_EVAL_DOM`, ...) are themselves supplied categories the human INVENTED when an existing domain didn't fit ("forcing these into an ill-fitting existing domain would be linguistically dishonest, so a new... domain tag is used instead" — line 182-186, an explicit admission that domain-tag creation is a human editorial act, not an induction).
- **Meaning source: SUPPLIED, unambiguously.** This is the module's own honest self-assessment too (docstring: "General open-vocabulary feature INDUCTION for arbitrary, never-hand-tagged verbs remains a separate, missing-LEARNING follow-up"). The self-test's own "circularity check" (scrambling the word→feature assignment collapses the polarity gap) proves the SIMILARITY COMPUTATION is earning real structure from the tags — but that only shows the cosine-over-bundled-tags MATH isn't an artifact; it says nothing about where the TAGS came from, which is squarely human authorship.
- **Brain counterpart:** none of the tag CONTENT has a brain-grounding claim; the module's own docstring is unusually candid about this — it explicitly cites Muraki/Pexman/Binney 2025 finding that the ATL-hub story does NOT extend to verbs (desire/intention verbs recruit mPFC/TPJ mentalizing circuits, not the posterior-temporal action-semantics network), and says only the domain-general "shared-feature-cosine COMPUTATION" is reused, "not a literal claim that verb meaning lives in one hub the way noun meaning does." That is the single most honest sentence in the whole pipeline about the supplied-vs-grounded distinction.
- **The ACQUIRED overlay (increment 1/1b write-back):** `ACQUIRED_OUTCOME_VERB_FEATURES`, empty at import, mutated ONLY by `register_acquired_outcome(word, polarity)` — which does `ACQUIRED_OUTCOME_VERB_FEATURES[word] = acquired_tags_for_polarity(polarity)`, and `acquired_tags_for_polarity` returns literally one of exactly two hard-coded frozensets: `_ACQUIRED_POS_TAGS = {"POS_AFFECT","AGONIST_REALIZED","SCALE_UP","RESULT_ROOT"}` or `_ACQUIRED_NEG_TAGS = {"NEG_AFFECT","AGONIST_BLOCKED","SCALE_DOWN","RESULT_ROOT"}`. **This is the crux fact for the adversarial question below: the acquisition loop's write-back is a 1-bit decision (which of 2 supplied tag-sets) — it never proposes a new tag, never proposes a domain, never learns a feature dimension. It is a classifier choosing among pre-specified answers, not a feature-induction mechanism.**

### 3. `hdlab/lexical_similarity.py` — the noun/ATL-hub analog organ

- **Representation:** `CONCEPT_FEATURES: Dict[str, FrozenSet[str]]`, 89 concepts (86 from `exp_n11c` + 3 supply additions), same FHRR-bundle-of-tag-vectors convention as §2, e.g. `"boat": {"NAUTICAL","WATERCRAFT","HAS_HULL","CARRIES_PEOPLE"}`, `"sister": {"SOCIAL_ROLE_DOM","FAMILY_RELATION"}`.
- **Computes:** `concept_similarity(a,b)` = cosine of bundled feature vectors; `SIMILARITY_LINK_THRESHOLD=0.50` (measured: `sim(vessel,ferry)=0.634` links, `sim(sister,rival)=0.398` and `sim(vessel,dock)=0.279` do not).
- **Meaning source:** SUPPLIED, McRae-style hand-authored feature norms (the module cites McRae/Cree/Seidenberg/McNorgan 2005 explicitly as the DATA convention it's copying, and is explicit that this is "DATA supply" in its own docstring header line 4). The FHRR bundle+cosine COMPUTATION is the substrate's own glass-box op (genuinely reused machinery, not borrowed), but again the tag values are 100% human-authored.
- **Brain counterpart:** this one DOES have a real, specific, cited brain-grounding claim for the COMPUTATION's shape: Cox et al. 2024 (PMC12224414) — vATL intracranial activity is graded/multidimensional and tracks McRae-style behavioral-feature-norm overlap, not raw co-occurrence. So the CLAIM here is narrower and more defensible than it might first read: "the way vATL computes graded similarity (feature-overlap, not co-occurrence-frequency) is what our cosine-over-bundled-tags reproduces" — a claim about COMPUTATION SHAPE, not about where the features come from. The paper itself doesn't claim vATL feature norms are innate; McRae-style norms are elicited from adult human raters, i.e. from a lifetime of grounded conceptual experience compressed into introspectable properties — exactly what our organ is missing the ACQUISITION of.
- **Limitation:** 89-concept vocabulary; genuinely a "domain-general shared-feature-cosine machine with no built-in dictionary" — the mechanism can, in principle, run over ANY tag set; it just doesn't currently have a way to acquire tags for a new concept except a human writing them.

### 4. `hdlab/context_grounded_valence.py` + `experiments/exp_grounded_appraisal_sim_earned_v1.py` — the one genuinely reward-earned component

This is the most important component to get right because it's the ONE place in the whole pipeline where "meaning" is not supplied by a human writing a lookup table.

**What the appraisal-sim ACTUALLY earns (read from the RL loop itself, not the docstring):**
- **World:** a purely synthetic, hand-designed simulation. 4 situation types (`BLOCK_HIGH`/`BLOCK_LOW`/`RECIPROCITY`/`NEUTRAL`), 8 discrete actions (`pursue`/`withdraw`/`harm(c0..c2)`/`help(c0..c2)`), and a hand-written `reward(ep, action)` function (e.g. `BLOCK_HIGH` + `harm(true coherent blocker)` → `+1.0`; `harm` anyone else → `-0.5`; anything else → `0.0`). Every one of these categories, every reward value, and the causal-coherence-vs-recency decorrelation is AUTHORED by the experiment designer. This is explicitly acknowledged in the file's own header comment: "GUARDS: ... supply only innate + appraisal schema."
- **Learning:** `train_theta` is a genuine online delta-rule contextual bandit (`theta += LR*(r - Q(s,a))*phi(s,a)`) over FHRR-encoded features (action-type, target-candidate coherence/recency, congruence, coping — all IDENTITY-FREE, i.e. the theta never sees WHICH candidate, only whether the candidate IS coherent). This is real TD-learning, and the file has genuine can-fail floors that PASS on disk: `RANDOM` (untrained theta) → near-chance; `MEMORIZED` (identity-keyed features instead of coherence/congruence) → fails to generalize to a held-out identity pool (`abs(Ft-F)<=0.10` generalization-gap check, `M<0.30` collapse-floor); `NO_APPRAISAL` (drops congruence/coping features) → measurably worse (`appraisal_nonvacuous = (F-NA)>=0.05`); a `coh_minus_rec_readout` witness shows the learned Q-values genuinely prefer harming the CAUSALLY COHERENT candidate over the merely-RECENT one. **This part is real, earned, glass-box, brain-relevant (Q-learning/dopaminergic-RPE-style valuation is a defensible OFC/striatal analog) — it is not a fake.**
- **BUT — what is actually consumed downstream, read off `score_item`/`combine_biased_competition`:** the 3-stage pipeline is `governor-perceptron → event-assembly(animacy) → biased-competition(situation > event > governor)`. `combine_biased_competition`'s 3rd argument, `situation_type`, when non-`None`, DOMINATES the other two stages by construction (biased-competition precedence). `channel_b_valence_table` (in `word_acquisition_loop.py`, but exercising `context_grounded_valence.score_item`) computes exactly this: pass `situation_type="RECIPROCITY"` on a throwaway canonical clause (`"she held the cup"`) and `situation_type="BLOCK_HIGH"` on the SAME clause — the returned `valence` differs ONLY because `situation_type` overrode everything else; the clause content is provably irrelevant (the code comment says so explicitly: "content is irrelevant (situation_type dominates); a valid tokenized item only"). **This means: in the ONLY way this "earned" theta is actually wired into word-meaning acquisition, it returns exactly ONE of TWO possible numbers, selected by a 2-way categorical variable that was ALREADY DECIDED by a hand-authored structural detector upstream (`goal_congruence_appraisal_type` — has_direct_object + animate_agent + passive + result_particle, pure surface syntax, zero verb identity).** `word_acquisition_loop.py`'s own increment-1b docstring confirms this is not a research overclaim but the SUBSTRATE'S OWN MEASURED FINDING: "the reward-theta was a fixed 2-value sign constant, dropped as proven-redundant, not a capability loss" (verified: increment 1b replaces the entire theta-lookup with a hard-coded `RECIPROCITY→POS / BLOCK_HIGH→NEG` map in `structural_vote`, with the pre-reg documenting this as measured-redundant, not assumed).
- **Meaning source:** genuinely EARNED, but earned about 4 ABSTRACT SITUATION CATEGORIES in a toy world that never contains a word. As reused for verb acquisition, its net informational contribution collapses to a constant sign lookup gated by a hand-authored syntactic classifier — so the "grounding" that's actually exercised on the path to a verb's polarity is 0 bits beyond what the syntactic classifier already decided.
- **Brain counterpart:** the RL/valuation machinery itself is a legitimate OFC/striatal-RPE analog; genuinely earning coherence-over-recency targeting is a real result. The bridge from "abstract 4-category situation-model" to "specific verb's lexical meaning" has no brain analog implemented here — the brain's equivalent would be forming an association between a WORD FORM and the reward/consequence of the SITUATION it describes, accumulated over thousands of narrated/lived episodes; nothing in this pipeline reads a verb's surface form INTO the RL loop at all (`phi()` never encodes lexical identity for `FULL`/`RANDOM`/`NO_APPRAISAL` — only `MEMORIZED` does, and that's the arm specifically designed to FAIL/generalize-badly).
- **Limitation, precisely stated:** is genuinely earned-not-supplied, but grounds a 4-way ABSTRACT ontology disconnected from lexical form; the bridge to lexical form is 100% hand-authored syntax (never learned, never reward-shaped itself).

### 5. `hdlab/goal_owner_select.py` — owner selection (how the above gets consumed)

- **Representation:** `GoalOutcomeRegister` (byte-identical extension of `AccumulateRegister`, the substrate's own FHRR relational-binding register — `bind`/`bundle`/`cleanup_argmax` over a role vocabulary `{GOAL, ACTION_AGAINST, OUTCOME_UNMET, OUTCOME_MET}`).
- **Computes:** `directed_goal_outcome_score` — for ONE proposed candidate (a hypothesized entity for the outcome slot), accumulate that candidate's OWN whole-passage (role,entity) sequence into a FRESH register, then decode whether the candidate's outcome-slot entity ALSO carries an earlier GOAL binding under that SAME assignment. `enumerate_and_score`/`select_outcome_owner` do this for every roster entity and argmax, with a content-coherence tie-break (goal-theme head-noun overlap with outcome-theme head-noun) for ties.
- **Meaning source:** this is the part of the pipeline closest to pure MECHANISM with no lexical-knowledge content of its own — the binding/decode operation is domain-general (it would work over any role vocabulary); its only "knowledge" ingredient is which role each event gets (GOAL vs UNMET vs MET), which is supplied entirely by upstream `type_goal_events` (§1). The referent resolver (`GeneralRecencyEntityResolver`) is a genuine structural (gold-free) grammatical mechanism: subject-first single-pass name/pronoun scan + backward-search gender/number recency resolution — no lexical semantics at all, purely syntactic/discourse-positional.
- **Brain counterpart:** hippocampal relational/conjunctive binding (this is the module's own repeatedly-cited framing, and it's an apt one — a fresh per-candidate register that binds role+entity and is later queried is structurally analogous to pattern-separated episodic binding). The Tier-3 evaluative/affect BRIDGING functions (`detect_evaluative_construction`, `detect_affect_state_construction`) are Graesser Class-7 backward causal-antecedent bridging inference — genuinely a different, higher-level mechanism (inference over discourse, not lexical similarity), and per the module's own self-tests, provably NON-lexical (mg2 case: outcome sentence "You are a dear, good boy, Henry" shares ZERO verb/theme overlap with the goal sentence, so ONLY the bridge — never Tier-1/2 lexicon or similarity — resolves it). This is a real, distinct, validated inferential capability.
- **Limitation:** the binding/decode mechanism and the bridging-inference mechanism are both brain-faithful shape and genuinely general — but they are 100% downstream consumers of whatever `type_goal_events`/`_verb_classes` already decided about verb meaning (§1). If the outcome verb never gets typed (never gets a role at all), this component has literally nothing to bind — it cannot rescue an OOV verb; it can only correctly ROUTE a verb meaning that was already recognized elsewhere.

### 6. `hdlab/word_acquisition_loop.py` — the learning attempt, and why it HARD_FAILed

- **Representation/orchestration only** — every load-bearing primitive is reused, not reinvented: PROPOSE = `predictive_coding.threshold_gate`; Channel A = `hdlab.learner` MDL induction over 4 boolean CLAUSE-STRUCTURE atoms (`has_direct_object`, `patient_np_present`, `result_particle_present`, `subject_is_animate_agent`) — **never the target verb's lemma**; Channel B (increment 1) / `structural_vote` (increment 1b) = `goal_typing.goal_congruence_appraisal_type`, itself pure argument-structure + animacy (no verb identity, no co-occurrence stat); CONSOLIDATE = `MIN_CONFIRM>=2` signature-match + `self_improving_loop.decide_keep_or_revert` abstain-band margin gate; WRITE-BACK = `verb_lexical_similarity.register_acquired_outcome` (§2's 1-bit tag-set choice).
- **The PROPOSE gate, inspected — a caveat the docstring doesn't surface:** `word_is_novel(lemma)` builds a synthetic 8-dim vector, `np.ones(8)` if the lemma is ALREADY in the base lexicon, `np.zeros(8)` if not, and feeds that to `threshold_gate` as (observed=ones, predicted=constructed). This IS the real production `predictive_coding.threshold_gate` function — but the "residual" it's computing is a fabricated stand-in that only encodes `lemma in dict`, not any actual predictive/perceptual residual over real content. Calling this "the same residual gate the substrate uses for novelty everywhere" (module docstring, line 68-70) is accurate about which FUNCTION is called but overstates what's being MEASURED — it's `lemma not in OUTCOME_VERB_FEATURES` wearing a predictive-coding costume. Not load-bearing for the audit's main finding, but a genuine instance of "read the code, not the label."
- **What actually happened (disk-verified, `data/exp_grounded_word_acquisition_increment1b_v1/metrics.json`, HARD_FAIL):** `structural_core_only` primary_accuracy = **16/36 = 0.4444**, BELOW the majority-class floor of **0.6389** — i.e. the learned structural-construction→polarity classifier is WORSE than always guessing the majority class. `unmet_recall = 2/13` (0.15) — it almost never correctly identifies a negative outcome. The `desiderative_eligible_subset_accuracy=0.3889` is BELOW the `flat_fallback_subset_accuracy=0.5` (Gate 5 fail: the learned mechanism is worse than the dumb fallback it's supposed to improve on). The noise-canary check shows `noise_consolidated=2/8` — meaningless/control words (`"answered"`, `"carried"`) got CONFIDENTLY (wrongly) consolidated with a polarity, an anti-drift LEAK, not just a miss. The scramble control (`scrambled_primary_accuracy=0.3667`) is close to the real accuracy (0.4444) rather than collapsing well below it, meaning the mechanism's real performance is not decisively above what a scrambled (meaningless) version of itself achieves.
- **Root cause, precisely (this is the "structural clause read measures transitivity not result-polarity" finding, verified against the code, not just asserted):** `CHANNEL_A_ATOMS = ["has_direct_object", "patient_np_present", "result_particle_present", "subject_is_animate_agent"]` are pure TRANSITIVITY/ARGUMENT-STRUCTURE cues. These cues correlate weakly-to-not-at-all with RESULT VALENCE across the general verb lexicon: e.g. "ruin," "spoil," "waste," "damage" (NEG) are all transitive-with-direct-object in exactly the same surface pattern as "mend," "fix," "save," "build" (POS) — `"She ruined the cake"` and `"She fixed the cake"` are STRUCTURALLY IDENTICAL clauses. No amount of MORE DATA of this same structural-atom shape can fix this, because the atoms genuinely do not carry the discriminating signal — this is a real negative result about feature choice, not underpowering. Channel B is not a rescue either: it reduces to the same collapsed-to-2-constants sign lookup from §4, gated by the SAME kind of surface syntax (has_direct_object/animate_agent/passive/result_particle) as Channel A — so both channels are, at bottom, TRANSITIVITY DETECTORS wearing different clothes, and transitivity does not determine polarity.
- **Meaning source:** genuinely an attempted LEARNING mechanism (MDL construction-induction is real, general, glass-box, and correctly implemented — it faithfully reports its own failure rather than being tuned to hide it, which is itself evidence of honest instrumentation). But it is learning FROM a feature space (clause transitivity/argument-structure) that does not contain the needed signal, so it HARD_FAILs honestly. This is the substrate's one real ATTEMPT to close the "features supplied vs. learned" gap for a decision-relevant axis, and the attempt's own numbers are the clearest evidence for where the wall actually is.

## PART 2 — the test case, traced component-by-component

**Passage:** `"Tom wanted to buy a bicycle. He wasted his savings."` — `waste` is OOV of every lexicon in the pipeline.

1. **`lemma_verb`** (spot-checked, `hdlab/thematic_role_labeler.py:178-199`): `"wasted"` → not irregular, doesn't end `ing`/`ied`, ends `ed` with len>3 → strip `"ed"` → `"wast"` (no double-consonant match, so no further strip). `"buy"` → no suffix rule matches → stays `"buy"`. Confirmed by direct trace of the suffix-strip logic, not assumed.

2. **`find_desired_state("Tom wanted to buy a bicycle.")`:** `dv_idx` locates `"wanted"` (in `DESIDERATIVE_PASS`). Scans forward, finds `"to buy"` (not `DET_STOP`). `embedded_lemma = "buy"`. `classes = _verb_classes("buy")`:
   - Tier-1: `"buy"` is in NONE of the 12 `CLASS_REGISTRY` sets → `{}`.
   - Tier-2: `_verblex.in_lexicon("buy", "outcome")` → `"buy"` is NOT in `OUTCOME_VERB_FEATURES` (checked directly against both `OUTCOME_SEED_POS`/`_NEG` and `OUTCOME_HELDOUT_POS`/`_NEG` dicts — absent from all four) → abstain, `{}`.
   - Tier-3: `ACQUIRED_OUTCOME_VERB_FEATURES` is empty at process start (never populated in production; only populated inside an acquisition-loop run) → `{}`.
   - `classes = set()`. Since neither `SUBJECT_IS_REFERENT_CLASSES` nor `OBJECT_IS_REFERENT_CLASSES` intersects an empty set, `referent = None`.
   - `desired = {"referent": None, "classes": set(), "verb_lemma": "buy", "pattern": "CONTROL"}`.

3. **`find_actual_state_candidates("He wasted his savings.")`:** scans every token; `lemma_verb("wasted")="wast"`; `_verb_classes("wast")` — Tier-1 no, Tier-2 no (`"waste"`/`"wast"` is absent from `OUTCOME_VERB_FEATURES` — confirmed, not present in any of the four source dicts nor the `_OUTCOME_LEMMA_VARIANTS` truncation map), Tier-3 no (empty overlay) → `classes=set()` → this token does NOT get appended as a candidate (the `if classes:` filter in `find_actual_state_candidates` requires a non-empty class set). No other token in the sentence carries a class either. **`candidates = []`.**

4. **`congruence_decision`:** `desired is not None` (proceeds past the first abstain check) but `candidates` is empty → **returns `("NA", {"reason": "actual_verb_class_unknown", ...})`** immediately — note it never even reaches the referent-linking or class-relation logic, because there's nothing to compare against.

5. **`congruence_with_lexicon_fallback`:** verdict is `NA` → falls back to `lexicon_predict("He wasted his savings.")`:
   - `V2_OUTCOME_UNMET`/`_MET` (flat 17-word list) — `"wasted"` is absent (the set has `"lost"`/`"lose"`/`"failed"`/`"fail"` etc. but not `"waste"`/`"wasted"`).
   - Tier-2 fallback scan (`_tier2_outcome_polarity_scan`) — for each token OOV of the V2 lexicon, lemmatize + `_outcome_polarity_tier2`, which calls `_verblex.classify_2way(lemma, _V2_POLARITY_SEED_POS, _V2_POLARITY_SEED_NEG, "outcome", ...)`. This REQUIRES `in_lexicon("wast", "outcome")` to be true for `mean_similarity_to_seeds` to return anything — it's False (same OOV fact as step 3) → `classify_2way` returns `None` immediately (`mean_similarity_to_seeds` returns `None` because the word itself, not just the seeds, is checked first) → abstain.
   - `has_unmet_t2 = has_met_t2 = False`. Combined with the literal-set miss → `lexicon_predict` returns **`"NONE"`**.

**Final answer: the pipeline returns NONE / no signal whatsoever** for a passage a six-year-old would instantly recognize as "he failed to get the bicycle." Two independent, compounding OOV failures produce this, not one:
- **(a)** `buy` — the GOAL's own embedded verb — is OOV of the class taxonomy, so the antecedent goal can't even be characterized as "wanting a possession" in a way that would let ANY outcome-verb be checked against it (this alone forces `congruence_decision` toward abstain even before the outcome sentence is examined).
- **(b)** `waste`/`wasted` — the OUTCOME's verb — is OOV of every tier (Tier-1 class registry, Tier-2 feature lexicon, Tier-3 acquired overlay, AND the flat V2 fallback lexicon), so `find_actual_state_candidates` returns nothing for the outcome sentence to compare against, and the lexicon-fallback backstop also has nothing to say.

Neither failure is a bug in the congruence LOGIC (§1c is exercised correctly here — it correctly abstains rather than guessing, which is the safe/precision-preserving behavior it was designed for). Both are OOV-of-a-fixed-vocabulary failures, and no component anywhere in the traced path has a way to look at "wasted his savings" and independently determine that wasting money is a bad outcome relative to a goal of acquiring something — that determination requires WORLD KNOWLEDGE about consequences (waste = expenditure without the intended benefit realized) that is not present, in any form, symbolic or learned, anywhere in the pipeline for this specific word.

## PART 3 — the adversarial adjudication

**Director's hypothesis:** "the wall = grounding (our verb-meaning features are hand-supplied/structural, not grounded)." **Verdict: substantially correct, but the precise, code-verified statement is narrower and more actionable than "grounding" alone suggests — it is grounding-of-the-relevant-scope, and it decomposes into two compounding facts, not one:**

1. **It is NOT primarily a coverage/data problem.** Adding `"waste"` as one more hand-tagged entry (SUPPLY) would fix this ONE example and would be the cheapest possible patch — but it would not touch the general problem, because the vocabulary is open-ended (English has thousands of result-verbs) and hand-tagging doesn't scale. More importantly, this session's OWN experiment (`word_acquisition_loop` increment 1b) directly tested the coverage-via-more-of-the-same-signal hypothesis — mining MORE corpus occurrences of the SAME structural atoms for held-out verbs — and it HARD_FAILed BELOW the majority-class floor (0.4444 vs 0.6389). That is a decisive, disk-verified refutation of "just needs more coverage of the same kind of signal." The signal itself (transitivity/argument-structure) does not carry the needed information, no matter how much of it you mine.

2. **It is NOT a representation-format problem.** The FHRR-bundle-of-tags cosine machinery (§2, §3) is a legitimate, general, glass-box, reasonably brain-analogous COMPUTATION (McRae/ATL-hub-shaped for nouns per Cox et al. 2024; domain-general for verbs, honestly caveated by the module's own docstring as NOT literally ATL for verbs). Swapping this for a different similarity metric or vector geometry would not change what CAN be represented — the ceiling is set by which tags exist, not by how tags are compared.

3. **It IS a missing-LEARNING-capability problem, AND it IS a grounding problem, and these are the SAME gap seen from two angles, not two separate ones.** The one component that could, in principle, ground a verb's meaning in something other than a human's a-priori judgment — the reward-earned appraisal-sim theta (§4) — is REAL (passes its own can-fail floors: RANDOM≈chance, MEMORIZED fails to generalize, NO_APPRAISAL measurably worse, `coh_minus_rec_readout>0`). But it grounds a CLOSED SET OF 4 ABSTRACT SITUATION CATEGORIES in a synthetic world that never contains a single word, and its only bridge to actual verbs is a 100%-hand-authored syntactic classifier (transitivity/animacy/passive/particle) — the SAME impoverished signal that sank the Channel-A structural-induction attempt. Verified directly from the code: when queried through the path word-acquisition actually uses, the "earned" component provably collapses to ONE OF TWO CONSTANTS (`channel_b_valence_table`, `combine_biased_competition`'s situation-dominates-everything precedence), and the substrate's OWN increment-1b experiment confirmed this is not incidental — removing the reward-theta lookup entirely and hard-coding the 2 constants was measured to be behaviorally IDENTICAL ("proven-redundant, not a capability loss"). So the grounded component contributes ZERO bits of verb-specific information to the acquisition pipeline as currently wired; all of its real "earning" is spent on a toy-world distinction (coherent-vs-recent target selection) that is a different problem from "what does 'waste' mean."

**Precise statement of the wall:** there is no mechanism ANYWHERE in this pipeline — supplied, structural, or earned — that can take an arbitrary novel verb's SURFACE FORM plus its narrative CONTEXT and produce a confident judgment of what happened to a goal, unless (a) a human already wrote that verb into a lookup table, or (b) it can be inferred from a signal (clause transitivity) that this session's own experiment proved does not carry that information. The one piece of GENUINELY EARNED machinery in the whole system (the appraisal-sim theta) is earning the wrong thing to help — it grounds situation-types, not word-forms, and nothing connects a word-form to the SITUATION MODEL'S own scored outcome for the episode that word occurred in (which is the mechanism that WOULD close this gap: instead of parsing a sentence's syntax to guess a situation-type, read the RESULT the situation model already independently derives for that episode from Component-5's own downstream binding — e.g. did the passage's goal-outcome binding, once resolved by other cues, come out MET or UNMET? — and use THAT as the reward-relevant label to associate with whatever verb occupied the outcome slot, closing a genuine text-to-consequence learning loop instead of the current syntax-to-situation-type-to-constant chain). That is precisely the direction the user's already-standing "6yo grounded foundation reading builds on" pivot points at, and this drill provides the code-level evidence for WHY that pivot, not another supplied-feature patch, is the correct next move.

## WHERE WE ACTUALLY STAND, PLAIN TERMS

Picture the whole pipeline as a chain of specialists, and picture "meaning" as a currency that has to originate somewhere before anyone downstream can spend it.

- **The grammar specialists (goal recognition, referent linking, binding, bridging inference) are genuinely good and genuinely general.** They can find "who wants what," track "who is who" across pronouns, and even do a kind of inference a plain lexicon can't (like realizing "you are a good boy" confirms a goal was met, with zero shared words). None of this is fake, and none of it is the problem.

- **The word-meaning specialist is a filing clerk, not a linguist.** Every verb's meaning — is buying good-for-a-goal, is wasting bad-for-a-goal — comes from a card a human wrote and filed in advance (a hand-typed tag list). The clerk can find a near-match by comparing cards (that's the "similarity" mechanism), but if no card was ever filed for a word, the clerk has nothing to say, no matter how obvious the word's meaning would be to a person.

- **We built one specialist who genuinely LEARNS meaning from consequences instead of being told it** — a small reward-driven simulation that discovers, on its own, that hurting the actual cause of a problem (not just the most recent suspect) is what pays off. That specialist is real and it works. But it currently only learns about a tiny made-up world of 4 abstract situations that never contains an actual word — it has never been shown a story. Its only connection to real words runs through the filing clerk's same limited toolkit (checking whether a sentence LOOKS transitive), which we directly tested this session and found does not reliably predict whether a verb's outcome was good or bad — "she fixed the cake" and "she ruined the cake" look identical to that toolkit.

- **We also tried to teach the filing clerk to write its own new cards from context clues alone (the acquisition-loop experiments), and that attempt HONESTLY FAILED** — worse than just guessing the most common answer. That's not a wasted result; it's a clean, disk-verified proof that "clause shape" isn't the missing ingredient. The missing ingredient is something more like real experience: reading a lot of stories and, for each new verb, connecting it to the CONSEQUENCE the rest of the story reveals (did the goal end up met or not) — which is exactly the reward-learning specialist's talent, just never pointed at real text.

- **So the wall is not "we chose the wrong math" and it's not "we just need to type in more words."** It's that the one part of the system that can learn word-meaning from experience instead of being handed it has never been connected to actual narrative experience — only to a synthetic toy world. Connecting it — teaching the substrate to associate a verb's surface form with the outcome its OWN situation-model later works out for that episode — is the specific, buildable next step this drill points to, not a vague "add grounding" instruction.
