## HEADLINE

**The brain does NOT run one big fuzzy search over a lifetime of memory. It runs a cheap, staged pipeline: (1) a compressed, sparse INDEX (hippocampal index theory / schema-gating) narrows a huge distributed store down to a small context-consistent candidate set BEFORE any fine completion runs; (2) an autoassociative attractor network (CA3, fed by DG's decorrelating expansion code) completes the partial cue to the nearest stored pattern WITHIN that narrowed set, in a small, load-independent number of settling steps; (3) relational/transitive inference over the store is either fast pattern-completion CHAINING across separately-stored episodes at retrieval time (REMERGE) or a precomputed, content-agnostic STRUCTURAL code (Tolman-Eichenbaum Machine; symbolic-distance-effect / rank-code literature) laid down at consolidation time that turns multi-hop inference into an O(1) comparison, decoupled from chain length. Fuzzy access stays cheap ONLY BECAUSE of stage (1) -- without a narrowing/index step, attractor-style cleanup (biological or modern-Hopfield/attention-style) costs O(candidate-set-size) per settling step, it does not become free by fiat.**

This project already has three of the four needed pieces built and separately validated (exact-paging index/narrowing, DG-style decorrelation front-end, pinv/resonator-style attractor completion, and K-hop algebraic relational traversal) plus a hybrid two-stage precedent (PP-125/126) that already gets fuzzy-narrow-then-exact-hop working end to end at recall@2=0.82-1.0. The missing piece is NOT a new mechanism -- it's composing these into one loop with a SOFT/redundant (not hard-hash) coarse-narrowing step, per the RC2 cautionary result.

P_deflated (novel-synthesis mapping of the architecture, composition of already-validated on-platform pieces + well-established biology): **0.42** (see calibration below).

## (a) THE BIOLOGY

### A1. CA3 pattern completion (autoassociative attractor from a partial cue)

CA3 recurrent collaterals form a Hopfield-like autoassociator (Marr 1971, *Phil Trans R Soc B*). Treves & Rolls (1994, *Hippocampus*; Rolls 2013, *Front Cell Neurosci*) give a closed-form sparse-network capacity: `p_max ~ k * C_RC / (a * ln(1/a))`, C_RC = number of modifiable recurrent synapses/neuron, a = activity sparseness, k~0.2-0.3; using rat anatomy (C_RC~12,000, a~0.02) this yields p_max ~ 36,000 stored patterns of the same order as an independent Willshaw-style estimate (Lisman/Idiart, *Learn Mem* 2007, P=c/a^2, ~20,000). Nakazawa et al. (2002, *Science*) give direct causal evidence: CA3-specific NMDAR knockout mice retrieve normally from FULL cues but selectively fail from PARTIAL cues -- CA3 recurrent plasticity specifically supports completion, not storage per se. Basin-of-attraction size (how much cue corruption still converges to the correct pattern) shrinks as more patterns are stored -- a robust theoretical result (well-established in the abstract Hopfield/attractor math; no clean hippocampus-specific accuracy-vs-corruption-fraction curve was found, medium confidence on the biological magnitude). Settling to a completed pattern takes ~1-2 gamma cycles (~5ms) essentially independent of how many patterns are stored, PROVIDED the network stays below capacity (Learn Mem 2007 gamma-oscillation model) -- i.e. retrieval cost is flat well below capacity and degrades near/above it, not a free lunch at all loads.

### A2. Dentate gyrus pattern separation (why CA3 doesn't confuse similar cues)

DG massively expands and sparsifies the EC input via strong feedforward inhibition (near-winner-take-all), decorrelating similar inputs before CA3 sees them (Leutgeb et al. rate/global remapping literature). This is a precondition for A1's capacity formula to hold in practice -- without decorrelation, similar stored patterns collide and basins overlap.

### A3. Hippocampal indexing + schema-gating (how the huge store gets narrowed BEFORE completion runs)

Teyler & DiScenna (1986) / Teyler & Rudy (2007): the hippocampus does not store content -- it stores a small, sparse INDEX that points to which distributed cortical loci were co-active. Retrieval = pattern-complete the (small) index from a partial cue, then the index reinstates the FULL cortical pattern via back-projection. This collapses the search problem from "search all of cortex" to "complete a small index," and a very recent formal treatment (Gershman, Fiete & Irie 2025, arXiv:2501.02950, "Key-value memory in the brain") explicitly reframes this as a **key-value store**: hippocampus holds keys, a query matches keys (not full content), matched keys address cortical content. Tse et al. (2007, *Science*; 2011, *Science*) show a pre-existing SCHEMA lets new schema-consistent facts be assimilated near-instantly, bypassing slow consolidation -- functionally, the schema is a retrieval STRUCTURE that narrows candidates by category/context before any fine completion. Content-addressability is genuine WITHIN a level (CA3 retrieves a whole pattern from a partial cue in one parallel settling process, not a scan) but the full pipeline is STAGED ACROSS levels (index -> reinstatement -> cortical elaboration) -- "parallel within a stage, staged across stages" is the accurate synthesis, not pure flat parallelism over the whole store. Context/theta-phase gating and the encoding-specificity principle (Tulving & Thomson 1973) further act as a coarse pre-filter: a cue only succeeds if it recreates enough of the original context, which is itself a narrowing mechanism, not just recall accuracy.

### A4. Relational / transitive inference over the store

Eichenbaum & Cohen's relational-memory theory: hippocampal binding is FLEXIBLE (decomposable/recombinable) so memories can be used in combinations never seen at encoding. Two mechanisms, both empirically supported, at DIFFERENT stages: (i) REMERGE (Kumaran & McClelland 2012) -- separately stored, pattern-separated episodes are combined ONLINE via recurrent interaction at retrieval/query time (chaining); (ii) integrative encoding (Zeithamova & Preston; Shohamy & Wagner 2008) -- overlapping episodes get FUSED into one conjunctive trace at encoding/consolidation time. Dusek & Eichenbaum (1997, *PNAS*) show the hippocampal system is necessary for the inferential jump itself (lesions abolish transitive inference while sparing trained pairs). Critically, the classic SYMBOLIC-DISTANCE EFFECT (faster/more-accurate inference for pairs with MORE intervening items, opposite of what serial hop-by-hop chaining predicts) plus a recent formal treatment (Lippl et al. 2024, PMC11252811, "A mathematical theory of relational generalization in transitive inference") show that broad classes of these systems spontaneously assign each item a scalar RANK during learning/consolidation, so that query-time inference is a single O(1) rank comparison, DECOUPLED from chain length/hop-count -- the cost is pushed into offline (sleep/replay-supported) precomputation of an integrated structural code, not paid per-query. The Tolman-Eichenbaum Machine (Whittington, Behrens et al. 2020, *Cell*) instantiates this: a content-agnostic STRUCTURAL code (entorhinal-like, updated via path-integration/attractor dynamics) is factored from CONTENT (hippocampal, conjunctive binding of structure + sensory input) -- because the structural code is content-agnostic, the same learned relational structure zero-shot-generalizes to new content domains.

### A5. Classical / ML mirror: SDM, modern Hopfield, ANN retrieval

Kanerva's Sparse Distributed Memory (1988): hard locations in a huge binary Hamming space; writes/reads pool over ALL hard locations within a Hamming-radius, giving fuzzy-cue retrieval BY CONSTRUCTION via a closed-form critical-distance formula (volume-of-intersection of hyperspheres). Fully glass-box (closed-form, no gradient-trained weights). Classical Hopfield capacity ~0.138N; Krotov & Hopfield (2016) dense associative memory (polynomial energy, capacity ~N^(n-1)); Ramsauer et al. (2020, "Hopfield Networks is All You Need") push to an exponential/softmax energy function giving capacity exponential in dimension AND prove this update rule is algebraically identical to transformer attention. Iteration COUNT to converge stays ~flat regardless of store size, but EACH iteration still computes a similarity/softmax over ALL stored patterns -- so **per-step compute is O(store-size)**; capacity growth does not come free of per-step cost growth. Two-stage engineering retrieval (IVF+PQ, Jegou et al. 2011; HNSW, Malkov & Yashunin 2016) gets query cost to O(log N) or effective sublinear by running a COARSE index/quantization step first (narrow to a shortlist) then FINE re-ranking only on that shortlist -- structurally identical in role to the hippocampal index. Direct biology<->engineering link: Bricken & Pehlevan (2021, NeurIPS, arXiv:2111.05498) formally show transformer attention closely approximates Kanerva SDM under realistic data conditions (verified on pretrained GPT-2); HippoRAG (arXiv:2405.14831) builds an LLM memory system explicitly on hippocampal-indexing theory (index over content, PageRank-based narrowing).

**Confidence:** A1/A2 core mechanism + Nakazawa causal evidence = well-established; exact capacity numbers = well-established WITHIN the Treves-Rolls framework (theory-derived, not directly measured in vivo) -- medium-high. A3 index/schema theory + Gershman-Fiete-Irie 2025 key-value reframing = well-established/high. A4 REMERGE-vs-integrative-encoding as complementary (not competing) = medium (active area); symbolic-distance-effect + rank-code O(1)-decoupling = high on the empirical effect, medium on the "hop-count decoupling" framing (an inferential extension of the literature, not verbatim-stated). A5 SDM/modern-Hopfield capacity math = high; per-step O(N) cost nuance = medium (derived, not directly quoted); Bricken-Pehlevan link = high (directly on point).

## (b) GLASS-BOX SUBSTRATE ARCHITECTURE

Two-stage pipeline, mirroring A1-A5 exactly:

**Stage 1 -- coarse index/narrowing (the hippocampal-index / schema-gate / IVF-HNSW analog).** Assign every stored item a SHARD/bucket label at write time using the existing schema-fit signal from the >=3-signal ingest gate (schema-fit + recurrence + unexpectedness) as the schema/context tag -- this is literally Tse-style schema-consistency gating deciding which "index slot" a new memory joins. At query time, a fuzzy/partial cue is routed to candidate shard(s) via a SOFT, REDUNDANT coarse hash (multiple overlapping hash functions each voting for a shard, SDM-radius-pooling style, or the already-VET'd learned noise-robust page router a33c634c) -- NOT a single hard deterministic hash. This caution is directly forced by this project's OWN RC2 result (`exp_multihop_router_crt_residue_addressed_v1`, HARD_FAIL): a hard, non-redundant per-modulus CRT decode lost to a naive full-vector baseline for exactly the reason 50 years of RNS/CRT coding theory and the grid-cell biology (A3, redundant population + soft decode) both predict -- one wrong hard decision derails the whole reconstruction, no partial credit. The coarse-narrowing step here must inherit REDUNDANCY + SOFT VOTING, not RC2's design.

**Stage 2 -- within-shard attractor completion (the CA3 analog).** Within the narrowed candidate shard (bounded size, held near but below the shard's own capacity, mirroring CA3's p_max formula), run the existing pinv auto-associative completion (`patternb_pinv_recovery_v1`, already VALIDATED acc=1.000 for 1-role partial queries) or resonator-network associative search (already characterized: `substrate_R6_b2_x_sparse_resonator_v1`, kmax_res=26 clean / kmax_b2res=8 under B2 superposition noise -- this IS an on-platform noise-tolerance-vs-load curve, the direct substrate analog of A1's basin-shrinkage-with-load). This step should be genuinely load-INDEPENDENT of the TOTAL store size because it only ever operates on the shard, not the whole store -- matching CA3's flat ~1-2-cycle settling time.

**Stage 3 -- relational compute over the retrieved subset.** `native_k_hop_reasoning` (A_rel^k matvec, algebraic graph-traversal, currently K=6 ceiling) plays the REMERGE role (online chaining across the shard's retrieved items). Per A4, a second construction should be tried: precompute a content-agnostic STRUCTURAL/rank code (a TEM-style transitive-closure embedding, built at "consolidation" time, decoupled from any particular content) so that multi-hop queries become an O(1) comparison against the precomputed structural code rather than K sequential hop-matvecs -- this could raise or flatten the current K=6 ceiling, OR (informatively) fail to, telling us whether the K=6 wall is representational/algebraic (same wall online and offline) or an online-computation artifact (removable by precomputation).

**Does this stay O(hops)-cheap, or what does fuzzy cost?** Cheap CONDITIONALLY: Stage 1 (shard narrowing) should cost O(hops)/O(log #shards) -- the same regime as the already-validated exact-paging store, since it's structurally an index lookup, not a full-store fuzzy sweep. Stage 2 (within-shard completion) should cost O(1) in TOTAL store size because it only ever touches one shard's worth of patterns (bounded by shard capacity, not by store size) -- this is the CENTRAL claim from the biology (A1, A5) and is NOT automatic; it requires stage 1 to actually work (shards must stay near-but-below their own capacity as the store grows, i.e. the substrate must ADD SHARDS, not grow shard size, as it scales -- exactly mirroring "more hippocampal index entries" not "one CA3 network holding everything"). Stage 3 relational cost is either O(K) (online chaining, current K=6 ceiling) or O(1) (if a precomputed structural code works) -- this is the one place where the literature (Lippl et al. 2024) directly predicts a real speedup is available, not just a capacity increase.

**Substrate-product implication:** this is directly a memory-quality lever, not a publication footnote -- if validated, it means fuzzy/partial-cue queries (a user's imprecise recollection, a noisy sensor readout, an approximate description) can be served at THE SAME COST as exact-key lookups already validated, PROVIDED sharding (not shard-growth) is the scaling discipline; and multi-hop relational Q&A over a huge fact-store could get cheaper (not just more capable) if a precomputed structural code is built during ingest rather than only doing online K-hop chaining at query time.

## Cheap decisive test

One CPU cell, reusing existing code paths (no new primitives): (1) tag stored items with a shard label using the existing schema-fit signal; (2) route a corrupted/partial query cue to shard(s) via a SOFT multi-vote hash (k independent hash functions, majority/union vote -- reuse a33c634c's noise-robust router logic if it generalizes, or a minimal from-scratch SDM-radius-pool baseline if not); (3) run existing pinv/resonator completion within the routed shard; (4) sweep cue-corruption fraction AND total-store-size (holding per-shard size near-constant by adding shards, not growing shards) and measure (i) completion accuracy vs corruption, (ii) completion cost vs total store size. Est. cost: ~1 day CPU (mostly composition of existing pieces, not new math).

## Falsifiable predictions (HARD-PASS / HARD-FAIL)

1. **Capacity-formula transfer.** Per-shard fuzzy-completion accuracy-vs-load should follow the SAME functional form already validated for this substrate (the reconciled exact-integral/d_eff capacity law from the 07-17 memory-chain-grade drill, or at minimum the qualitative monotone-degradation shape of `substrate_R6_b2_x_sparse_resonator_v1`). **HARD-PASS:** measured per-shard completion-accuracy-vs-load matches the existing validated capacity formula within the same tolerance band as the current reconciliation (no new capacity mechanism required). **HARD-FAIL:** per-shard completion capacity is >2x worse than the existing formula predicts even after correcting for effective-V, implying ITERATIVE/attractor cleanup has a genuinely different (worse) capacity law than the one-shot cleanup already characterized.

2. **Stage-1/Stage-2 cost decoupling.** Total query cost (route + complete) should grow at most O(log #shards) as TOTAL store size grows, provided shard COUNT (not shard size) scales with the store. **HARD-PASS:** at 10x total store size (via 10x more shards, each near its own capacity), measured compute grows <2x. **HARD-FAIL:** compute grows roughly linearly with total store size regardless of sharding discipline (narrowing doesn't actually reduce touched-candidate count, e.g. because the soft-hash's false-positive/union rate blows up with shard count).

3. **Soft/redundant routing beats hard routing on fuzzy cues.** Per the RC2 lesson + grid-cell A3 biology. **HARD-PASS:** a soft, redundant (multi-vote) coarse router beats a hard single-hash router by >=20% recall on corrupted-cue queries specifically (a comparable-magnitude effect, in the opposite direction, to RC2's -0.088 route-accuracy delta). **HARD-FAIL:** hard single-hash routing performs equivalently or better within noise -- meaning the RC2 lesson does not transfer to a narrow-then-complete regime (plausible since this router only needs to narrow candidates, not exactly reconstruct an address, so partial credit works differently than CRT's all-or-nothing decode; would be a genuinely informative refutation, not a re-run of RC2).

4. **Precomputed structural code decouples relational cost from hop-count.** Per Lippl et al. 2024 / symbolic-distance-effect. **HARD-PASS:** a precomputed transitive-closure/structural embedding lets multi-hop query accuracy stay flat (or degrade markedly less) past the current K=6 online-chaining ceiling. **HARD-FAIL:** the precomputed structural code shows no improvement over online K-hop chaining at K>6 -- informative because it would mean the K=6 ceiling is a genuine representational/algebraic wall (present online AND offline), not an artifact of paying the relational cost per-query rather than at consolidation time.
