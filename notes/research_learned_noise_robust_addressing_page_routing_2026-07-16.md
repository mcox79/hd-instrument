# Research note: can ADDRESSING itself be learned and noise-robust? (the perfect-page-table assumption, lifted)

**Date:** 2026-07-16
**Trigger:** Director task -- the whole memory/paging/reading thread (working-memory integration note, brain-N/sparse-capacity note, both `exp_wm_paging_*` cells) converged on one untested assumption: every cell that "decouples effective WM from active-N" does so GIVEN a perfect, hand-built page-table (`page_of = {node: node // page_size}`, an exact dict, not learned, not noise-tolerant). This note asks whether the addressing/routing step itself -- not just the completion/decode step -- can be learned and can stay correct from a partial/noisy content cue, leading with the brain's own solution to exactly this problem.
**Method:** 3 parallel Sonnet lit-scan sub-agents (public neuroscience/CS literature only, generic terms, no substrate specifics off-platform) covering (1) hippocampal memory indexing theory + place/grid cells as a learned generalizing coordinate system + the Tolman-Eichenbaum Machine, (2) dentate-gyrus pattern separation + CA3 pattern completion + the separation-completion tradeoff, (3) classical/modern Hopfield content-addressable memory + hashing/learned-index structures as a non-biological comparison class. Plus direct re-read of this project's own two paging cells and a directly-relevant prior negative result (DG-style pre-write separation composed with an existing completion mechanism).

## HEADLINE

**The brain does not solve "learn one function that is simultaneously noise-robust AND separates novel content" with a single mechanism -- it solves it with an architectural DIVISION OF LABOR between two purpose-built stages, and this project has already built (separately, for other purposes) a proven primitive for each stage but has never wired them together as a routing pipeline.** Hippocampal Memory Indexing Theory (Teyler & DiScenna 1986; Teyler & Rudy 2007) frames the hippocampus as a learned INDEX into distributed cortical content, not a copy of the content -- and the concrete circuit implementation of "learned index" splits into dentate gyrus (DG), which does **pattern SEPARATION** (expansion + extreme sparsification, a largely fixed/non-per-item-trained random-projection-plus-winner-take-all operation that maps ANY input, including ones never seen before, deterministically to a well-separated sparse address -- structurally identical to locality-sensitive hashing, Indyk & Motwani 1998), and CA3, which does **pattern COMPLETION** (a Hebbian recurrent-collateral attractor network -- mechanistically and, per Ramsauer et al. 2020, FORMALLY identical to one step of modern-Hopfield / transformer-attention retrieval -- that recovers a full stored item from a partial/noisy cue). The literature (O'Reilly & McClelland 1994) is explicit that separation and completion are **computationally antagonistic on the same substrate** (wide attractor basins buy noise tolerance but merge similar-but-distinct items; narrow basins buy separation but lose noise tolerance) -- the brain's answer is not a clever single mechanism that beats this tradeoff, it is putting one stage tuned to each end of the dial in series. A third, independent brain mechanism -- grid-cell multi-scale modular coding (Hafting et al. 2005; Fiete, Burak & Brookings 2008) -- solves a *different* piece of the same problem (a combinatorially large, generalizing address RANGE from small per-module codebooks, each module tolerating its own share of noise, mathematically a residue-number/CRT-style code) and is the closest biological analog to this substrate's own resonator/factorizer decode. **This project already has proven, chain-grade primitives for the DG stage (fixed random expand+sparsify projection, used in the Spoke-3 EC->DG design and the WM decoupled-dimensionality note; the block-local-K sparse resonator, HARD-PASS on factor recall) and for the CA3 stage (FHRR bind/unbind + codebook-argmax cleanup, the resonator machinery used in every paging/relational cell to date) -- but every existing paging cell (`exp_wm_paging_exact_store_ram_disk_v1`, `exp_wm_paging_relational_compute_v1`) hands the router an EXACT, hand-built dict (`node -> page`) instead of routing through a DG-style learned/fixed-projection stage.** That is the untested piece, and it is cheap to test because it is a re-pairing of existing parts, not new architecture.

**A directly-relevant prior negative must be respected, not waved away**: this project already ran a DG-style pre-write separator composed with an EXISTING completion/cleanup mechanism (dense-KV uniform-Tikhonov pseudo-inverse) and it HARD-FAILED at smoke -- geometric separation worked exactly as designed (eff-rank lift 5.79x, off-diagonal collapse 13x) but recall got WORSE, not better (`notes/exp_dev_anisotropy_dg_pattern_separation_prewrite_v1_SMOKE_HARD_FAIL_2026-06-26.md`). The diagnosis there was that the *specific downstream cleanup* (a Tikhonov solve that structurally exploits real-embedding correlational structure, i.e. the "cone") was incompatible with an upstream separator that destroys that same structure. This does not directly transfer to the cell recommended below (which pairs the separator with a plain codebook-argmax resonator cleanup on synthetic near-orthogonal phasors, not a Tikhonov solve on real anisotropic embeddings), but it is exactly the failure MODE this note's cell must guard against and explicitly ablate for: pairing a separator with the wrong completion partner can make things worse, not better, even when the separator's own geometry is working perfectly. This is why the recommended cell below is an ablation ladder, not a single arm.

## (a) How the brain learns + robustly uses addressing

### A1. Hippocampal Memory Indexing Theory (8 citations)

Teyler & DiScenna (1986, *Behav Neurosci* 100(2)) propose the hippocampus does not store episodic content -- it forms a sparse, conjunctive **INDEX**, a hippocampal activity pattern binding together the distributed neocortical ensembles active during an experience; because hippocampus receives convergent input from, and projects back to, those same cortical areas, a partial cue reactivating the index can pattern-complete the full distributed cortical trace. Teyler & Rudy (2007, *Hippocampus* 17(12)) update this to a hierarchical index-of-indices that becomes progressively less dependent on hippocampus as direct cortico-cortical connections strengthen (systems consolidation). **Learning rule**: the index itself forms via comparatively fast, one-shot-capable LTP in hippocampal circuitry (CA3 recurrent collaterals, CA1), contrasted with slower, higher-threshold cortical Hebbian learning -- a dual-rate scheme (this is the mechanistic root of complementary-learning-systems theory already used elsewhere in this project). **Generalization** here is architectural, not statistical: because content lives in cortex and only a compact pointer lives in hippocampus, wildly different content can be indexed by the same fixed-size mechanism without hippocampus needing to grow with cortical content -- this is precisely the "memory has its own N" / RAM-vs-disk framing already validated in `exp_wm_paging_exact_store_ram_disk_v1` (HARD-PASS-eligible per its pre-reg), reframed here as evidence that the INDEX and the CONTENT were never meant to share one representational space in the brain either.

### A2. Place cells, grid cells, and the Tolman-Eichenbaum Machine (8 citations)

O'Keefe & Dostrovsky (1971) discovered place cells; Hafting, Fyhn, Molden, Moser & Moser (2005, *Nature*) discovered medial entorhinal grid cells firing in a periodic hexagonal lattice, organized into discrete **modules** sharing a scale but varying in phase/orientation (Moser, Kropff & Moser 2008, *Annu Rev Neurosci*). The mechanism that gives grid coding its GENERALIZING (interpolation/extrapolation) power is specifically the **multi-scale periodic, modular structure**: each module encodes position modulo its own period, and combining several incommensurate periods yields a combinatorial, near-unique code over a range far larger than any single module's period -- Fiete, Burak & Brookings (2008, *J Neurosci* 28(27)) show this is mathematically a **residue-number-system / Chinese-Remainder-Theorem-style code**. A novel, never-visited location does not need to be independently memorized -- it is automatically representable as a new combination of already-learned periodic phases. The dynamics are driven by **continuous-attractor path integration** (self-motion input into recurrent network dynamics, Burak & Fiete 2009, *PLOS Comput Biol*, arXiv:0811.1826), not a gradient-based or one-shot rule; accuracy degrades with accumulated path-integration drift over distance/time and requires environmental recalibration. **The Tolman-Eichenbaum Machine** (Whittington, Muller, Mark, Chen, Barry, Burgess & Behrens 2020, *Cell* 183) generalizes this beyond space: medial entorhinal cortex carries a content-FREE structural/relational code (transition statistics of an abstract state-graph, of which spatial grid coding is one instance) while lateral entorhinal cortex carries the sensory/content code; hippocampus binds the two conjunctively. **This factorization -- structure separated from content -- is exactly why the same learned relational scaffold can bind entirely new content zero-shot** (TEM correctly answers novel relational queries, e.g. inferring an untrained family member, purely by reusing the abstract graph structure with new fillers). Flag: TEM's structural/generative component is trained by backprop-through-time (biologically contested), while the hippocampal binding step is Hebbian/one-shot -- the theory itself flags this as a plausibility gap, not a settled mechanism.

### A3. DG pattern separation + CA3 pattern completion + the tradeoff that forces a two-stage architecture (10 citations)

Marr (1971, *Phil Trans R Soc Lond B* 262) proposed DG performs **expansion recoding**: a much larger, sparse population of granule cells than entorhinal input neurons, each sampling a small random subset of inputs, so overlapping inputs become largely non-overlapping, very sparse (empirically ~2-4% active) output codes; O'Reilly & McClelland (1994, *Hippocampus* 4(6)) formalize this as random sparse conjunctive projections plus strong inhibitory competition -- **both expansion and sparsity are required together**, neither alone decorrelates as well. This is architecturally a **fixed, largely non-per-item-trained function** (a random projection plus winner-take-all/top-k), which is exactly why it generalizes to inputs never seen before -- there is no lookup table to be missing an entry from; every input gets mapped somewhere by construction (the same property, for the same structural reason, that Indyk & Motwani's 1998 locality-sensitive hashing has -- a fixed hash family applied uniformly to any query, seen or unseen).

CA3's dense recurrent-collateral system (Marr 1971; McNaughton & Morris 1987; Rolls 2013, *Front Syst Neurosci* 7:74; Treves & Rolls 1994, *Hippocampus* 4(3)) stores patterns as Hebbian-modified fixed points of an attractor network; a partial/noisy cue is driven by iterative recurrent excitation (against inhibitory normalization) to settle into the nearest complete stored attractor -- **pattern completion**. Treves & Rolls derive an idealized capacity `p_max ~ N/(a*ln(1/a))` (rising as sparsity `a` falls), the same functional form as Tsodyks & Feigel'man (1988) and consistent with classical Hopfield-family scaling (Amit, Gutfreund & Sompolinsky 1985, capacity ~0.138N, catastrophic spurious-attractor proliferation beyond that loading -- a sharp phase transition, not smooth degradation).

**The crux finding for this note**: O'Reilly & McClelland (1994) show separation and completion are **computationally antagonistic on one substrate** -- basins wide enough to correct heavy cue noise are, by the same geometry, wide enough to merge two similar-but-distinct stored items (false completion); basins narrow enough to keep similar items apart are too narrow to tolerate much cue corruption. Their resolution is explicitly **architectural, not a single-network compromise**: put a dedicated separation stage (DG: sparse, expanded, strongly inhibited) *upstream* of a dedicated completion stage (CA3: denser, Hebbian, attractor-settling), so each specializes at an opposite end of the same dial instead of one network trying to do both. (Caveat: a 2025 arXiv paper, "Paradoxical increase of capacity due to spurious overlaps in attractor networks," arXiv:2510.17593, argues spurious-overlap effects can under some conditions *increase* effective capacity via a sparsening mechanism -- flagged as a live, non-consensus research question, not settled fact; all quantitative capacity formulas above are idealized/binary-unit/one-shot-Hebbian approximations per their own authors, order-of-magnitude guidance only.)

### A4. Classical/modern Hopfield networks and hashing/learned indexes as the CS-side comparison class (7 citations)

Hopfield (1982, *PNAS* 79(8)) is the formal model underlying CA3-style completion: Hebbian outer-product weights, energy-descent dynamics settle a corrupted cue into the nearest stored attractor; Amit, Gutfreund & Sompolinsky (1985) derive the ~0.138N capacity ceiling. Krotov & Hopfield (2016, NeurIPS, arXiv:1606.01164) and Ramsauer et al. (2020, "Hopfield Networks is All You Need," arXiv:2008.02217) show a higher-order/softmax energy function gives **exponential** (not linear) capacity and is **formally identical to one step of transformer self-attention** -- retrieval error decreases exponentially in a separation quantity `Delta_i` between stored patterns, and cue corruption effectively reduces `Delta_i`, giving smooth (not cliff) degradation until separation collapses into metastable mixture states. **Crucially, this family has essentially ZERO capacity for genuinely novel content -- capacity results are only about explicitly-written patterns; anything not stored is pulled toward the nearest existing attractor at best, or a hallucinated blend at worst.** Indyk & Motwani (1998, STOC, locality-sensitive hashing) and Kraska et al. (2018, SIGMOD, "The Case for Learned Index Structures," arXiv:1712.01208) sit at the opposite pole: a fixed hash/learned-CDF function routes ANY query -- seen or unseen -- somewhere, with no training-time enumeration required (generalization "for free," structurally, not by interpolation) but with **no correction mechanism** for a corrupted query (a perturbed key can hash to a completely unrelated bucket unless the hash family is explicitly built locality-sensitive) and a documented, non-vanishing failure mode under covariate shift / out-of-distribution keys. The lit-scan's own explicit comparative verdict: **attractor/Hopfield-style completion is the apt analogy for noise-correction of an already-indexed cue; hashing/learned-index routing is the apt analogy for generalizing to genuinely novel content; neither alone gives both**, and conflating "exponential capacity" with "generalizes to unseen patterns" (a documented confusion in secondary sources) is a specific error this note explicitly avoids.

## (b) Mapping to the substrate

### B1. What the existing paging cells actually assume (verified by direct read)

Both `experiments/exp_wm_paging_exact_store_ram_disk_v1.py` and `experiments/exp_wm_paging_relational_compute_v1.py` build the page/store index as a **literal Python dict** (`exact_store = {key_id: val_id ...}` in the recall cell; `page_of = {i: i // page_size for i in range(M)}` in the relational cell) -- an exact, hand-built, pre-computed table with zero learning and zero noise tolerance at the ROUTING step. Both cells' HARD-PASS claims are entirely about what happens *after* the correct page has already been identified (bounded per-page/per-access crosstalk via the resonator/cleanup completion step, which IS the CA3-analog and IS already noise-tolerant for VALUE decode within a page). **Neither cell has ever tested: (i) what happens if the query cue itself is a corrupted/partial version of the true key (does routing still find the right page?), or (ii) what happens for content that was never inserted into the hand-built table at all (does the router even have an entry to look up?).** This is exactly the gap the Director's task framing names: "everything works GIVEN a perfect, exact page-table."

## (c) Recommended first cell -- exp_dev-actionable (pointer-only, per USER-locked no-routing-files discipline: this section IS the hand-off, no separate `exp_dev_handoff_*.md` file is filed)

**Anchor candidate:** `exp_addressing_learned_noise_robust_page_router_v1` (name is a suggestion, not binding on exp_dev).

**Why this cell, why now:** it is the cheapest cell that directly tests the ONE untested piece the whole memory/paging thread converged on -- routing, not completion -- by re-pairing two primitives this project has ALREADY separately certified (the Spoke-3/WM-note fixed expand-projection, and the resonator/codebook-cleanup completion step already used in both `exp_wm_paging_*` cells). No new primitives are required. It directly operationalizes the task's three named properties: (i) generalization to novel content, (ii) completion from a noisy/partial cue, (iii) bounded per-page crosstalk via pattern separation.

**Mechanism sketch (glass-box, DG-analog router + CA3-analog completer, ablation ladder to isolate the prior-negative risk):**
1. Build V distinct content items, each a true key phasor (FHRR, `N` dims) bound to a value phasor, exactly as in `exp_wm_paging_relational_compute_v1`'s edge construction.
2. **DG-analog router**: apply a FIXED random expansion `E: N -> N_exp` (`N_exp = f*N`, `f` in {2,4,8} to sweep) to the key, then top-k sparsify (k near the classical optimum, reuse the block-local-K sparse resonator's proven parameterization) to get a sparse address code; derive a page id from the sparse code (e.g. hash of the active-index set, or the block-local winner pattern already used in the certified sparse-resonator primitive). This function is FIXED (no per-item training) so ANY key -- including one never inserted -- gets an address deterministically, operationalizing "generalizes for free."
3. **CA3-analog completer**: within the routed page (a small bundle of <= P items, P at or below the safe crosstalk cap per the already-measured N/16-32 cliff), decode via the existing bind/unbind + codebook-argmax resonator cleanup -- identical to the completion step already proven in both `exp_wm_paging_*` cells.
4. **Ablation ladder** (isolates the anisotropy-cell failure mode before it can repeat): (A) `ROUTED_EXACT` -- today's hand-built dict page-table (oracle upper bound, reused verbatim from the existing cells); (B) `ROUTED_LEARNED_SPARSIFY_ONLY` -- top-k sparsify with NO expansion (`f=1`); (C) `ROUTED_LEARNED_DG_FULL` -- expand+sparsify (the full DG-analog); (D) `FLAT` -- no addressing at all (control, must crater, reused from existing cells).
5. **Query conditions swept independently**: (i) clean cue, in-sample content (sanity floor); (ii) NOISY cue -- true key phasor corrupted by a swept fraction of phase noise or component dropout, in-sample content; (iii) NOVEL content -- keys constructed the same way but never inserted/"trained" on, clean cue (tests generalization of the fixed router in isolation from noise); (iv) NOISY cue on NOVEL content (the hardest, most decisive combination).

**Falsifiable predictions (deflated per lit-scan calibration; HARD-PASS/HARD-FAIL mandatory):**
- **HARD-PASS:** at V well past the measured flat-bundle crosstalk cliff (N/16-32) -- `ROUTED_LEARNED_DG_FULL` end-to-end retrieval accuracy (noisy cue -> route -> complete) >= 0.85 on BOTH in-sample and NOVEL content (generalization gap <= 0.05 between the two), AND routing stability under cue noise (P(noisy cue routes to same page as its own clean key) at a corruption level that already craters `FLAT`) >= 0.90, AND routing separation (P(two distinct items collide in the same page)) stays <= 0.10 as V scales, AND `ROUTED_LEARNED_DG_FULL` beats `ROUTED_LEARNED_SPARSIFY_ONLY` by >= 0.15 (expansion is load-bearing, not just sparsification -- directly testing the O'Reilly-McClelland "both together" claim) AND trails `ROUTED_EXACT` (the oracle) by <= 0.10 (a learned/fixed router costs little relative to a hand-built perfect index).
- **HARD-FAIL:** `ROUTED_LEARNED_DG_FULL` accuracy on NOVEL content is >= 0.20 worse than on in-sample content (the router secretly needs per-item calibration -- it is not really a generalizing function) OR routing stability under noise < 0.50 at a corruption level well inside the regime the task cares about (false-routing dominates -- the router is not noise-robust) OR routing separation collapses (collision rate grows with V, i.e. the fixed projection does not scale as a separator) OR `ROUTED_LEARNED_DG_FULL` is NOT better than `ROUTED_LEARNED_SPARSIFY_ONLY` (expansion buys nothing, contradicting the A3 "both required together" literature finding) OR `ROUTED_LEARNED_DG_FULL` is WORSE than `FLAT`/no-addressing at all (repeating the anisotropy-cell failure mode -- geometry works but recall doesn't; if this happens, re-run the SAME diagnostic ladder used in the anisotropy HARD-FAIL note, i.e. check eff-rank/off-diagonal geometry independently of end-to-end accuracy, to attribute the failure to a pairing mismatch vs a fundamental limit).
- **MIDDLE:** any one but not all of the above -- route to a v2 sweeping the specific failing knob (expansion factor `f`, top-k value, page size `P`, or hash-of-active-set granularity).

**Brain-check (mandatory on HARD-FAIL, per always-on discipline):** if `ROUTED_LEARNED_DG_FULL` fails, check whether the FULL two-stage split (separate DG-analog fixed projection + separate CA3-analog completion) was actually exercised, or whether the ablation collapsed to a single-mechanism-doing-both regime -- the literature's own resolution to the separation/completion tradeoff (A3) is architectural DIVISION OF LABOR, not one clever function; a HARD-FAIL that persists even with the two stages genuinely separated and independently tuned would be a real, brain-consistent structural finding (not an implementation gap) that fixed random projections cannot buy both properties on this substrate's geometry -- report which.

## Substrate-product implications

- If the recommended cell HARD-PASSes: the product story becomes "the substrate can route a query to the right stored page/record even when the query is a corrupted or partial description of it, and even for content it has never explicitly indexed before" -- this is the mechanism that would let paging (already proven for capacity in the `exp_wm_paging_*` cells) work in a realistic setting where queries are fuzzy natural-language cues, not exact keys. This is the single missing piece between "paging works given a perfect page-table" and "paging works from how a user actually asks."
