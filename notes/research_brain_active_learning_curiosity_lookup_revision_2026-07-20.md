## (a) HEADLINE

The literature gives a clean, three-stage mechanism the substrate can adopt almost directly: (1) a knowledge gap only becomes a **drive to seek** when it is both *salient* (registered at all) and *perceived as closable at reasonable cost* — an inverted-U/"Goldilocks" gate (Loewenstein 1994; Kidd, Piantadosi & Aslin 2012/2014; Berlyne), with a demonstrated causal link from a metacognitive low-confidence signal to increased search effort (Cleary et al. 2023 déjà vu study) — this maps directly onto the substrate's **existing conformal/Chow abstain signal** (`hdlab/conformal.py`: empty or small-bounded prediction-set → trigger; huge/unbounded set → the query itself lacks gap-structure, don't bother). (2) Skilled readers monitor comprehension via breakdown-detection (Markman 1977/79; Baker & Brown 1984) and follow an implicit **internal-strategies-first, external-lookup-last** escalation (re-read → context inference → hypothesize-and-read-on → *then* dictionary/ask) — no source found formalizes this ordering as an empirical decision rule, but it is the uniform convention across fix-up-strategy taxonomies and is exactly what reciprocal teaching's "clarifying" step operationalizes as last resort (Palincsar & Brown 1984). (3) Belief revision succeeds only when a **replacement causal explanation** is supplied, not a bare negation (Johnson & Seifert 1994; Anderson, Lepper & Ross 1980; Chan et al. 2017 meta-analysis) — bare retraction leaves the continued-influence effect (CIE) largely intact, and self-generated explanatory structure is what makes discredited beliefs (belief perseverance, Ross-Lepper-Hubbard 1975) resistant to correction. The well-known "backfire effect" (correction *strengthens* the false belief) is **contested/largely refuted** as a general phenomenon (Wood & Porter 2019, n>10,000; 2023 replication failures) — correction generally works, just incompletely, so the substrate should not over-engineer around a defunct human failure mode.

All three mechanisms compose into one loop, and — the key finding for buildability — **every stage maps onto a component the substrate already has or has already designed this session**: gap-detect = conformal/Chow abstain (metacognition chain-grade, already VET-confirmed positive); internal-retrieve-first = existing cleanup/pattern-completion + codebook query (no new machinery); external lookup = allowed foundation-scaffolding (dictionary/KB/search text, ingested through the *same* reliability pipeline as any other corpus text — never an external LLM reasoning on the substrate's behalf); verify+reliability-gate = the source-independence/common-mode detector designed the same day (`research_brain_source_independence_monitoring_2026-07-20.md`) plus a literal-contradiction/coherence check; revise-with-provenance = an explicit, glass-box, provenance-tagged write — decoupled from the still-under-forensic-audit contrastive coherence-loop (STEP-2 crux), so this does NOT need to wait on that crux resolving.

## (b) Cheap decisive test

**Question:** does the active loop end with a more-correct model than passive reading?

**Design (two arms, one held-out eval set, same base reader):**
- **PASSIVE arm:** reader processes each item once; no lookup; produces its answer/belief-state from context alone.
- **ACTIVE arm:** reader processes each item; gap-detect fires when the conformal/Chow signal on a span is *empty* (no confident candidate) or *small-bounded-ambiguous* (2-3 rival candidates) — NOT when the set is large/unbounded (malformed query, no real gap-structure, per the Goldilocks gate) → internal-retrieve-first (query own codebook/cleanup for the term/fact) → if still unresolved, external lookup (a fixed, small, pre-registered dictionary/KB source — e.g. WordNet gloss or a controlled fact list) → the lookup result is ingested as raw untrusted text through the reliability + common-mode gate (source-independence check, trust weight) and a literal coherence/contradiction check against the current model → revise ONLY if the gate passes, writing an explicit provenance-tagged update (fact + source + gate-score + timestamp, no overwrite-in-place — old + new both retained, old flagged superseded, so downstream bindings that used the old belief can be identified rather than silently orphaned, which is the substrate-analog guard against continued-influence-effect residue).

**Eval set requirement (construction-determinism guard):** items must contain terms/facts genuinely under-determined by context alone (rare technical terms, or a stated fact later contradicted by a look-up-able correction) — NOT a vocabulary list solvable by context inference alone, which would let PASSIVE win trivially and make the comparison meaningless (mirrors the Goldilocks/inverted-U requirement that the gap be real, not synthetic-easy).

**Must-fail / ablation controls (mandatory, run alongside the main comparison):**
1. **Bad-source injection:** for a held-out subset, feed the lookup step a deliberately wrong/corrupted definition or fact. The reliability gate must downgrade/reject it at a materially higher rate than genuine lookups — this is the direct test that the gate is load-bearing, not decorative (per the standing "must-fail control" design-gate discipline).
2. **Ungated-lookup arm:** ACTIVE loop with the reliability/coherence gate disabled (accept every lookup unconditionally). This arm must perform *worse* than the gated ACTIVE arm on the bad-source-contaminated subset — demonstrating revision genuinely CAN make things worse without the gate (a loop that can't fail this way isn't measuring anything).
3. **Randomized-lookup control:** gap-detect fires and a lookup is performed, but the returned content is real text unrelated to the query (no information gain). This must NOT improve accuracy over PASSIVE — if it does, the apparent gain is noise-averaging/ensemble effect, not genuine gap-resolution.
4. **Gap-detect-without-lookup control:** abstain fires and is logged, but no external lookup occurs (reader falls back to its best passive guess). This isolates whether the ACTIVE arm's gain comes from the *lookup content* (it should) versus merely from knowing where it was uncertain (it should not, by itself, move accuracy).

## (c) Falsifiable predictions

**HARD-PASS** (the active loop is a genuine, above-passive-reading improvement):
- ACTIVE arm accuracy on held-out under-determined items exceeds PASSIVE arm by ≥10 percentage points (pre-registered margin).
- Gated-ACTIVE beats ungated-ACTIVE on the bad-source-contaminated subset by a materially larger margin than on the clean subset (the gate is doing real, differential work — not just adding a constant).
- Bad-source lookups are rejected/downgraded by the reliability gate at ≥2x the rate of genuine lookups.
- Randomized-lookup control shows no significant accuracy change vs PASSIVE (rules out noise-averaging as the explanation).
- Revision events carry full provenance (source id, gate score, timestamp) and are 100% traceable via the existing glass-box audit backbone — no silent overwrite.

**HARD-FAIL** (loop does not measure genuine gap-resolution, or is construction-determined):
- ACTIVE arm ties or underperforms PASSIVE on the real held-out set (extra machinery adds noise, not signal — the single most damning outcome).
- Ungated-ACTIVE performs statistically indistinguishably from gated-ACTIVE on the bad-source subset (reliability gate is decorative, not load-bearing).
- Bad-source lookups are accepted at a rate statistically indistinguishable from genuine lookups (gate has no discriminative power — same failure class as the source-independence detector's own HARD-FAIL band from the same-day companion drill).
- ACTIVE arm's entire accuracy gain is concentrated on items where the looked-up text contains the literal answer string verbatim (construction-determined: the eval set didn't actually require gap-detection judgment, just string-match after lookup — re-author the eval set, don't bank the result).
- Randomized-lookup control shows a gain comparable to real-lookup (the win is coming from "more text," not "more correct text" — directly reproduces the already-refuted "more corpus" scapegoat finding from this session's earlier arc, and would mean this drill re-derived a known dead end rather than a new mechanism).

## (e) Substrate-product implications

- **Product framing:** "the reader knows when it doesn't know, goes and checks, and only updates its model when the check is trustworthy — and can show its work" is a genuine differentiator, not a restatement of passive ingestion. It is also, per axis 3, doing something humans are *bad* at by default (bare-negation correction, belief perseverance via self-generated explanation) — so a substrate that requires a replacement causal link (not just overwrite) before revising is explicitly beating a documented human failure mode, matching the framing precedent set by the same-day source-independence drill ("catches what people systematically miss").
- **Build order implication:** the gap-detect and internal-retrieve-first stages are buildable and testable TODAY (both rest on already-VET-positive or already-existing components). External-lookup and the reliability-gate consumption are buildable today using the source-independence detector's design (same-day sibling note), pending that detector's own cheap decisive test landing. Only the "what strength to fold in" tuning benefits from the confidence-weighted-consolidation sibling drill landing first — but that is a refinement, not a blocker; a first version can use a fixed accept/reject threshold.
- **Guard the glass-box invariant explicitly in the build:** lookup sources (dictionary/KB/search results) are ingested as **raw text data** through the substrate's own reliability + coherence + abstain machinery — no external LLM sits between "lookup returned text" and "accept/reject/revise." This is a testable property, not just a stated principle: an implementation check should confirm zero LLM API calls exist on the accept/reject/revise code path, and the ungated-lookup / bad-source-injection controls above are exactly the tests that would catch a violation in practice (a loop that can't be fooled by a bad source is one where the *substrate*, not an external model, is doing the reasoning).
- **Top guard (most important):** the revision mechanism MUST be able to make the model worse when fed a bad source with the gate disabled (must-fail control #2 above). If gated and ungated arms perform identically on the bad-source subset, the "reliability gate" is decorative and the whole loop's trustworthiness claim is unfounded — this is the single check to run first, before investing in the full comparison.
