Status: SOLVED (on a held-out meaning task; the live-path wiring it depends on is a separate, named problem). Re-verify command: .venv/Scripts/python.exe verification/test_lemmatised_grounding_task.py.

The literal problem
Our only meaning asset that survives leaving common vocabulary is a table of ~36,810 sensorimotor-normed words, looked up by exact spelling — hdlab/grounded_similarity.py:165 is the entire lookup: return _table().get(word.lower()). So it holds country and misses countries, holds release and misses released, holds animal and misses animals. The meaning is in the table; the word in front of it is just wearing a different ending.

The bar (verbatim)
"A CI-separated margin over the strongest floor you actually RUN, gated on that floor's UPPER bound, on a held-out task … THE REQUIRED CONTROL, AND IT IS THE ONE THAT DECIDES: an information-free twin that lemmatises each miss to a RANDOM covered word instead of its own lemma. IT MUST LOSE."

The trap the brief flagged, and the move that escaped it
The brief had deflated itself: the defect costs 0 on every scorable instrument we own — because SimLex/SimVerb words are already dictionary forms — and read() never consults the asset. The other strategy session marked it "same shape as the refuted flat_store": a large gain from an alternative, with no measurement of what the defect costs.

That is a statement about where the defect was looked for, not whether it costs anything. The defect only bites on inflected text, so the fix is to build the instrument where it bites. Take the meaning benchmarks (human similarity ratings on lemma pairs), present each word in a real inflected corpus form (generated by an independent rule inflector, kept only if it actually occurs in the reading corpus ≥3× and misses the raw table), and score four lookup policies against the human ratings:

RAW — the live exact-string policy.
LEMMA — the fix: on a raw miss, retry hdlab/thematic_role_labeler.lemma_word (already live on the reading path).
TWIN — the mandated info-free control: on a miss, retry a random covered word.
BASE — an oracle: look the gold lemma up directly = the asset's own ceiling on this sub-population.

Controls, and the two drills on the negatives
The mandated twin loses everywhere (LEMMA−TWIN CI-separated ABOVE, 3/3). Recovering a random covered word carries no meaning; recovering the correct lemma does. So this is meaning, not "any vector beats none."
I added two floors beyond the mandated one (orthographic, frequency), so LEMMA had to beat the strongest of three — foreclosing "it's just letter- or frequency-overlap."
Drill 1 — is the one non-clearing population (SimLex-verb, n=198) a lemmatiser failure? No. The BASE oracle clears the same floor on all four populations (SimLex-verb +0.203 [+0.013, +0.390]); LEMMA sits only ~0.017 rho below the oracle everywhere, with 0 false recoveries there. The non-clear is power at the asset's own marginal ceiling, not the fix inserting wrong meaning.
Drill 2 — false-recovery hand-check. 0/536 nouns; 5/700 SimVerb-test (0.71%). Hand-checking the five: four (raped→rape, taped→tape, hoping→hope, waging→wage) are cases where my synthetic inflector generated a non-doubled form that genuinely belongs to a different lemma, and lemma_word mapped it correctly — in the live system those are right, not wrong. Only lives→life (a real life/live ambiguity resolved noun-first) is a genuine lemmatiser error, ≈0.1%.
Brain fidelity
PINNED-BY-EVIDENCE: the brain strips inflectional morphology at the lexical interface before semantic access; the semantic hub is lemma-addressed (masked morphological priming — countries primes country like an identity prime; Rastle & Davis 2008, Marslen-Wilson 1994, Taft & Forster 1975). Lemmatise-on-miss copies that operation; the known over-segmentation of the mechanism (corner→corn+er) predicts the residual false recoveries, and lemma_word's is_known_word gate is our stand-in for the brain's later semantic-coherence check. Correctly does not strip derivational morphology (nation→national changes meaning).
OURS-UNDER-TEST: reusing the lemma's grounded vector unchanged for the inflected form (justified — number/tense don't change sensorimotor grounding; landed morphological-pair cosine 0.76 vs −0.01 floor), and WordNet morphy as the decomposer (a convenience, but its ~0.1% error is measured, and the brief already settled that a heavier lemmatiser buys only +1.4 coverage points).
What is optimized, and what is NOT established
Optimized to its ceiling: the fix lands within ~0.017–0.019 rho of a perfect-lemmatiser oracle on every population. There is no meaningful headroom left in lemmatisation itself.
Not a live-path result: read() still does not consult the asset (the B5 adapter, priority 3, is unbuilt). This establishes the meaning value of the fix; it does not by itself move any read()-based number.
The synthetic-inflection scope: benchmark pairs are shown in real corpus surface forms; there is no naturally-occurring inflected-similarity benchmark. If a reviewer rejects synthetic inflection, withdraw the absolute margin first — but the direction (LEMMA ≫ TWIN, LEMMA ≈ BASE, RAW mute) is robust to it.
The frequency floor is chosen in-sample (strongest channel), which makes it if anything too strong — the conservative direction.

def grounded_vector(word: str) -> Optional[torch.Tensor]:
    t = _table()
    v = t.get(word.lower())
    if v is not None:
        return v
    from hdlab.thematic_role_labeler import lemma_word   # already live on the reading path
    return t.get(lemma_word(word.lower()))

Key realizations (the enabling moves)
Build the instrument where the defect bites. The cost was "0 on every instrument we own" only because those instruments feed the lookup dictionary forms; inflecting the benchmark to real corpus surfaces converted an unmeasurable coverage statistic into a CI-separated task result. Same shape as the refuted flat_store, opposite outcome — because here the premise was measured directly rather than assumed.
A BASE oracle turns every negative into a diagnosis. LEMMA ≈ BASE and false_rate ≈ 0 ⇒ the fix is faithful; where it doesn't clear, the oracle doesn't either ⇒ it's the asset's ceiling, not the fix.
Run more floors than the one you're told to. Adding orthographic + frequency floors caught a frequency confound that eats the noun signal at low n; recomputing the floor on the full corpus flipped it from NOT_SEPARATED to ABOVE — the "recompute the floor on the item's own population" rule in action.
Hand-checking the false recoveries reduced the error attributable to the fix — 4 of 5 were my inflector's collisions, and the lemmatiser had done the right thing.
Disk beat the brief: the finding note claimed women→woman/feet→foot are recovered by "neither method"; they are (irregular table + morphy).

TLDR
Our meaning table matches words letter-for-letter, so it's blind to "countries", "released", "walked". Teaching it to strip endings before giving up doesn't just make it speak more (already known) — it makes it speak correctly: on a standard test against human word-similarity judgements, feeding the table inflected words the way they appear in real text and then stripping the endings recovers essentially all the meaning the base word would give — clearly beating random-word substitution and string/frequency look-alikes, across three independent word sets, with a wrong strip about 1 in 700. It's within a hair of a perfect ending-stripper, so there's nothing left to tune. The one catch: the reader still has to be wired to look in this table at all — a separate job — and this result is what proves that wiring is worth doing.
