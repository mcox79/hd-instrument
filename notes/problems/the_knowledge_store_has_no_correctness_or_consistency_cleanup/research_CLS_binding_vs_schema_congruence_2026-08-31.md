## BOTTOM LINE FIRST

**(a) YES — "random-orthogonal binding store + SEPARATE relational-schema congruence geometry" is the brain-faithful architecture, and it is the CENTRAL claim of Complementary Learning Systems theory, not an incidental one.** The whole reason the brain has TWO memory systems is that ONE representation *cannot* be both a fast, interference-free arbitrary-binding store AND a slow, overlapping similarity-generalizer — that is the catastrophic-interference dilemma CLS was formulated to resolve (McClelland, McNaughton & O'Reilly 1995). Making one representation do both is not a neutral engineering choice; it is *the* dominated design the brain evolved a second system to avoid.

CLS citation chain for the architecture:
- **Binding store = sparse, pattern-separated, ~orthogonal by design** → Marr 1971; O'Reilly & McClelland 1994; Treves & Rolls 1994; McClelland/McNaughton/O'Reilly 1995; Norman & O'Reilly 2003; Yassa & Stark 2011.

So the random-orthogonal codebook is a faithful model of the *hippocampal binding store*; it is NOT a faithful model of the *cortical semantic store* — and the store must NOT try to make the binding codebook also carry congruence (that is the dominated single-representation move). ## Q1. How the brain STORES arbitrary bindings, and what CODE it uses (→ is a random-orthogonal VSA codebook faithful?)

**Circuit:** entorhinal input → **dentate gyrus (DG)** performs *pattern separation* (decorrelates/orthogonalizes inputs) → **CA3** recurrent autoassociator stores the conjunction and does *pattern completion* from partial cues → CA1. Marr 1971 ("Simple memory: a theory for archicortex," *Phil Trans R Soc*) first proposed sparse recoding + a recurrent autoassociative store; O'Reilly & McClelland 1994 (*Hippocampus*) and Treves & Rolls 1994 (*Hippocampus*) formalized DG-as-separator / CA3-as-completer and the separation↔completion trade-off.

**The code is SPARSE and ~ORTHOGONAL BY DESIGN.** DG memory representations engage only ~2–4% of granule cells (Yassa & Stark 2011, *TINS*, "Pattern separation in the hippocampus"); low granule→CA3 contact probability means even *similar* inputs elicit *non-overlapping* CA3 ensembles (empirical: Leutgeb et al. 2007 *Science*; Bakker et al. 2008 *Science*). The purpose is stated explicitly across the modelling literature: **orthogonalize inputs so that stored patterns have minimal overlap.**

**The computational reason = interference vs capacity (the load-bearing point).** In an associative store, recall error (crosstalk) grows with the *overlap* (correlation) between stored patterns; capacity is maximized when patterns are decorrelated/orthogonal. Sparse orthogonal codes minimize pairwise overlap → minimize interference → maximize the number of arbitrary bindings that can be stored and retrieved without confusion (Marr 1971; Treves & Rolls 1994; Rolls 2013 *Front Syst Neurosci*). This is the SAME argument as VSA capacity theory: near-orthogonal high-D random codes give near-zero binding crosstalk, and capacity rises with dimensionality (Plate 1995; Kanerva 2009, "Hyperdimensional computing"; Frady, Kleyko & Sommer 2018). Kanerva's Sparse Distributed Memory (1988) is the explicit bridge: it is a hippocampus-inspired model in which random high-D addresses are near-orthogonal precisely to minimize interference.

**VERDICT Q1: a random-orthogonal codebook IS the faithful model of the hippocampal BINDING store** (arbitrary, one-shot, interference-minimized). The only fidelity gap is mechanism-of-orthogonality: brain = sparsity; ours = high-D density. Same computation, swept parameter (see BOTTOM LINE nuance). It is NOT faithful — and must not be reused — as the *semantic/congruence* store (Q2).

## Q2. WHERE the brain computes semantic similarity / schema congruence — and is it SEPARATE from binding? (YES, and forcing one code to do both is dominated)

**Semantic hub = anterior temporal lobe (ATL), with OVERLAPPING, graded, DISTRIBUTED codes** — the exact opposite geometry to the hippocampal binding store. Hub-and-spoke: modality-specific "spokes" feed a transmodal ATL "hub" whose distributed activation pattern is *highly overlapping for semantically related concepts* (horse/zebra) and distinct across categories, so the hub NATIVELY expresses conceptual similarity structure and supports inductive generalization (Rogers et al. 2004 *Psych Rev*; Patterson, Nestor & Rogers 2007 *Nat Rev Neurosci*, "Where do you know what you know?"; Lambon Ralph, Jefferies, Patterson & Rogers 2017 *Nat Rev Neurosci*, "The neural and computational bases of semantic cognition").

**The separation is the CENTRAL CLS claim, not a detail.** McClelland, McNaughton & O'Reilly 1995 (*Psych Rev*) argue that a *single* system cannot both (i) rapidly store arbitrary new bindings without overwriting old ones AND (ii) slowly extract overlapping statistical/semantic structure — the two require OPPOSITE code geometries (sparse-orthogonal vs dense-overlapping) and OPPOSITE learning rates. Trying to do both in one representation produces catastrophic interference; the brain's solution is *two* systems with complementary properties. Norman & O'Reilly 2003 (*Psych Rev*) instantiate this: the hippocampal model uses sparse conjunctive codes, the cortical model overlapping codes, and each FAILS at the other's job.

**VERDICT Q2: CONFIRMED.** Binding (hippocampal, sparse/orthogonal) and congruence (cortical ATL, overlapping/graded) are SEPARATE representations by design. A random-orthogonal codebook has, by construction, ~zero cosine between related concepts — so "congruence-by-cosine on the raw binding store" is *impossible*, exactly as `SOLVED.md` found. Building the congruence geometry SEPARATELY (as the organ does) is not a workaround; it is the brain's architecture. The single-representation alternative is computationally DOMINATED (the catastrophic-interference result).

## Q3. How the cortical schema is BUILT — raw co-occurrence, or CONSOLIDATED RELATIONAL structure? (→ is your relational geometry the faithful cortical mechanism?)

**The cortical schema is a CONSOLIDATED RELATIONAL/STRUCTURAL map, not raw co-occurrence.** Two convergent literatures:

1. **Systems consolidation extracts gist/regularity across episodes** (not surface statistics of any one): CLS interleaved cortical learning (McClelland/McNaughton/O'Reilly 1995; McClelland 2013 *JEP:Gen*, schema-consistent fast cortical learning); Tse et al. 2007 *Science* ("Schemas and memory consolidation") + Tse et al. 2011 *Science* — a *schema* is a **relational framework of prior associations**, and consolidation into mPFC is *accelerated* when a fact fits that relational framework; trace-transformation to a schematic residue (Winocur & Moscovitch 2011).

2. **The consolidated schema has explicit GRAPH/RELATIONAL geometry** — this is the decisive literature for your question:
   - **Garvert, Dolan & Behrens 2017 (*eLife*), "A map of abstract relational knowledge in the human hippocampal–entorhinal cortex":** subjects saw objects sampled from random walks on a GRAPH; the hippocampal-entorhinal system reconstructed a map whose geometry matched the *graph's* relational structure (associative strength / who-shares-edges), NOT raw pairwise co-occurrence. This is essentially your member-Jaccard "who-shares-which-relation" geometry, measured in the brain.
   - **Schapiro et al. 2013 (*Nat Neurosci*), "Neural representations of events arise from temporal community structure":** cortical/hippocampal event representations coalesce around GRAPH COMMUNITIES (relational topology), not raw transition frequency — items in the same community become similar even when raw co-occurrence is matched. Structure beats surface.
   - **Whittington et al. 2020 (*Cell*), Tolman-Eichenbaum Machine:** the system FACTORIZES relational STRUCTURE (medial entorhinal) from CONTENT (lateral entorhinal), and it is the STRUCTURE factor that generalizes across environments. Raw co-occurrence lives on the content side; congruence/inference rides the structure factor.
   - **NEW, directly on point — "An abstract relational map emerges in the human medial prefrontal cortex WITH consolidation" (*Curr Biol* 2026):** the RELATIONAL map is specifically a *consolidated cortical* product in mPFC — i.e. the schema you want to judge congruence against is the *consolidated relational graph*, exactly.
   - Updated CLS: Kumaran, Hassabis & McClelland 2016 (*TICS*) — the cortical system builds *structured* representations that support generalization; replay extracts that structure.

**VERDICT Q3: YES — the neuroscience predicts the cortical schema is RELATIONAL/STRUCTURED, built by CONSOLIDATION, not raw distributional co-occurrence.** Your relational graph geometry (who-shares-which-relation, member-overlap) is the more brain-faithful cortical mechanism; the raw distributional concept space is the brain's *un-consolidated content spoke* (LEC "what"). The AUC 0.75 (relational) vs 0.566 (distributional) gap is the empirical signature of the structure factor separating congruence where surface statistics barely can — precisely CLS/TEM's prediction. This also explains `SOLVED.md`'s adversary result mechanistically: the content spoke is *fooled* by matching context (0.000) because surface statistics are exactly what a plausible-looking wrong extraction reproduces; the structure factor is not (0.818).

## Q4. Systems-level congruence FLOW — is congruence a PROJECTION into the cortical schema, read SEPARATELY from the hippocampal trace? (YES)

**Flow (hippocampal retrieval → cortical schema projection → mPFC/ACC congruence read):**
1. **Hippocampal retrieval:** partial cue → CA3 pattern completion → CA1 (Marr; O'Reilly & McClelland 1994). The trace stores the *arbitrary binding*; it does NOT itself encode congruence.
2. **Projection into the cortical schema:** the retrieved item is projected into the ATL semantic hub + the entorhinal/mPFC relational map — the overlapping/structural geometry where similarity and schema-fit are *computable*.
3. **mPFC/vmPFC reads congruence (match/resonance):** van Kesteren et al. 2012 (*TINS*, SLIMM) — mPFC detects congruence of the item with the *activated cortical schema* ("resonance"); congruent → mPFC gates (inhibits) further hippocampal encoding, incongruent → prediction error → hippocampus builds a fresh trace. Gilboa & Marlatte 2017 (*TICS*) — mPFC as the schema match/mismatch hub. Preston & Eichenbaum 2013 (*Curr Biol*) — hippocampal-PFC interplay implements schema-based congruence.
4. **ACC signals conflict / prediction error** if the projection mismatches (Botvinick et al. 2001; Alexander & Brown 2011 — covered in the sibling file).
   Comparator detail: CA1 itself computes a local match/mismatch between the CA3 prediction and entorhinal input (Kumaran & Maguire 2007), but the *schema-congruence* read is the cortical/mPFC projection, distinct from the stored trace.

**VERDICT Q4: CONFIRMED and it validates the two-store architecture.** Congruence is NOT read off the binding trace; it is computed by PROJECTING the retrieved fact into a SEPARATE cortical schema geometry and reading match/mismatch in mPFC (with ACC conflict). This is precisely what the organ does: score a stored fact against a separate relational geometry it does not itself live in. The architecture — orthogonal binding store, separate relational congruence geometry, project-and-read — is the systems-level brain flow.

## TLDR (plain English)
The brain keeps memory in TWO different systems on purpose, and it is not a coincidence — it is the single most important thing brain science learned about memory. One system (the hippocampus) writes down brand-new facts fast, using a "code" where every fact is deliberately made as unlike every other fact as possible, so new facts never smear over old ones. The other system (the outer cortex) slowly builds a web of *how things relate* — a map of which things share which relationships — and that map is what lets the brain feel whether a new fact "fits." A person can't feel whether a fact fits by staring at the fact alone; they project it into that relationship-map and check for friction. Our knowledge store is built exactly like the first system (facts made maximally unlike each other), which is the *right* design for a fact store — but it means the store has no built-in sense of what "fits," so we correctly built that sense as a SEPARATE thing. And the version of "fitting" that worked best in our tests — comparing facts by which relationships they share, rather than by raw word-overlap — is precisely the version the brain uses. Raw word co-occurrence is the brain's raw input; the relationship-map is what it distills that input INTO, and it's the map that does the judging. So both of the owner's architectural choices are the brain's own choices. Because we aren't limited by a biological body, we can legitimately do the same computations *better*: use far bigger codes so facts never interfere at all, build the whole relationship-map at once and exactly (instead of slowly, a little each night), and judge every fact against the complete map — with ONE catch the brain enforces automatically and we must add by hand: never let a fact help build the very map you're using to judge that fact, or a planted error will make itself look correct (we measured this trap directly).
