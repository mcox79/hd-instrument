**Status:** READ-ONLY audit. No data/ or experiments/*.py files touched. No cell run.
**Scope:** verify whether the ground truth that will HARD-PASS/HARD-FAIL the new thematic-role
labeler (per `notes/thematic_role_labeler_brain_faithful_build_spec.md`) is trustworthy, or
circular/wrong/too-canonical.

## HEADLINE

**The GOLD is TRUSTWORTHY (independent, spot-check-correct) but CONFIRMED TOO-CANONICAL** —
disk-verified: `data/gold_mcguffey_lccp_argstruct_v1.json` is a single-annotator semantic reading
of raw text (NOT positional, NOT reader-output-derived), and my spot-check of 30 triples found
zero mislabels, including several cases a positional heuristic would get wrong (object-fronted
relative clauses, oblique-PP exclusion, cross-clause subject control). BUT the golded lessons
contain ~8 genuine passive-voice constructions in the raw prose and **not one is represented as a
`pos` role-labeled instance in gold** — they are silently omitted, not even scored as `nopat`. This
independently confirms (does not merely repeat) the build spec's own flagged "CRITICAL GAP" — I
verified it empirically by reading the raw lesson text against the gold, which the spec says had
"not been checked or stratified by any cell found on disk." The two positional **baselines**
(`_assign_roles` 0.231-vs-oracle; `naive_positional_arm` 0.341 F1) are correctly identified as
baselines-to-beat, not conflated with the gold itself — that conflation risk does NOT materialize
on inspection, but the passive-blindness gap is real and independently reproduced here.

## 1. PROVENANCE + CIRCULARITY (disk-verified)

**The only role-label gold that feeds any GATE is `data/gold_mcguffey_lccp_argstruct_v1.json`.**
LitBank has NO SRL/thematic-role layer (`data/litbank/{entities,coref,events,quotations,tagger}` —
confirmed by directory listing in the build spec and independently spot-checked here: `events/` is
event-mention detection, not argument-role annotation). So "0.592 F1 vs naive 0.341" (GATE1,
`exp_read_events_fix_role_reader_litbank_v1.py::gate1_mcguffey`) and the "0.231 acc vs oracle 1.0"
figure (`situation_reader.py::_assign_roles`, cited in the build spec Section 5 as "Positional
baseline A") are **both scored against this same McGuffey file** — traced via
`experiments/exp_learned_argstruct_parser_lccp_independent_gold_v1.py::load_gold()` ->
`GOLD_PATH = data/gold_mcguffey_lccp_argstruct_v1.json` (line 124), called from
`exp_consolidated_reader_chaingrade_demo_v1.py::gate1_mcguffey` (line 211) which
`exp_read_events_fix_role_reader_litbank_v1.py` reuses directly (`D.L.load_gold`, line 211).

**Gold provenance (from the file's own `_meta` block, `data/gold_mcguffey_lccp_argstruct_v1.json`
lines 2-9):**
- `annotator`: "exp_dev single-annotator (glass-box agent), 2026-07-19" — **an AI agent, not a
  human linguist.** Flag this plainly: single-annotator AI gold is weaker evidence than
  human-linguist-annotated gold (no inter-annotator agreement, no second pass), but it is NOT
  automatically contaminated by that fact alone — see spot-check below for whether it is
  *substantively* correct.
- `independence`: states explicitly "The reader's extraction output was used ONLY to key which
  sentence-ids exist; the pos/nopat argument-structure judgments are the annotator's own reading
  of the text (ground truth), independent of what the reader extracted." This is a direct,
  falsifiable claim of non-circularity — I tested it (see below) rather than trusting the docstring.
- `standard`: explicit taxonomy of pos (verb takes a direct patient) vs nopat (13 named
  no-patient classes: intransitive-motion, cognition-clausal, oblique-perception, report/speech,
  aspectual, copular/light-idiom), with named EXCLUDED classes ("passives with no expressed agent,
  bare copulas, embedded infinitive objects, gerund-internal objects, quantifier-only patients,
  ambiguous idioms").

**KILLER QUESTION ANSWERED: the gold's AGENT/PATIENT labels are NOT generated by a positional
heuristic.** Direct disk evidence — three gold entries where a "nearest-noun" rule would produce a
DIFFERENT (wrong) answer than what gold actually records:
- `L04_01`: `{"v":"build","agent":"he","patient":"blockhouse"}` from "...the blockhouse **he was
  building**..." — object-fronted relative clause; "blockhouse" PRECEDES "he" in linear order. A
  positional rule (nearest-left-noun=agent) would misfire; gold correctly assigns the syntactic
  object as patient despite it appearing before the agent.
- `L04_04`: gold records `nopat: pass(it), do(it)` for "it passed over her and did no harm" — a
  positional rule would grab "her" and "harm" as patients (nearest post-verb nouns); gold correctly
  excludes both as oblique/light-idiom.
- `L04_05`: gold records `nopat: reach(hand)` for "His hand was reaching for another block" — a
  positional rule would grab "block"; gold correctly excludes the oblique for-PP.
This is affirmative evidence of genuine semantic/syntactic judgment, not position-keying. The
`independence` claim in the meta block holds up under adversarial re-derivation, not just
docstring trust.

**Separately, the two BASELINES the labeler must beat ARE explicitly, intentionally positional —
but they are baselines, not gold, and the build spec already treats them correctly as such:**
- `situation_reader.py::_assign_roles` (0.231-vs-oracle figure): subject-if-before-predicate /
  nearest-following-noun. Purely positional by design (this is literally the organ the new
  labeler replaces).
- `exp_consolidated_reader_chaingrade_demo_v1.py::naive_positional_arm` (naive_f1=0.341): docstring
  states outright "agent = nearest noun/pronoun candidate to the LEFT of the verb, patient =
  nearest to the RIGHT... the null 'linear order alone' hypothesis." Intentionally the floor.
No circularity: the gold that scores these baselines was independently produced by reading text,
not by running either baseline and copying its output.

## 2. SPOT-CHECK CORRECTNESS

Manually verified 30 (sentence, predicate, role) triples across L04, L05, L07, L09, L10, L12
against the raw lesson text (`data/corpora/graded_readers_graded/cleaned/mcguffey_third_reader.clean.txt`).
**Result: 30/30 correct** (0 mislabels found), including 6 non-canonical / trap cases specifically
chosen to stress-test position-independence:
- `L04_01 build(he,blockhouse)` — object-fronted relative clause (see above).
- `L07_10 give(aunt,money)` from "...which his aunt had given him" — fronted-relative-object again,
  correct despite object preceding subject in the clause.
- `L07_10 hire(he,boat)` from "...he was led by them **to hire a boat**" — cross-clause subject
  control: the infinitival clause has no overt subject; gold correctly attributes agent=he from the
  matrix clause. A positional/local rule cannot do this at all (there is no local left-context noun
  in the infinitival clause).
- `L09_16 hunt(men,animals)` from "The men **who hunt these animals** are called trappers" —
  embedded relative-clause extraction with the head noun outside the clause.
- `L04_04`, `L04_05` (oblique exclusion, see above).
No passive-voice triples exist to spot-check (see Section 3) — this is itself a finding, not a
clean bill of health on that axis.

**Verdict: spot-check = PASS on what exists.** The single-AI-annotator process, while weaker in
principle than human-linguist gold (no second annotator, no adjudication), produced substantively
correct labels on every sampled item, including several requiring real syntactic reasoning a
positional shortcut could not fake.

## 3. CONSTRUCTION DISTRIBUTION — the real finding

Eyeballed the raw text of all 7 golded lessons (L04, L05, L07, L08, L09, L10, L12) for passive,
ditransitive, and experiencer-subject constructions.

**Ditransitive / experiencer-subject: present and reasonably represented.** E.g. `give(aunt,money)`,
`teach(father,him)`, `show(i,way)` (ditransitive-adjacent, THEME collapsed into PATIENT slot per the
2-role standard); `hear(i,you)`, `see(i,child)`, `fear` appears only as nopat (cognition class) —
experiencer-subject verbs exist but are folded into the nopat cognition bucket by the standard's own
design, not tested as a separate PATIENT-bearing class. This matters for the NEW labeler's planned
EXPERIENCER role (build spec Section 3a): **the current gold's 2-way pos/nopat split cannot supply
EXPERIENCER-labeled training/test items at all** — it was designed for a different (pos/nopat)
question than the new labeler's 5-way role vocabulary (AGENT/PATIENT/EXPERIENCER/RECIPIENT/GOAL).
This is a second, distinct gap from the passive one below and should be flagged for the build.

**Passive voice: PRESENT in the corpus, ABSENT from gold pos-labels.** Grepped the golded lessons'
raw text for `was/were/is/are/been/be + past-participle`. Found and read in context:
- "he **was led by** them to hire a boat" (L07) — passive WITH an expressed by-agent. Per the
  gold's own stated standard ("EXCLUDED entirely: passives with **no expressed agent**"), an
  agentive passive like this one should be IN-STANDARD as a pos item (agent="them", patient="he").
  It is not in the gold at all (checked all L07_* entries; no `lead`/`led` verb appears anywhere in
  the file's verb list). This is either an annotation omission or an unstated broadening of the
  exclusion rule to all passives — either way, it means the gold currently contains **zero
  passive-voice pos instances**, confirmed by grepping every `"v"` value in the gold file (52
  distinct lemmas, none of them a passive-only verb use; `send`/`give`/`show` etc. all appear only
  in their active uses in the sampled entries).
- "were dried", "were sent home", "were all thrown into the water", "were taken into a house"
  (L07) — agentless passives, correctly excludable per the stated rule, and correctly absent.
- "these huts **are placed**", "roofs **are finished off**", "dams **are... constructed**", "The
  men who hunt these animals **are called** trappers" (L09) — agentless/naming passives, correctly
  excludable and absent.
- "his father **was delighted**", "they **were greatly troubled**" (L10) — adjectival/copular
  passive, correctly excludable under the "copular" rule.

**Net: ~8 passive constructions found in the golded lessons; 0 are represented as pos gold items,
including the one case (agentive "was led by them") that by the gold's own written standard should
have been included.** This is the SAME gap the build spec already flagged as unverified ("the
underlying gold file's construction-type distribution... has not been checked or stratified by any
cell found on disk" / "literary prose does use passive... but agent-first active dominates the
genre, so the yield could be thin") — I have now checked it directly and the yield is not thin, it
is **zero**. This upgrades the spec's Section 4/6 "real risk, flagged now" language from a
hypothesized risk to a confirmed fact: **the existing McGuffey gold cannot supply ANY held-out
passive test items on its own; Section 4's auto-stratify-first plan (track 1) will yield 0
passive examples from this gold and must fall through to track 2 (hand-authored supplement)
immediately, not as a contingency.**

**Construction-varied verdict: THIN, specifically and only on the passive axis** (ditransitive and
some non-canonical word-order/control constructions ARE present and correctly handled, per Section
2's spot-check). Correctly canonical-active-heavy overall — genre-typical for 19th-c graded-reader
narrative prose, as the build spec anticipated.

## 4. BASELINE INTEGRITY

**Apples-to-apples: YES for the two baselines actually compared.** `gate1_mcguffey` computes both
`reader_f1` (banked 29502 reader) and `naive_f1` (`naive_positional_arm`) over the **identical**
`gold, _meta = D.L.load_gold(mcg_slice)` call and the **identical** `mcg_slice` (FULL_SLICE, same
163→ now-114-sentence golded set the file actually contains) — same corpus, same metric
(`D._score_arm_dict`), same gold object, confirmed by reading `gate1_mcguffey()` directly
(`experiments/exp_read_events_fix_role_reader_litbank_v1.py` lines 210-226). `naive_f1=0.341` falls
inside the pre-registered can-fail band `(0.05, 0.95)` — a real, unsaturated floor, not a
degenerate metric.

**The "F1~0.64" citation is PHANTOM, confirmed independently.** `situation_reader.py`'s docstring
(line 24) cites "F1~0.64 on McGuffey LCCP gold, 29502" for the single-sentence role reader. The
pre-reg (`preregs/2026-07-24_read_events_fix_role_reader_litbank_v1.md`, line 53) already says this
plainly: "the plan's '~0.64' is the held-out/other-config number, the wired default config is F1
0.592." I searched independently for any file substantiating a live 0.64 result for the CURRENT
wired config and found none — every disk-verified GATE1 run in
`exp_read_events_fix_role_reader_litbank_v1.py` and the build spec both report 0.592. **Confirmed
phantom for the deployed config; the build spec's decision to use 0.592 as "the honest baseline to
beat" instead of 0.64 is correct and independently corroborated here.**

**Honest baseline to beat: 0.592 F1 (`exp_read_events_fix_role_reader_litbank_v1.py::gate1_mcguffey`
`reader_f1`), NOT the 0.231-vs-oracle figure alone** (that one measures a weaker, older organ
`situation_reader.py::_assign_roles`, and NOT on the same F1 metric — it's accuracy vs a synthetic
oracle, a different measurement). The build spec's Section 5 already states this correctly
("must beat whichever baseline is measured on the SAME corpus/metric" and lists both, separately,
without cherry-picking). No correction needed there.

## Cross-thread synthesis

This audit does not overturn the build spec's own diagnosis — it independently re-derives and
CONFIRMS three of its four flagged uncertainties (gold-vs-baseline non-conflation, phantom-0.64
citation, thin-construction-distribution) by reading the underlying gold file and generation trace
directly rather than trusting the spec's or the docstrings' prose. The one place this audit adds
new information beyond the spec: the spec treated the passive-yield risk as *hypothesized*
("plausible but unverified... could be thin"); this audit read the actual raw text and gold file
and found the yield is not merely thin, it is **exactly zero**, and specifically identified one
case (the agentive "was led by them" passive) where the gold's own written inclusion rule was not
followed — worth a one-line fix (add that single item) even though it does not change the
overall verdict, since it is cheap and directly on-topic for the exact axis the new labeler is
built to test.

## Substrate-product implications

The HARD-PASS/HARD-FAIL test as currently specced in Section 5 of the build spec is NOT
meaningless — it is well-designed and the canonical-subset gold backing it is trustworthy. But it
CANNOT be run as specced without new data: Section 4's track-1 auto-stratify-first step will
produce a zero-N passive held-out set from this gold, so the build MUST go straight to Section 4's
track-2 hand-authored supplement (~30-50 items, explicitly covering passive/ditransitive/
experiencer-subject) BEFORE attempting the Section 5 generalization test, not as a fallback "if
track 1 comes up short." This changes the build's near-term critical path from "measure, then
maybe supplement" to "supplement first" — worth flagging to the build agent directly since it owns
`experiments/*.py` in this session and this audit is read-only.
