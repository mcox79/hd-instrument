# Research: is the (source, relation) -> sibling multi-hop test even FAIR? Brain-first drill on goal-directed traversal

**Filed by:** research sub-agent. **Trigger:** reader win-cell v3 (decoupled codes, `exp_grounding_multihop_decisive_win_v1` lineage) FAILED — decoupling codes INCREASED same-relation aliasing rather than reducing it. Emerging hypothesis (HOLD, being VET'd separately by skunkworks): the query `(source_node, relation)` alone UNDERDETERMINES the target when node A has multiple true R-neighbors `{B1, B2, B3}` — no mechanism, substrate or biological, can pick a unique "correct" sibling from that input alone. This drill does NOT try to fix the cell. It questions whether the TEST ITSELF is fair, using the brain as the reference standard, before any more engineering effort is spent chasing a possibly-manufactured wall.

**Method:** 3 parallel Sonnet lit-scan sub-agents, one per angle: (1) brain mechanism for branch-point disambiguation during relational/spatial traversal (PFC goal-maintenance, hippocampal goal-modulated replay/VTE, theta phase coding); (2) formal task-framing / underdetermination (transitive-inference probe structure, database functional-dependency theory, Hadamard well-posedness, KG query-embedding set-semantics); (3) fair-test redesign literature (goal-conditioned RL/UVFA, A*/informed search, query-embedding path-context carrying, working-memory/episodic-buffer models). Generic neuroscience/CS/logic query terms only, no substrate-specific mechanism names or numbers off-platform, per query-privacy discipline.

## HEADLINE

**The test as currently posed is UNFAIR-BY-CONSTRUCTION, and the brain never asks the question we are asking.** Four independent literatures — biological neuroscience of choice-point navigation, classical cognitive-psychology transitive-inference task design, formal database/logic well-posedness theory, and modern knowledge-graph query-embedding formalisms — converge on the identical structural diagnosis: **a bare `(current_state, relation-type) -> unique successor` query is only well-posed when the relation is FUNCTIONAL at that node (exactly one true successor). When the relation is genuinely one-to-many, that query has no single correct answer by construction** — not because the answering system (brain or substrate) is deficient, but because the question omits the one piece of information (a goal/target, or an accumulated path-context) that every domain surveyed requires to make branch-point selection determinate. The brain does not resolve this by being cleverer at guessing from `(A, R)` alone; it resolves it by **never actually asking that question** — biological traversal is goal-conditioned from the start (PFC holds an active target; hippocampal replay sweeps forward candidates weighted toward that target before commitment), and formal multi-hop query systems (transitive-inference probes, KG query embeddings) either supply a second determining constraint or explicitly accept the answer as a SET, never as a forced singleton.

**VERDICT: YES, our (source, relation) -> single-sibling retrieval test is intrinsically underdetermined and, as posed, unfair.** It is not measuring a substrate limitation; it is measuring whether the substrate can guess a coin-flip (or 3-way, 5-way, etc.) choice that no information-theoretic amount of "better encoding" can resolve, because the missing bit isn't in the query. Decoupling the codes (win-cell v3) made this WORSE, not better, for a mechanistically clean reason (see Cross-thread synthesis): decoupling removes the very semantic correlation that was accidentally providing a soft disambiguating signal (partial goal-leakage via co-occurrence structure), leaving the resonator/cleanup step with strictly less information to break the tie than before — so aliasing among true siblings increased exactly as the query got MORE information-starved, which is the predicted signature of an underdetermination problem, not a decoding-quality problem.

## The brain mechanism (existence proof this drill leads with, per USER-locked biology-first discipline)

Two cooperating systems resolve branch-point ambiguity in biological relational/spatial traversal, and NEITHER is a memoryless `(current_node, relation) -> lookup`:

1. **Prefrontal goal-maintenance (top-down bias).** Miller & Cohen's integrative PFC framework (Annu. Rev. Neurosci. 2001) frames cognitive control as PFC actively holding a goal/rule representation that biases which of several structurally-available pathways downstream circuitry selects — the same local branch point yields different correct choices depending on which goal is currently held active. Classical dlPFC delay-period activity (Fuster & Alexander 1971; Goldman-Rakic 1995) shows persistent, distractor-resistant, target-specific firing across the interval before a choice must be emitted — a working-memory trace of WHERE THE TRAVERSAL IS HEADED, not merely where it currently is.

2. **Hippocampal goal-modulated forward replay / vicarious trial-and-error (VTE).** At a physical choice point (T-maze/Y-maze), hippocampal ensembles sweep forward down one candidate arm then the other BEFORE commitment (Johnson & Redish 2007, J. Neurosci. 27:12176, direct-consistency across independent sources). Critically, this sweeping is not neutral local expansion: Pfeiffer & Foster (2013, Nature 497:74, DOI 10.1038/nature12112) show hippocampal sequences before goal-directed runs are strongly biased toward the CURRENTLY-REMEMBERED GOAL, even for novel start-goal combinations never physically experienced together — direct evidence that the sweep content is goal-conditioned, not a blind enumeration of local branches. Redish's 2016 review (Nat. Rev. Neurosci. 17:147, direct-read, PMC5029271) supplies the circuit-level account: mPFC "polls" hippocampus to initiate the search; hippocampus generates/sweeps candidate continuations; ventral striatum values during deliberation; OFC values after commitment. A 2023 human fMRI study (Nat. Commun. 14:1946, DOI 10.1038/s41467-023-35967-6, direct-read, PMC10206082) states the finding in almost exactly our own framing: **"the correct decision to be made at [a shared branch point] depends on one's current goal and context"** — the identical physical node is represented differently in hippocampus depending on which goal is active, and hippocampal activity at the branch point carries prospective information about the goal-specific continuation, not a symmetric enumeration of all locally-valid neighbors.

3. **Theta phase coding supplies the substrate for carrying path-context, not just point-position.** Phase precession (O'Keefe & Recce 1993 and successors) encodes fine-grained sequence/trajectory information within each theta cycle — where the animal is WITHIN a path (where-from/where-to), not an isolated (place, direction) pair. This is the physical mechanism that VTE sweeps and goal-directed replay ride on top of: the basic spatial/relational code already carries trajectory context, and goal/PFC bias determines which candidate continuation the sweep favors.

**Important honest nuance (not hedged away):** Redish's review explicitly notes goal-modulation during VTE is graded/probabilistic, not an absolute override — sweep content correlates with eventual choice but "is not uniformly targeted toward the chosen goal." The brain does not achieve perfect, zero-error disambiguation even WITH a goal signal; it reduces but does not eliminate residual exploratory uncertainty at genuinely ambiguous branch points. This sets a realistic (not utopian) calibration expectation for any redesigned test: even a fair, goal-carrying query should not be held to a 100%-determinacy bar — brain-aligned "good" performance still has graded residual uncertainty, calibrated against the branching factor.

## Cheap decisive test

Zero new dispatch, pure re-analysis of the ALREADY-LANDED v3 decoupled-codes data plus one small follow-up smoke: for the same subgraph/harness, compare THREE query framings at matched N and matched code:
1. **NAIVE (current, unfair)** — `(source, relation) -> predict the one sibling` scored against a single ground-truth sibling chosen arbitrarily among the true set.
2. **SET-ACCEPTING (Query2Box/MetaQA-style, no new information added)** — same query, but score as PASS if the top-ranked prediction is a MEMBER of the true sibling set (not a specific pre-chosen one).
3. **GOAL-CARRYING (brain/A*/UVFA-style, new information added)** — `(source, relation, target_signature)` where `target_signature` is a second piece of accumulated path-context already available in a real multi-hop chain (e.g., which sibling was consistent with hop 2's downstream relation, or an explicit target node from the actual traversal task) -> predict that ONE specific sibling.

If (2) and (3) both show dramatically higher apparent "success" than (1) on the IDENTICAL underlying codes/decoder (no re-engineering), that is the decisive signature that (1)'s failure was a query-design artifact, not a substrate capability gap. If (2)/(3) fail just as badly as (1), the underdetermination-of-the-query hypothesis is refuted and the aliasing is a genuine encoding/decoding defect, not a test-fairness artifact.

## Falsifiable predictions (HARD-PASS + HARD-FAIL)

**Prediction 1 (naive test is measuring underdetermination, not capability):** On the same v3 decoupled codes, SET-ACCEPTING scoring (framing 2 above) shows materially higher hit-rate than NAIVE single-target scoring (framing 1), at a magnitude consistent with the branching factor (e.g., if mean out-degree for a relation-type is ~3, SET-ACCEPTING hit-rate should approach ~3x the NAIVE rate, since NAIVE is effectively being scored against a 1-in-k coin flip among true answers).
- HARD-PASS: SET-ACCEPTING hit-rate >= 0.6 (a real, usable signal) AND >= 2x the NAIVE hit-rate on the same codes/decoder, confirming most of the "failure" in framing 1 was mis-scored correct-but-wrong-sibling answers.
- HARD-FAIL: SET-ACCEPTING hit-rate is NOT materially better than NAIVE (< 1.3x) — would mean the decoder isn't even reliably landing on ANY true sibling, i.e. the problem is a genuine encoding/crosstalk defect independent of query framing, and the underdetermination hypothesis does not explain the v3 regression.

**Prediction 2 (goal-carrying query restores determinacy and reverses the v3 regression):** GOAL-CARRYING scoring (framing 3), using a second piece of path-context that a real multi-hop chain already produces (e.g., the downstream hop-2 relation as the disambiguating signal, analogous to A*'s goal node or UVFA's goal-conditioning), lands materially higher AND reverses the specific v3 finding (decoupling no longer increases aliasing, because the goal signal — not incidental code correlation — now supplies the disambiguating bit).
- HARD-PASS: GOAL-CARRYING top-1 accuracy on DECOUPLED codes >= 0.55 AND >= the equivalent GOAL-CARRYING accuracy on the original (non-decoupled) codes minus 0.05 (i.e., decoupling no longer hurts once the query carries its own disambiguating signal — confirming decoupling's apparent harm in v3 was specifically because it removed an ACCIDENTAL disambiguator that a properly-designed query should supply on purpose instead).
- HARD-FAIL: GOAL-CARRYING accuracy on decoupled codes is NOT materially better than NAIVE decoupled accuracy, and/or decoupling STILL increases aliasing even with an explicit goal signal present — would mean decoupling harms retrieval through some OTHER mechanism unrelated to disambiguation-information (e.g., destroys retrieval-relevant correlation the resonator step itself needs, independent of query framing), which would refute this drill's core diagnosis and point back to [[reference-correlation-hurts-associative-store-capacity-decouple-from-retrieval]] as the dominant explanation instead.

**Prediction 3 (brain-aligned calibration: even a fair test has graded, non-zero residual error scaling with branching factor):** A brain-aligned redesigned test should NOT be scored against a 100%-determinacy bar. Per the Redish VTE nuance (goal-modulation is graded, not absolute), a fair test's HARD-PASS bar should itself scale down gracefully as branching factor increases, not demand perfect accuracy regardless of how many true siblings exist.
- HARD-PASS: the redesigned test's calibration curve (accuracy vs. out-degree/branching-factor) shows a smooth, expected monotonic decline with branching factor (more true siblings -> harder, as in the brain), not a cliff.
- HARD-FAIL: accuracy is flat/independent of branching factor even under the fair GOAL-CARRYING framing — would suggest the redesigned test still isn't capturing the real disambiguation difficulty (an over-correction, e.g. leaking so much of the answer into "goal_signature" that the task becomes trivial rather than fair).

P_deflated (the full "our test is unfair, and a goal-carrying redesign fixes it" verdict, as an operational finding to be VET'd): **0.42** (base intuition ~0.62 — this is an unusually clean, four-domain-convergent theoretical case with strong direct-read primary sources on 2 of the 3 angles, not a speculative single-paper leap; deflated 0.20 per lit-scan calibration penalty because no source in any scan directly tests THIS substrate's specific decoupled-code regime — the convergence is structural/theoretical, not an empirical precedent on our exact codes). Individual predictions (1-3) are each higher, ~0.50-0.55, since Prediction 1 is close to a re-scoring exercise on already-landed data (cheap, low-novelty-risk) and Predictions 2-3 are the more novel, appropriately-capped parts near the 0.50 novel-synthesis ceiling.

## Intuitive summary

**What we did:** instead of trying to fix the multi-hop memory test that just failed, we asked a more basic question first: is the test itself even fair? We looked at how real brains handle the exact same situation — following a fact or relationship from something that has several possible "next steps" (a person has several friends, a place has several neighbors) — and asked whether the brain ever tries to guess the right one from just "starting point + type of relationship" alone, with nothing else to go on.

**What we found:** no, it never does. Three completely separate bodies of evidence say the same thing. In real brains, before you commit to a choice at a fork, your prefrontal cortex is actively holding onto WHERE YOU'RE TRYING TO GO, and your hippocampus previews several possible next steps ahead of time, weighted toward that goal — not blindly, and not from the fork alone. In classic laboratory memory-reasoning tests (the "A is bigger than B, B is bigger than C..." style tasks used on humans and animals for 50 years), the question asked is always a specific, fully-specified comparison ("is B bigger than D?"), never an open-ended "what's bigger than B?" — because researchers have long known the open version has no single right answer when there could be several. And in the branch of computer science that builds AI systems to answer multi-step questions over networks of facts, the standard fix for exactly this problem is to never force a single answer out of a "one thing connects to several things" step — either you accept the whole set of valid answers, or you carry along an extra piece of information (a target, a goal, a memory of what came before) that narrows it back down to one.

**Why it matters:** our own test was quietly asking the second, unfair kind of question — "given a person and 'has a friend,' guess THE friend" when that person has three friends — and no amount of clever engineering can make that question determinate, because the missing piece of information (which friend we actually care about) simply isn't in the question. Worse, our last attempt at a fix (separating the "address book" codes from the "meaning" codes) accidentally made things worse specifically because it removed some leftover, accidental correlation that had been quietly supplying part of that missing information — like removing a lucky guess-helper instead of replacing it with a real one. The fix this drill proposes is cheap and doesn't require any new engineering: re-score the SAME already-failed data two new ways — once accepting any of the true answers as correct (not just one pre-picked one), and once giving the query one extra piece of real, already-available context (the way a brain gets a goal, or a modern AI search gets a target) — and see if the "failure" mostly disappears. If it does, that's strong evidence we've been debugging a broken test, not a broken substrate, and the actual fix is redesigning the question, not building a bigger or fancier memory system. If it doesn't, that's still useful — it tells us honestly that the problem is real and engineering-fixable, and we can go back to the architecture ideas already queued up with a clear conscience.
