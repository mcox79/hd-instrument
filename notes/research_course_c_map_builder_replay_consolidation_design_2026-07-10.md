## Part 1 — The prerequisite, confronted concretely

### 1.1 What exactly was tested (read off the pre-reg + source, not memory)

`preregs/2026-06-27_stage3_hrr_involutive_systematic_generalization_v1.md` + `experiments/exp_stage3_hrr_involutive_systematic_generalization_v1.py` (both read in full):

- **Storage**: a single memory bundle `F = sum_i bind(verb_i, bind(subj_i, obj_i))` over N_TRAIN_FACTS=500 facts, N_DIM=8192.
- **Query**: for a held-out object `obj_NEW` (constructed to share 30% of spatial dims with seen-object prototypes, via `FEATURE_OVERLAP_FRAC=0.30`), compute `unbind(verb, unbind(F, obj_NEW))` and cleanup over the entity codebook.
- **Bind/unbind implementation**: the cell defines its OWN `hrr_bind`/`hrr_unbind` inline (lines 171-182 of the source) via `torch.fft` circular convolution/correlation on **real (bipolar {-1,+1}) vectors**, NOT a call into the substrate's chain-grade `hdlab/binding.py` primitive.
- **Result**: `ARM_HRR_INVOLUTIVE.heldout_acc = 0.0067` = chance (0.005). HARD_FAIL, verdict_msg `hrr_mechanism_null`.

### 1.2 Root cause — three compounding, independently fixable choices

**(a) Wrong binding primitive — real/bipolar HRR, not complex FHRR.** `hdlab/binding.py` dispatches bind/unbind on dtype: `complex64 -> FHRR` (elementwise complex multiply; unbind = multiply by conjugate — an EXACT unitary inverse, since every phasor component has `|z|=1`) vs `float32 real -> HRR` (FFT circular convolution — lossy). The stage3 cell's own self-test (T1, source lines 561-573) proves this explicitly: even for an EXACT-key recovery test (`unbind(bind(a,b),b)` with the SAME `b` used for both), the cell's bipolar-real implementation only reaches `cosine >= 0.55` — not the near-1.0 that FHRR's complex-phasor path would give. The cell chose the substrate's WEAKER of two available primitives, and documented this choice explicitly in its own comments ("Bipolar HRR is approximate... 0.55 not 0.95... The substrate uses bipolar everywhere") — a scope decision, not a discovered wall.

**(b) Severe crosstalk from one global superposition.** All 500 facts bound into ONE `F` vector. The pre-reg's own "Option B" scale justification computes HRR involutive unbind SNR ~ `1/sqrt(K_facts)` (Plate 1995) = `1/sqrt(500) ~= 0.045` — a per-item recovery signal already near the noise floor for SEEN facts, before any attempt at generalizing to an unseen one. Course C must NOT repeat this: relation-type operators must be factorized (a small number of shared per-relation-TYPE transforms, not one shared bundle over all facts) — this is also the literal TEM prescription (structure factorized apart from content) and the RotatE/DRUM precedent (per-relation-type parameters, not one global object).

**(c) The deepest issue — discrete convolution-bind is similarity-DESTROYING by design, and the cell relied on similarity surviving anyway.** This is the mechanistic crux the lit-scan resolved precisely. Convolution binding with a random vector `a` is an **isometry**: `sim(bind(a,x), bind(a,x')) = sim(x,x')` exactly (Plate's own result). Binding does NOT inherently destroy similarity. What destroys it is upstream: in standard discrete VSA, each entity gets an **independent i.i.d. random vector with no continuous parametrization linking similar entities to similar vectors** — so `sim(x,x')` is already near-zero for any two distinct entities by construction, and the (similarity-preserving) bind operation then faithfully propagates that near-zero similarity into the bound code. Stage3's `FEATURE_OVERLAP_FRAC=0.30` only copied a SPATIAL block of raw dims between prototype-sharing entities — this does not create the kind of smooth, globally-distributed, phase-encoded similarity structure that survives an FFT-domain correlation. The fix, precisely: **fractional power encoding (FPE)** (Frady, Kleyko, Kymn, Olshausen, Sommer, arXiv:2109.03429) raises a fixed unit-modulus phasor base vector to a CONTINUOUS power `r` (equivalently: scale each Fourier-domain phase component linearly by `r`), which makes inner-product similarity a smooth, monotonically-decaying function of the underlying continuous distance — by a random-Fourier-features/Bochner's-theorem argument (Rahimi & Recht 2007), not a heuristic. **Spatial Semantic Pointers** (Komer, Stewart, Voelker, Eliasmith, CogSci 2019) apply exactly this per-axis to encode continuous coordinates so that bind = translation and similarity = distance. Stage3 used neither continuous phase-encoding nor a genuinely similarity-preserving entity code; it used raw i.i.d. random entity vectors with a superficial spatial patch shared — a materially different (and strictly weaker) construction.

### 1.3 Verdict on the prerequisite: fixable, not fundamental — but not the whole story

Answer to the assigned question: **config/method limit, not a fundamental wall.** All three of (a)/(b)/(c) are addressable by using the substrate's proven FHRR complex primitive with per-relation-type phase-rotation operators (RotatE-equivalent) and FPE-style continuous entity encoding, factorized per relation type rather than bundled globally. Any Course C build MUST use FHRR (complex64), not the real/bipolar path stage3 used.

**However, this does not clear Course C to proceed unscoped.** The on-substrate cert ledger contains THREE MORE relevant negatives, all more recent (2026-07-10) and all more rigorous than stage3 (FULL, 3-seed, confound-checked), that stage3's specific bugs do NOT explain away:

TransE is an ADDITIVE/geometric code, not a discrete symbol-bind — this negative is NOT explained by "wrong binding primitive."

## Part 2 — The map-builder design, brain-grounded piece by piece

### 2.1 The representation: FHRR phase-rotation relations + FPE-style entity encoding

- **Entities**: encode each entity via **fractional power encoding** over a small set of continuous (or continuous-relaxed) features rather than an arbitrary i.i.d. random vector — i.e., if the entity has ANY continuous or graded attribute signal available (even a coarse one, e.g. embedding-derived coordinates in a low-dim feature space), FPE-encode it so that entity similarity is preserved as inner-product similarity in the hyperdimensional space (Frady et al. 2022; Komer et al. 2019). Where no continuous attribute exists, fall back to the substrate's proven FHRR i.i.d. random assignment (this preserves exact discrimination for entities with no known metric relationship — do not force a metric onto entities that genuinely have none, this would be manufacturing structure that was never in the corpus, exactly what the density-floor note warns against).
- **Relations**: represent each relation TYPE (not each fact) as a single shared **unit-modulus phase-rotation operator** in the complex/FHRR embedding — mathematically identical to RotatE's `r ∘ h ≈ t` with `|r_i|=1` for all frequency components. This is a substrate-native re-derivation of RotatE using the substrate's OWN proven-exact FHRR bind, and directly fixes TransE's provable symmetric-relation collapse (RotatE handles symmetry via `r=±1`, antisymmetry, inversion via `r_2=r_1^{-1}` i.e. conjugate, and composition via phase addition `theta_3 = theta_1+theta_2` — all four of TransE's documented failure patterns, per Sun et al. 2019).
- **Factorization discipline (the TEM move, and the fix for stage3's crosstalk)**: the relation operator is factorized APART from entity content and SHARED across every entity pair of that relation type — never bundled into one global superposition of all facts. This directly matches TEM's structure/content split (Whittington et al. 2020) and avoids the `1/sqrt(K_facts)` crosstalk that sank stage3.
- **Scope honesty (from the TEM/CSCG lit-scan)**: this factorization generalizes NEW ENTITY PAIRS under a relation type the operator was fit on (content-in-known-structure) — it is NOT claimed to generalize to a genuinely novel relation TYPE never seen in any form. Neither TEM nor CSCG (George et al. 2021) has been shown to do the latter; our task (FB15k-237 held-out edges under existing relation types) only needs the former, which is the case both models DO demonstrate.

### 2.2 "Replay" concretely, for us

Not literal spatial traversal — for a relational-triple corpus, replay = **repeated, randomly-interleaved re-presentation of stored (h, r, t) triples across many passes**, each pass taking a gradient/update step on the shared per-relation-type phase operators, rather than one end-to-end fit over the full training set in a single pass. Concretely modeled on generative-replay mechanics (Shin et al. 2017): triples are the "pseudo-samples" (we don't need a learned generator since we HAVE the stored corpus directly — this is closer to true rehearsal than generative replay, which is actually a SIMPLER, lower-risk starting point since it sidesteps generator-drift/mode-collapse, a documented failure mode of the generative variant).

### 2.3 The consolidation/settling gate — degree-invariance and reliability, not indiscriminate iteration

Two concrete, literature-grounded candidate mechanisms for "when has this settled into something useful, not overfit or collapsed":

1. **Recall-consistency gating** (Lindsey & Litwin-Kumar, eLife 2024): only lock in a per-relation-operator update if repeated re-presentation of the SAME triple across replay passes gives a CONSISTENT (not noisy, one-off) update direction — an explicit, computable reliability statistic (agreement across repeated recalls), directly addressing the "unregulated consolidation overfits to noise" failure named in the prior consolidation prior-art note (Thread 1).
2. **Validation-error early-stopping** (Sun et al. 2023, Nat. Neurosci.): the actual mechanism in that paper is a stopping RULE, not a per-item reweighting scheme (correcting a simplification in the earlier deep-drill note's framing) — halt further consolidation of a given relation-operator once continued replay would raise held-out/validation error, estimated via a small held-back triple set per relation type. This is directly implementable as a per-relation-type early-stopping check during the replay loop.

Both mechanisms are only validated on small, linear, or toy-scale simulations (Sun et al.: linear teacher-student; Lindsey & Litwin-Kumar: <5000 synapses) — treat as a well-motivated MECHANISM CLASS to borrow, not a proven-at-scale technique.

**Cross-channel independence gate (own prior-art note, Thread 2/Pitfall #3, non-negotiable pre-flight step)**: before trusting the replay loop at all, verify the geometric/structural channel and any secondary channel (e.g., a raw frequency/co-occurrence channel used for the must-fail control below) are not already mutually predictable or both degree-correlated. If they are, the whole architecture is moot before the loop starts — this is a 30-minute check, do it FIRST.

**Anti-collapse instrumentation**: track singular-value spectrum / effective rank of the entity-embedding space and the relation-operator space every N replay passes (SSL collapse-diagnostic precedent, per the prior consolidation note); halt/flag on dimensional or complete collapse.

### 2.4 The one thing nobody has shown — stated as a risk, not hidden

A dedicated lit-scan (Q4, KG-embedding training-regime effects) explicitly searched for any paper showing that an **iterative/interleaved training procedure (vs. one-shot end-to-end fit) changes the GENERALIZATION PROPERTIES of a fixed relation-embedding architecture** — as opposed to (a) a few points of standard transductive accuracy (curriculum learning, CL4KGE 2024: +3-11% Hits@10, same-distribution held-out triples, not novel-structure generalization) or (b) retention/forgetting under distribution shift (continual-learning KGE literature). **No such paper was found.** This is the single load-bearing NEW claim Course C rests on beyond "use the right operator" (Part 2.1, which is independently well-precedented via RotatE) — it is neither confirmed nor refuted externally; it is genuinely untested. This is why Course C's overall P (Section headline, item 4) stays capped at 0.20-0.25 even though the operator-fix sub-claim alone is much better-grounded (P~0.40).

### 2.5 The verifier for generated (never-observed) inferences

Per `research_generate_and_test_relational_inference_candidate_b_2026-07-10.md`: any inference the geometric channel proposes for a NEVER-observed (h,r,t) must be gated by a hard, cheap, auditable verifier — support/confidence computed from OTHER instances of the same relation-type-composition pattern elsewhere in the graph (AMIE/RNNLogic-style), NOT biology's soft novelty/RPE-style gate (which the brain itself uses, per the deep drill note's Section 1.4 arbiter discussion, but which is not the recommended substrate design — the ML-grade hard verifier is cheaper, auditable, and already has working precedent on this exact problem class).
