## HEADLINE

**The composition is structurally sound in its store-capacity half (already proven) but UNTESTED and non-trivial in its audit-and-drift half -- and the single sharpest open risk is that per-hop ROUTING is itself a new noisy per-hop estimate, which is exactly the failure shape that already broke two other reasoning-loop fixes this session.** Three findings, ranked by how load-bearing each is to the "is this sound" question:

1. **The store-capacity mechanism transfers cleanly, because it operates in a provably separate feature space from the loop's own machinery.** v1/v2's community-gist codebook is a near-orthogonal ROUTING space, deliberately decoupled from the content/value codes per the already-certified correlation-hurts-store law -- this is the same decoupling discipline the glass-box loop's own bind/cleanup/audit machinery already assumes (working-memory active-slot rebind, Merkle-logged steps, margin-gated commit are all orthogonal-space operations). There is no known interference term between "route to a community" and "bind/gate/audit within it" -- routing is a pure filter applied before retrieval, not a modification of retrieval's own math. This is the biologically well-grounded part: it is a direct implementation of hippocampal SCHEMA-CONSTRAINED retrieval (Tse et al. 2007; already used in the prior note) composed with entorhinal GRID-CODE-STYLE coarse addressing of conceptual space (Bellmund, Gardenfors, Moser & Doeller, *Science* 2018, "Navigating cognitive space") -- the entorhinal grid system provides exactly this kind of low-dimensional coarse coordinate BEFORE hippocampal fine-pattern-completion resolves the specific item, in both physical and abstract/social conceptual spaces (Constantinescu, O'Reilly & Behrens 2016, *Science*, "Organizing conceptual knowledge in humans with a hippocampal formation similar to that used for navigation" -- grid-like hexagonal-symmetry signals measured during purely conceptual, non-spatial two-dimensional judgment tasks). Spreading-activation theory (Collins & Loftus 1975, "A spreading-activation theory of semantic processing") independently supports the same architectural claim from a different angle: activation in a semantic network propagates outward from a cue and DECAYS with graph distance, so in practice only a bounded local neighborhood around the cue ever reaches usable activation strength -- the brain's own retrieval dynamics never touch the whole network per query, they are intrinsically community-bounded by decay, which is the functional analog of the substrate's explicit two-stage route-then-restrict.

2. **The loop's causal-editability / audit guarantee does NOT survive the insertion for free -- it requires ONE structural addition: the routing decision itself must become a logged, Merkle-chained step, not a hidden pre-filter.** `glass_box_loop.py`'s four certified properties (discriminator fires; hand-edit of a logged step causally flips downstream recompute; tamper is detected via Merkle-root mismatch; deterministic replay reproduces answer+root) are properties of the LOGGED STEP SEQUENCE, not of retrieval in the abstract. If community-selection happens silently before the logged retrieve step, it becomes an un-audited, un-editable decision sitting upstream of everything the audit trail claims to cover -- a hidden gate that could route a query to the wrong community and there would be no causal handle to inspect or correct it, which directly violates the "inspectable, hand-editable, not merely functionally correct" promise that is the entire point of the deep-prize build (glass-box, not black-box). This is a code-level fix (log the routing pick as its own auditable step type, same Merkle-chain discipline as the existing hops), not a mechanism failure, but it is a REQUIRED addition, not automatic, and it is the first concrete thing that would need to change before this composition could be certified rather than merely composed.

3. **The genuinely open risk, and the one that ties directly to Barrier #2:** community-of-communities routing has, to date, only been certified for a SINGLE retrieval per store-size setting (v1/v2's own kill-tests sweep total-V and per-community-load L, but neither exercises a multi-hop CHAIN where hop k's routing decision feeds hop k+1). Two distinct failure modes are possible once routing is chained, and the Barrier #2 investigation (`research_deep_chain_reasoning_bounded_compounding_error_brain_first_2026-07-08.md`, HARD_FAIL confirmed same day on `exp_pfc_gate_waypoint_rescue_coarse2fine_verify_v1`) already diagnosed the exact SHAPE of failure to watch for: **compounding error occurs precisely when a downstream correction step re-derives its answer from MORE OF THE SAME noisy upstream signal, rather than from an informationally-independent source.** Applied to routing specifically: if hop k+1's community pick is derived from hop k's retrieved (possibly already-slightly-wrong) bridge content, and hop k's bridge content was itself produced by a routing decision drawn from the SAME coarse-gist codebook using the SAME kind of noisy margin-based selection, routing error could compound across hops in the same unbounded, growing-with-depth shape that broke the two already-tried ML-side chain-drift fixes (coarse-to-fine, verify-against-self). This has NEVER been tested -- v1/v2's kill-tests are single-shot-per-V, not chain-depth sweeps. It is the single sharpest open question in this composition, described fully as the kill-test below.

## Cheap decisive test

**Single sharpest kill-test (the one requested):** insert the CERTIFIED community-routed retrieval (v1 single-tier, v2 nested) as the per-hop store inside `glass_box_loop.py`'s existing multi-hop chain, and sweep TOTAL store size V (small -> large, matching v1/v2's own 580->58000 range) under three arms, while holding the loop's own gate/audit/requery code path completely unmodified.

**Design (buildable now, CPU, synthetic community-structured KB -- no real-KB ingest or native-encoder dependency needed, see "buildable now vs reader-gated" below):**

- **Arm A -- FLAT_STORE_CONTROL (must-collapse, saturation-vacuous-smoke guard):** `glass_box_loop.py` exactly as certified today -- each hop's retrieve/cleanup runs against the WHOLE per-hop store (no routing). This reproduces the crosstalk wall INSIDE the chain context (not just single-retrieval, which is all v1/v2 tested): as total V grows, self-audit-passing multi-hop success rate must visibly DEGRADE. If it does not degrade at the largest tested V, the harness is not exercising the crosstalk regime and the whole test is void (per `[[feedback-saturation-vacuous-smoke]]`).
- **Arm B -- COMMUNITY_ROUTED_WITHIN (the treatment, matching PRED-4 "within-community" case from the prior note):** insert v1/v2's route-then-restrict retrieval as the loop's per-hop store, but construct every test query so all hops resolve WITHIN one community (no cross-community bridge needed). Routing decision is logged as its own Merkle-chained audit step (the required code addition from HEADLINE point 2). Should stay flat vs total V, exactly per v1/v2's own certified single-shot result, now demonstrated inside a real multi-hop chain with the audit trail intact end-to-end.
- **Arm C -- COMMUNITY_ROUTED_CROSSING + ROUTING-NOISE INJECTION (the genuinely new arm, targets the #2 interaction directly):** same as Arm B, but (i) construct queries where hop 2's correct answer lives in a DIFFERENT community than hop 1's cue community (the bridge case), and (ii) separately, inject a controlled error rate into the coarse-routing codebook's margin (perturb a fraction of routing picks) to directly measure whether a wrong routing pick at hop k propagates into hop k+1 as a GROWING (unbounded, multi-hop-compounding) error or a BOUNDED (single-hop, self-correcting or capped) error. This is the test that directly answers whether per-hop routing needs its OWN Barrier-#2-style fix (e.g. bidirectional forward+reverse routing agreement, echoing the replay-generate-then-select principle and the grid-cell modular-redundancy sub-mechanism, both from the same-day Barrier #2 note) before this composition can be trusted at depth, or whether routing is structurally exempt because it is a fresh, stateless per-hop classification rather than an accumulated estimate.

Paired seeds (>=3), matched query difficulty and chain depth (2-3 hops, matching the certified loop's own multi-hop composition primitive) across all V settings, cv <= 0.15.

## Falsifiable predictions (HARD-PASS + HARD-FAIL)

**PRED-A (composition preserves audit properties):** with routing logged as a first-class audited step (HEADLINE point 2's fix applied), all four of `glass_box_loop.py`'s certified properties (discriminator fires, causal hand-edit of ANY logged step including the new routing step flips downstream recompute, Merkle tamper-detect, deterministic replay) continue to hold with community-routing inserted.
- HARD-PASS: all four properties verified in `verification/`-style tests with the routed loop, at every V setting tested.
- HARD-FAIL: any property silently breaks (e.g. editing the routing step does NOT flip the recompute, meaning routing is de facto NOT part of the causal chain despite being logged) -- this would mean the composition needs a deeper wiring fix, not just a logging addition.

**PRED-B (store-capacity result transfers from single-shot to chain context, Arm A vs Arm B):** FLAT_STORE_CONTROL degrades with total V inside the chain (reproducing the crosstalk wall in the harder multi-hop setting, not just v1/v2's single-retrieval setting); COMMUNITY_ROUTED_WITHIN stays flat.
- HARD-PASS: FLAT_STORE_CONTROL shows >=30% relative degradation in multi-hop self-audit-passing success rate from smallest to largest V; COMMUNITY_ROUTED_WITHIN shows <10% relative degradation over the same range (joint condition, matching the discriminator discipline already used for v1/v2).
- HARD-FAIL: COMMUNITY_ROUTED_WITHIN ALSO degrades with total V at a rate statistically indistinguishable from FLAT_STORE_CONTROL -- would mean something about chaining (not present in v1/v2's single-shot tests) reintroduces global crosstalk that per-retrieval routing alone does not show, e.g. the WM active-slot rebind step accidentally reads from the whole store rather than the routed community.

**PRED-C (the load-bearing new claim -- routing-error compounding across hops, Arm C):** a wrong routing pick at hop k propagates into hop k+1 as a BOUNDED, non-growing error (fresh independent classification each hop), NOT as an unbounded, growing-with-depth error (the shape that already broke both tried ML-side chain-drift fixes).
- HARD-PASS: injected routing-error rate at hop k produces a downstream hop-(k+1) failure rate that stays proportional to the injected rate itself (no multiplicative growth across additional hops) -- i.e. routing errors do not compound the way bisection errors did; the per-hop routing decision behaves as an informationally-fresh, independent lookup each time.
- HARD-FAIL: downstream failure rate grows super-linearly with chain depth for a FIXED per-hop injected routing-error rate (the same qualitative shape Ross-Bagnell / the confirmed HARD_FAIL diagnosed) -- this would mean per-hop routing needs its own independent-channel correction (bidirectional agreement or multi-scale redundant routing codes, per the Barrier #2 note's governing principle) BEFORE this composition can be trusted past a couple of hops, i.e. the composition is NOT simply "insert v1/v2's retrieval and go," it inherits Barrier #2's still-open problem rather than sidestepping it.

**PRED-D (cross-community bridge cost, Arm C bridge case, directly extends the prior note's PRED-4):** chains that must cross a community boundary pay a FIXED per-crossing cost, independent of total V, not a V-scaling cost.
- HARD-PASS: cross-community chain fidelity cost is flat vs total V (a constant penalty per crossing).
- HARD-FAIL: cross-community cost ITSELF scales with total V (meaning the bridge/crossing mechanism -- essentially "does the coarse-router even know which OTHER community to jump to" -- is not actually bounded, and needs its own hub-level index, per the anterior-temporal-lobe hub-and-spoke literature, Patterson, Nestor & Rogers 2007, already used in the prior note).

## Substrate-product implications

- **Is the composition sound? Conditionally yes, with one required code addition and one genuinely open empirical question.** The store-capacity mechanism transfers with no expected interference (different, deliberately-decoupled feature space). The audit/causal-editability guarantee requires routing to be promoted to a logged, Merkle-chained step -- straightforward, same pattern already used for the loop's other primitives, not a redesign. The one thing that is NOT yet known, and cannot be reasoned to certainty from existing certs, is whether chained per-hop routing decisions compound error the way the already-HARD_FAILED waypoint-pick fixes did (PRED-C) -- this is an empirical question this note's Arm C is specifically built to answer, and it is flagged explicitly so it is not silently assumed away.
- **Sequencing recommendation:** (1) promote routing-as-audited-step into `glass_box_loop.py` first (cheap, mechanical, no new science); (2) run Arm A/B (store-capacity-in-chain-context) -- this should PASS near-certainly given v1/v2's existing single-shot certification, and is the low-risk half of the composition; (3) run Arm C (routing-error-compounding + bridge-crossing) BEFORE claiming the composition scales past a couple of hops -- this is the load-bearing gate, and its outcome should be read jointly with whatever the in-flight Barrier #2 GPU FULL run (`chain-drift GPU FULL`, replay-generate-then-select) reports, because a HARD_FAIL on PRED-C would mean routing needs the SAME fix currently being tested for waypoint-picking, not a separate one -- i.e. if Barrier #2's independent-channel fix lands, it should be applied to per-hop routing too, as one unified mechanism, not two parallel patches.
- **Flagged HIGH-PROBABILITY-SUPERIOR, conditionally:** IF PRED-C HARD-PASSes (routing error does not compound across hops), this composition is the cleanest available path to scaling the deep-prize glass-box reasoning capability from 48k toward the full ingested KB (1.28M+) with NO loss of the loop's inspectability/editability guarantees -- because both halves (store capacity, chain-safe routing) would then be independently bounded rather than one being a hope. If PRED-C HARD-FAILs, the composition is still directionally correct (the store-capacity half is real and certified) but is NOT superior to simply keeping reasoning chains SHORT per Barrier #2's current fallback guidance, until routing gets its own independent-channel correction.
- **Buildable now vs reader(#1)-gated:** entirely buildable now, ZERO dependency on the in-flight native-reader work. The CHAIN_GRADE cert this composition extends is explicitly scoped as "real TOPOLOGY with random codes; certifies relational-retrieval + self-audit routing, not semantic-embedding reasoning" -- community structure for the routing codebook can be built synthetically (as v1/v2 already did, `sqrt(V)` communities) or measured directly off ConceptNet's REAL graph topology (already used for the 48k CHAIN_GRADE cert itself, via Newman modularity Q, already wired in v1's own kill-test guard). No dense-semantic embedding front-end is required for any arm of this test. This can ship in the same lane as the in-flight nested-store v2 FULL confirmation, as a direct follow-on cell once v2 lands.
