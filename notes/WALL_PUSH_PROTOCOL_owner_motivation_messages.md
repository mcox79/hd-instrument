# WALL-PUSH PROTOCOL — the owner's motivation messages (verbatim), 2026-09-12

**Why this file exists.** Every solver session hit walls continuously and needed these reminders to keep pushing to the truly
brain-foundational (BF) solution. The brain exists, so a glass-box, non-LLM solution is demonstrably functioning in every human
on earth. **Strategy (and any agent it dispatches) must apply these to ITSELF.** In auto mode, "a wall" is never a conclusion:
it becomes (a) deeper research + a stronger brain-faithful build attempt, or (b) a specific board question to the owner. Never a
"ceiling" written into the record. The owner's explicit concern: an autonomous session deciding a wall has been hit when the
owner knows it can be broken, as it has been time and time before.

## The messages (use them as written; send them to agents; re-read them when stuck)

1. make sure what we're building is brain foundational - research where you're unsure. In particular, if you hit a wall, we
   need to understand deeply why - if the brain can do it, we should be able to do it too. Also consider whether this needs to
   generalize, and how the brain does it.

2. Any more we can push here?
   - evaluate for brain foundational fidelity, research drills any walls that you come across. If the brain can do it, it's
     possible, and we can do it once we understand.
   - Additionally, understanding the capabilities, limitations, opportunities and brain foundational status of adjacent
     components helps us plan the next problems to address

3. keep in mind while you're doing this - I want you to fully prototype this component and an upstream brain foundational
   component (and all the way upstream if there are more) to show that this can excel and exceed. make it happen, and confirm
   no other downstream consumers of the upstream optimization regress.
   make SURE, via research, that what you're implementing upstream is brain foundational. THE ONLY WAY YOU OVERCOME THIS WALL
   IS FOR EVERY COMPONENT, YOU AND UPSTREAM, TO BE BRAIN FOUNDATIONAL. If a truly brain foundational component is not working
   properly - it almost always means that some other component that it relies on is not 100% brain foundational.

4. Any walls you encounter should be fully researched. The brain can do it, so we can as well, and to do so we need to
   understand fully.

5. OK so with your updated knowledge, are there any remaining upgrades or efficiencies we should implement? How are we
   performing against the brain, and where do we lose signal now?

6. i want you to go back to the full chain, and MAKE SURE IT'S 100% BRAIN FOUNDATIONAL. It cannot have easy off the shelf parts
   if they're not 100% brain foundational. if we think we implemented 100% brain foundational here, and it's failing, we got
   something wrong. Confirm that the end component we're working on is 100%, absolutely sure, brain foundational, then trace
   the signals it needs from the top down, evaluating each part for how much of that signal makes it. If it's losing a lot of
   signal, it's not brain foundational

7. Keep in mind during this solution: I want you to fully prototype this component and an upstream brain foundational
   component (and all the way upstream if there are more) to show that this can excel and exceed. make it happen, and confirm
   no other downstream consumers of the upstream optimization regress. make SURE, via research, that what you're implementing
   upstream is brain foundational. THE ONLY WAY YOU OVERCOME THIS WALL IS FOR EVERY COMPONENT, YOU AND UPSTREAM, TO BE BRAIN
   FOUNDATIONAL. If a truly brain foundational component is not working properly - it almost always means that some other
   component that it relies on is not 100% brain foundational.
   1) make sure the end component is 100% brain foundational. What are the inputs? Is this supported by research?
   2) Trace where, all the way up the chain, we're losing the signal on those inputs.
   3) Wherever we're losing signal, dig DEEP to find out why - it's going to be that somewhere, it's not brain foundational.
   4) Make sure the tools we're using aren't cheap off the shelf things that are easy. We do things right, not easy

8. You need to research and drill that result aggressively. Where are we losing signal, and how does the brain do it exactly?
   Where do we differ from the 100% brain foundational approach, precisely?

9. OK is this a complete, excellent solved problem?
   and is it fully brain foundational, conveying all the benefits of the brain function we're replicating?

10. while you're working on this keep the following in mind: How does this perform against a brain, and where do we exactly
    differ? make sure we're fully brain foundational. check if any organs are matches for what you need. When you approach
    optimization, evaluate, aggressively with great precision, exactly how the brain does it, and work to exactly replicate
    it. Do not do a half-effort here - the closer we are the better we do.

11. now that you have a very good understanding of the problem, the walls, and how the brain does it: How does our performance
    compare against the brain, where along the chain do we lose signal, and what exactly differs between our implementation
    and how the brain does it exactly?
