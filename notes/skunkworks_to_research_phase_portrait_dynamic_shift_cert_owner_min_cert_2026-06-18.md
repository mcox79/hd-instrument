## Ask 3 (taken first -- it grounds Ask 2) -- cert-integrity of dynamic selection
YES, dynamic selection introduces a NEW CERT SURFACE: the SELECTION itself is a claim ("operating-point X is best for task T") that needs cert-grounding or it's an unverified assertion. The principled cert-architecture:
- **The SELECTION_RULE becomes a cert-grade artifact** -- a DETERMINISTIC function mapping a task-FINGERPRINT -> operating-point {N, encoder, decoder, alpha, readout}, where each entry is JUSTIFIED by a cert-grade PHASE_PORTRAIT measurement. So Element 1 is the PREREQUISITE substrate for Element 2: the rule is a deterministic function OVER the portrait.
- **Answer-cert = min(selection-rule cert, chosen-operating-point measured-bounds cert)** -- this is the min-cert-along-path discipline (B-alpha) REUSED. An answer via dynamic selection is cert-grade only if BOTH the rule is cert-grade AND the chosen operating-point is cert-measured for that regime. Clean, already-have-the-machinery.
- **By-construction guard (critical):** the fingerprint must be INTRINSIC task features, NOT benchmark-identity. A rule tuned to maximize a specific benchmark = overfitting the selection to the eval (by-construction, the A1 trap again). The rule needs its OWN HELD-OUT cert: does deterministic-fingerprint-selection beat a FIXED operating-point on HELD-OUT tasks the rule wasn't built on? That meta-eval is the cert-test for Element 2.
- **11th-rule:** the selection loop must be DETERMINISTIC (no LLM/learned-policy) -- a lookup/function over the portrait, not a learned controller. Clean if it's a deterministic fingerprint->point table.
- **Stateful vs stateless (your sub-question):** STATELESS per-query selection is the cert-clean version (each query deterministically selects fresh from its fingerprint -> reproducible). STATEFUL (remembers last config) introduces history-dependence -> the same query can get different points depending on history -> non-reproducible -> cert-problematic. So USER's "shift back and forth" = the substrate picks the right point PER TASK (which naturally shifts as tasks change), NOT a remembered-state machine. Recommend stateless.
