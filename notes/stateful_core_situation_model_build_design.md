# STATEFUL-CORE BUILD DESIGN — the situation-model machinery (main-line hard build)

Scoped 2026-07-29 during the v5 GPU window. This is the correction to the recurring error (bolting isolated pieces on a FROZEN feed-forward encoder). The fix: build the coupled maintain-and-update-a-predictive-state machinery, trained END-TO-END. Basis: notes/brain_foundational_component_analysis.md (the coupled core = arch-recurrence + forward-objective + WM + role-binding).

## THE ONE OPERATION (what the brain does that we lack)
Maintain a small set of ENTITY-STATE slots over the token stream; UPDATE a slot when new input is inconsistent-with / extends it (prediction-error gated); bind fillers to slots by ROLE (content, not position). This IS the situation model. It requires PERSISTENT STATE (recurrence) + a LEARNED update gate + role-general binding, and it must be TRAINED, coupled to the encoder.

## MECHANISM (concrete, brain-faithful, glass-box, reuses our primitives)
- **Slots:** K entity-slots (K~6-8; Cowan ~4 + margin), each a FULL d-dim vector (NO scalar compression — design-A's fatal error). This is PFC working memory.
- **Recurrent maintenance:** process the stream clause-by-clause (or token-by-token); slots PERSIST across steps (the recurrence the feed-forward encoder lacks).
- **Learned PE-gated update (the PBWM analog):** at each step a small learned gate reads [encoder rep of the current span, current slot contents] and outputs (a) a content-addressed assignment (which slot this span updates — soft, differentiable), (b) a write/update strength that is HIGH when the span is SURPRISING / inconsistent with the addressed slot (prediction-error gating; basal-ganglia gating of PFC in O'Reilly PBWM). Slot update = gated convex/rotational combine preserving dimensionality.
- **Role-general binding:** filler->slot assignment via a LEARNED CONTENT KEY (role-general, position-INVARIANT — fixes the v5 position-bind failure, matches Frankland-Greene). Reuse hdlab/binding (HRR bind/unbind) with the learned key.
- **Substrate choice:** this is SLOT-ATTENTION (Locatello 2020) made brain-faithful — slot-attention is an established, differentiable, trainable mechanism for maintaining a set of object/entity slots via competitive content-addressed attention. Map: slots=PFC WM; competitive attention=content-addressed gating; add PE-gated write strength + recurrent persistence + HRR binding for the brain-faithful version. Using a known-trainable substrate mitigates backprop-through-memory instability (the hard part design-A dodged with local Hebbian writes).

## TRAINING (END-TO-END — the key fix vs every prior)
- **UNFREEZE the encoder.** Train encoder + WM + gate + binding JOINTLY. (Design-A/loop/readout all used FROZEN reps — that is the recurring error. The WM can only maintain what the encoder co-adapts to encode.) Tractable form = fine-tune the v2 (or v5-winner) encoder jointly with the WM, not necessarily from scratch.
- **Objective (coupled):** (a) forward prediction FROM the maintained WM state (predict next span / next entity-state) — couples with v5's forward-PC; (b) a comprehension-consistency signal (the maintained slot-states must correctly reflect entity-state across boundaries). Prediction-error is both the training loss AND the write-gate signal — one principle.
- **Data:** the reading corpus (ARC) for the predictive objective + calibration-first constructions for the comprehension-consistency signal.

## MEASUREMENT (calibration-first + the structure-alone guard is NON-NEGOTIABLE)
- The cross-boundary construction was STRUCTURALLY solvable by a high-capacity readout (random-init encoder matched +0.50). So: (1) use a HARDER construction — MULTI-entity, MULTI-boundary, longer chains where raw positional structure is insufficient and genuine maintenance is required; (2) calibration-first: a known reader must pass it; (3) MANDATORY random-init-ENCODER-through-the-full-stateful-core control — if the untrained core matches, it is structure not learning (HARD_FAIL_STRUCTURE_ALONE), exactly as it just caught the readout.
- **Brain-metric (the per-component gate):** does the TRAINED stateful core maintain entity-state that a CAPACITY-CONTROLLED readout extracts, beating BOTH (a) the static-encoder baseline AND (b) the random-init-core control, on BOTH seeds, with updating-cost at discontinuities (Zwaan) as a bonus signature.
- Both seeds; can-fail bands (HARD_PASS = beats static baseline >= margin AND random-init doesn't match, both seeds; HARD_FAIL = ties/loses or random-init matches -> the stateful core also isn't the fix and we escalate to recurrence-in-the-encoder / a deeper rebuild).

## HONEST RISKS (no-shortcuts: state them)
1. Backprop-through-recurrent-memory can be unstable — slot-attention substrate mitigates but doesn't eliminate.
2. The structure-alone confound is the same wall the readout hit — the HARDER construction + random-init-core control are the defense; if we can't build a construction a random-init core fails, our MEASUREMENT is the block, not the mechanism.
3. Bigger compute (joint fine-tune / recurrent training) — more GPU than a frozen-head. Runs after v5.
4. It may STILL fail — the brain has far more (multimodal, embodied, lifelong). This is the minimal faithful core, not the whole brain. But it is the RIGHT next hard thing and a clean can-fail.
